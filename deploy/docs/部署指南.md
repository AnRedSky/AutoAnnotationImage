## 二、30 秒极简部署

```bash
# Windows
cd d:\works\...\thesis-image-annotation
.\scripts\start_docker.ps1

./scripts/start_docker.sh
```

脚本自动完成: 准备 .env → 生成密钥 → 构建镜像 → 启动服务 → 健康检查

## 三、手动部署 (6 步)

### 步骤 1: 准备 .env

```bash
# 从模板复制
cp .env.example .env

# 生成强随机密钥 (替换 7 个 CHANGEME 占位符)
python scripts/gen_secrets.py
```

### 步骤 2: 验证 Docker

```bash
docker --version          # >= 24.0
docker compose version    # >= v2.20
```

### 步骤 3: 构建镜像

```bash
# 增量构建 (推荐, 利用缓存)
docker compose build

# 强制全量重建
docker compose build --no-cache
```

**构建耗时参考**:

| 阶段 | 首次 | 增量 (缓存命中) |
|------|------|-----------------|
| uv sync (PyPI 依赖) | 5-15 min | <30s |
| COPY .venv --chown | ~1.5 min | ~1.5 min |
| 前端 npm build | 2-5 min | <10s |
| **总计** | **8-20 min** | **30-90s** |

### 步骤 4: 启动服务

```bash
docker compose up -d
```

### 步骤 5: 等待健康检查

```bash
# 查看服务状态 (等待全部 healthy)
docker compose ps
```

预期输出:
```

annotation_worker_train      Up (healthy)
annotation_worker_annotate   Up (healthy)
annotation_api               Up (healthy)
annotation_mysql             Up (healthy)
annotation_redis             Up (healthy)
annotation_minio             Up (healthy)
```

### 步骤 6: 验证部署

```bash

# 跨服务通信验证
```

## 六、常见问题

### Q1: 构建时 uv sync 很慢

**原因**: 首次构建需下载 ~1.8 GB Python 依赖 (torch/torchvision/ultralytics)。

**解决**:
- 耐心等待 5-15 分钟 (取决于网络)
- 后续构建缓存命中, 仅需 <30s
- 可添加 PyPI 镜像: 在 Dockerfile builder 阶段加 `ENV UV_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple`

### Q2: 端口冲突

**现象**: `Bind for 0.0.0.0:3306 failed: port is already allocated`

**解决**:
```bash
# 查找占用进程
netstat -ano | findstr :3306
# 停止冲突容器
docker stop <container_name>
# 或修改 .env 中的端口映射
```

### Q3: API 启动后立即退出

**排查步骤**:
```bash
docker logs annotation_api --tail 50
```

常见原因:
- 数据库迁移未执行 → `docker exec annotation_api alembic upgrade head`
- 环境变量错误 → 检查 `.env` 文件
- 卷权限问题 → 确认 `docker-entrypoint.sh` 存在且有执行权限

### Q4: Worker 不消费任务

**排查**:
```bash
# 检查 Worker 状态
docker exec annotation_worker_annotate celery -A app.tasks.workers.celery_app inspect active

# 检查 Redis 队列
docker exec annotation_redis redis-cli -a $REDIS_PASSWORD llen train
docker exec annotation_redis redis-cli -a $REDIS_PASSWORD llen annotate
```

### Q5: 前端页面空白

**排查**:
```bash
# 检查 Nginx 日志
docker logs annotation_frontend

# 检查前端是否可访问
curl http://localhost:8080/healthz

# 检查 API 代理
curl http://localhost:8080/api/health
```

## 七、镜像体积优化建议

当前镜像体积参考值:

| 镜像 | 体积 | 评估 |
|------|------|------|
| annotation/api:local | 6.08 GB | ⚠️ 偏大 (torch CUDA) |
| annotation/worker:local | 6.08 GB | ⚠️ 偏大 (torch CUDA) |
| annotation/frontend:local | 54.4 MB | ✅ 优秀 |
| mysql:8.0 | 764 MB | ✅ 标准 |
| redis:7-alpine | 39.1 MB | ✅ 优秀 |
| minio/minio:latest | 175 MB | ✅ 标准 |

**后续优化方向** (可选):
1. **torch CPU-only**: 修改 uv.lock 使用 `https://download.pytorch.org/whl/cpu` 索引, 预期 -3~4 GB
2. **BuildKit cache mount**: 在 Dockerfile 中添加 `RUN --mount=type=cache,target=/root/.cache/uv`, 加速重复构建
3. **镜像扫描**: 使用 `trivy image annotation/api:local` 检测安全漏洞
