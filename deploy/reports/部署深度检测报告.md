### 2.2 发现的问题与修复

#### 问题 1: shebang 路径错误 (v3.3.2 修复) 🔴 严重

**现象**: API 容器启动失败, 报 `exec /app/.venv/bin/uvicorn: no such file or directory`

**根因**: builder 阶段 `UV_PROJECT_ENVIRONMENT=/build/.venv`, 生成 `.venv/bin/*` 脚本 shebang 为 `#!/build/.venv/bin/python`。base 阶段 `COPY` 到 `/app/.venv` 后, shebang 指向不存在的路径, 所有入口脚本 (uvicorn/celery) 均无法执行。

**修复**: 所有 Dockerfile builder 阶段 `UV_PROJECT_ENVIRONMENT` 改为 `/app/.venv`, 与 base 阶段路径一致。

**影响文件**:
- [backend/Dockerfile](file:///d:/works/WorkBuddy/Myhome/ThesisDesignImplementation/thesis-image-annotation/backend/Dockerfile)
- [backend/Dockerfile.api](file:///d:/works/WorkBuddy/Myhome/ThesisDesignImplementation/thesis-image-annotation/backend/Dockerfile.api)
- [backend/Dockerfile.worker](file:///d:/works/WorkBuddy/Myhome/ThesisDesignImplementation/thesis-image-annotation/backend/Dockerfile.worker)

#### 问题 2: chown -R 导致镜像层翻倍 (v3.3.2 修复) 🔴 严重

**现象**: API/Worker 镜像各 12 GB, 远超预期 ~6 GB

**根因**: Dockerfile 执行顺序为 `COPY .venv → COPY 源码 → chown -R app:app /app`。`chown -R` 遍历 `/app` 下所有文件 (含 5.9 GB 的 .venv), 在 copy-on-write 层中产生完整副本, 镜像体积翻倍: 5.9 GB (.venv COPY) + 5.9 GB (chown 层) = 11.8 GB。

**修复**: 重构执行顺序为 `RUN groupadd/useradd → COPY --chown=app:app`。`COPY --chown` 在拷贝时直接设置属主, 不产生额外层, 镜像体积减半。

**体积对比**:
```
修复前: python:3.10-slim (130MB) + apt (6MB) + .venv COPY (5.9GB) + chown层 (5.9GB) = ~12 GB
修复后: python:3.10-slim (130MB) + apt (6MB) + .venv COPY --chown (5.9GB)         = ~6 GB
节省:   ~6 GB (-50%)
```

#### 问题 3: 命名卷权限拒绝 (v3.3.2 修复) 🔴 严重

**现象**: API 启动报 `PermissionError: [Errno 13] Permission denied: '/app/models/data'`

**根因**: Docker 命名卷 (model_data/upload_data/api_logs) 以 root:root 挂载。容器以非 root 的 `app` 用户运行, 无法在卷中创建子目录。`config.py` 在 import 阶段调用 `mkdir()` 触发崩溃。

**修复**: 新增 [docker-entrypoint.sh](file:///d:/works/WorkBuddy/Myhome/ThesisDesignImplementation/thesis-image-annotation/backend/docker-entrypoint.sh), 容器以 root 启动 → 创建必要目录 + chown → 通过 `gosu` 降权到 `app` 用户执行主命令。

**影响文件**:
- [backend/docker-entrypoint.sh](file:///d:/works/WorkBuddy/Myhome/ThesisDesignImplementation/thesis-image-annotation/backend/docker-entrypoint.sh) (新建)
- [backend/Dockerfile](file:///d:/works/WorkBuddy/Myhome/ThesisDesignImplementation/thesis-image-annotation/backend/Dockerfile) (安装 gosu + ENTRYPOINT)
- [backend/Dockerfile.api](file:///d:/works/WorkBuddy/Myhome/ThesisDesignImplementation/thesis-image-annotation/backend/Dockerfile.api) (同上)
- [backend/Dockerfile.worker](file:///d:/works/WorkBuddy/Myhome/ThesisDesignImplementation/thesis-image-annotation/backend/Dockerfile.worker) (同上)

#### 问题 4: Frontend tmpfs 权限拒绝 (v3.3.2 修复) 🟡 中等

**现象**: Nginx 报 `mkdir() "/var/cache/nginx/client_temp" failed (13: Permission denied)`, frontend 容器反复重启

**根因**: `read_only: true` + `tmpfs` (root 拥有) + Dockerfile `USER app` = 非 root 用户无法在 tmpfs 挂载点创建缓存目录

**修复**: docker-compose.yml 中 frontend 添加 `user: "0:0"`, nginx master 以 root 启动 (nginx 标准模式), worker 进程仍降权运行。`read_only: true` + `tmpfs` 保留文件系统隔离。
