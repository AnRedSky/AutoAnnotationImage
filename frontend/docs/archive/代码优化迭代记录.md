## 二、SSE 流式订阅代码重复消除

### 2.1 问题

`api/index.ts` 中 `trainingApi.streamProgress` 和 `detectionApi.streamProgress` 各自实现了一套完整的 SSE 流式订阅逻辑, 约 **100 行重复代码**:
- `fetch` + `ReadableStream` 读取
- `\n\n` 帧分割 + `data: ` 前缀剥离
- JSON.parse + 终端态判定 (SUCCESS/FAILURE/REVOKED)
- `AbortController` 取消

### 2.2 修复方案

**新建** `src/utils/sse.ts`, 提取统一的 SSE 流式工具:

```typescript
export interface SSECallbacks {
  onMessage: (data: any) => void
  onComplete?: () => void
  onError?: (err: Error) => void
}

const TERMINAL_STATES = new Set(['SUCCESS', 'FAILURE', 'REVOKED'])

export function createSSEStream(url: string, callbacks: SSECallbacks): () => void {
  const controller = new AbortController()
  let finished = false
  // ... fetch + ReadableStream + 帧解析 + 终端态判定
  return () => controller.abort()  // 返回取消函数
}
```

**修改** `api/index.ts`, 两处 `streamProgress` 统一调用 `createSSEStream`:

```typescript
// 修复前: ~50 行重复逻辑
// 修复后:
streamProgress: (taskId, callbacks) =>
  createSSEStream(`${BASE_URL}/api/training/${taskId}/stream`, callbacks)
```

### 2.3 收益

- 消除 **~100 行** 重复代码
- SSE 解析逻辑集中在单一工具文件, 便于维护和测试
- `AbortController` 管理统一, 避免内存泄漏

## 三、Token 管理统一 (单一真值源)

### 3.1 问题

Token 在 **3 处** 独立管理, 容易不同步:
1. `stores/user.ts`: 使用 `STORAGE_KEY = 'image-annotation-user'` 存储 `{ token, user }` JSON
2. `api/http.ts`: 401 时 `localStorage.removeItem('token')` (key 名不同!)
3. `views/Login/index.vue`: 登录成功后 `localStorage.setItem('token', tk)` (第三处写入)
4. `views/Layout/index.vue`: 退出时 `localStorage.removeItem('token')` (第四处删除)

**根因**: store 用 `image-annotation-user` key, http/Login/Layout 用 `token` key, 两个 key 不同步。

### 3.2 修复方案

**统一为 `localStorage['token']` 单一真值源**, store 作为响应式镜像:

```typescript
// stores/user.ts
export const TOKEN_KEY = 'token'
export const useUserStore = defineStore('user', () => {
  const token = ref<string | null>(localStorage.getItem(TOKEN_KEY))
  const user = ref<UserInfo | null>(null)
  const setAuth = (t: string, u: UserInfo) => {
    token.value = t; user.value = u
    localStorage.setItem(TOKEN_KEY, t)  // 唯一写入点
  }
  const clear = () => {
    token.value = null; user.value = null
    localStorage.removeItem(TOKEN_KEY)  // 唯一删除点
  }
  return { token, user, setAuth, clear }
})
```

**联动修改**:

| 文件 | 改动 |
|---|---|
| `api/http.ts` | 401 时调用 `useUserStore().clear()` + 动态 import router 跳转 (带 redirect query) |
| `router/index.ts` | 移除死代码 `!localStorage.getItem('token')` 检查 |
| `views/Login/index.vue` | 移除直接 `localStorage.setItem`, 改由 `userStore.setAuth` 统一管理 |
| `views/Layout/index.vue` | 移除冗余 `localStorage.removeItem('token')` |

### 3.3 并发 401 防抖

```typescript
// api/http.ts
let isRedirectingToLogin = false
// 401 拦截:
if (!isRedirectingToLogin) {
  isRedirectingToLogin = true
  useUserStore().clear()
  const router = (await import('@/router')).default
  router.push({ path: '/login', query: { redirect: router.currentRoute.value.fullPath } })
}
```

### 3.4 收益

- Token 真值源唯一, 不再出现 store / localStorage 不同步
- 并发 401 (多个 API 同时过期) 只触发一次登录跳转
- 登录后自动回跳到原页面 (redirect query)

## 四、API 调用规范

### 4.1 问题

`trainingApi.start` 手动拼接 query string:

```typescript
// 修复前
start: (params) => http.post(
  `/training/start?dataset_id=${params.dataset_id}&base_model=${params.base_model}&...`
)
```

### 4.2 修复方案

```typescript
// 修复后: 使用 axios params 选项
start: (params) => http.post('/training/start', null, { params })
```

### 4.3 收益

- 不再手动拼接 URL, 避免特殊字符编码问题
- 与后端 `Query(...)` 签名匹配, 避免 422 错误

### 5.2 Annotate 页面 onBeforeUnmount 清理

**问题**: 切换数据集时, 旧的 `autoSaveTimer` (setTimeout) 和 `maskUrl` (ObjectURL) 不会被清理, 导致内存泄漏。

**修复**:
```typescript
const autoSaveTimer = ref<number | null>(null)

onBeforeUnmount(() => {
  if (autoSaveTimer.value) clearTimeout(autoSaveTimer.value)
  if (maskUrl.value) URL.revokeObjectURL(maskUrl.value)
})
```
