# 文档审核清单（提交前必查）

> **版本**: v1.4
> **配套规范**: [00-00-文档风格规范.md](00-00-文档风格规范.md)
> **使用方式**: 每次新增或修改文档后，逐项打勾；全部 ✅ 方可提交

---

## 1. 文档头规范

- [ ] 仅包含 H1 标题，正文紧随其后
- [ ] 顶部**无** `> **本节件已按 [00-00-文档风格规范] 修订：YYYY-MM-DD**` 这类声明
- [ ] 顶部**无** `> **版本** / **编制日期** / **覆盖时间** / **目标** / **适用** / **范围** / **作者** / **维护人** / **冻结日期** / **Git Tag**` 等键的元信息块
- [ ] 顶部**无** `**编制日期**` / `**版本**` / `**关联文档**` 不带 `>` 前缀的元信息行
- [ ] 顶部**无** `- **键**: 值` 列表形式的元信息行
- [ ] H1 行内**无** BOM 残留
- [ ] 历史版本信息不写在文档中（git commit 已记录）

## 2. 禁止词扫描

用以下命令快速扫描（PowerShell）：

```powershell
Select-String -Path '.\docs\**\*.md' -Pattern '一定程度上|显著提升|大幅提升'
```

如有任何命中，必须修改。

- [ ] 全文无自夸性主观判断
- [ ] 全文无"一定程度上 / 显著 / 大幅 / 有效 / 良好"等模糊副词
- [ ] 不在正文中出现无关的"使用指南"等说明性区块

## 3. 路径检查

```powershell
Select-String -Path '.\docs\**\*.md' -Pattern '旧项目路径|临时测试路径'
```

- [ ] 全文路径使用统一项目根 `d:\works\WorkBuddy\Myhome\ThesisDesignImplementation\`

## 4. 描述方式

- [ ] 描述功能时使用"做什么 + 怎么用"格式
- [ ] 描述流程时使用步骤编号 + 操作
- [ ] 描述问题时给出"现象 + 根因 + 解决方案"
- [ ] 描述数据时给出绝对值 + 单位 + 测试环境
- [ ] 不使用"经过分析发现"、"深入研究"等空话

## 5. 链接规范

- [ ] 所有文档内链接指向真实存在的文件
- [ ] 跨目录链接使用相对路径
- [ ] 链接文本准确反映目标内容
- [ ] 不在正文中出现"参考资源"等说明性章节

## 6. 表格与代码

- [ ] 表格列标题清晰
- [ ] 所有代码块标注语言（`bash`、`python` 等）
- [ ] 命令可复制粘贴（无中文全角符号混用）
- [ ] 示例数据真实可重现

## 7. 结构与样式

- [ ] H1 唯一且不重复
- [ ] 章节层次合理（最多 4 级）
- [ ] 章节标题不包含句号、问号
- [ ] 不使用斜体、删除线、emoji（除 ⚠️）
- [ ] 关键警告使用引用块 + ⚠️

## 8. 命名与归档

- [ ] 文件命名符合 `NN-XX-名称.md` 格式
- [ ] 同一主题最多 2 段编号
- [ ] 已废弃文档移至 `archive/` 而非删除
- [ ] `archive/` 内文档不再修改内容

## 9. 评审流程

- [ ] 作者自查：以上 1-8 项全部 ✅
- [ ] 同伴评审：另 1 名成员确认通过
- [ ] 核心文档（README/使用手册）：额外 1 名高级成员确认
