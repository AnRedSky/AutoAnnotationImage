# 系统功能规划文档

---

## 一、功能范围与边界

### 1.1 总览

系统功能按**必要性**分为三层：

| 层级 | 标识 | 说明 | 优先级 |
|---|---|---|---|
| **MVP** | 🔴 P0 | 核心核心能力必须实现 | 必实现 |
| **增强** | 🟡 P1 | 提升用户体验/数据完整性 | 尽量实现 |
| **扩展** | 🟢 P2 | 锦上添花，时间允许才做 | 可选 |

### 1.2 范围裁剪（依据 2026-07-11 老师反馈）

**剔除**（不做）：

- ❌ 用户注册/密码重置/邮箱验证（简单功能）
- ❌ 键盘快捷键（提升效率，非核心能力）
- ❌ 系统可行性分析
- ❌ 复杂权限管理（仅 admin / annotator / viewer 三级）
- ❌ 实时多人协作（WebSocket，复杂且非核心能力）
- ❌ 移动端适配
- ❌ 模型在线部署为推理服务（仅训练 + 离线推理）

**保留**：

- ✅ 3 个核心核心能力（AI 预标注 / 人工修正 / 模型训练版本）
- ✅ 3 种格式导出（COCO / YOLO / CSV）
- ✅ 6 个统计接口
- ✅ 5+ 系统插图

## 二、MVP 功能规划（P0 必实现）

### MVP-A：AI 自动标注

| 项 | 说明 |
|---|---|
| **功能点** | 同步/异步预标注 + Top-5 候选 + 置信度阈值 |
| **输入** | dataset_id, model_name, confidence_threshold |
| **输出** | 每张图片的 top1/top5 标签 + 置信度 + 状态变更 |
| **验收标准** | ✓ 1000 张图片批量推理 < 5 分钟（CPU）<br>✓ top1_conf ≥ 阈值 → status=ai_labeled ✓<br>✓ top1_conf < 阈值 → 保持 pending ✓<br>✓ 至少 3 个预训练模型可选 |
| **对应 API** | `POST /api/auto-annotate/run` / `GET /api/auto-annotate/status/{task_id}` / `GET /api/auto-annotate/models` |
| **完成度** | ✓ W2 已实现 |

### MVP-B：人工标注与修正

| 项 | 说明 |
|---|---|
| **功能点** | Top-5 候选确认/强制采用 + 其他类别修正 + 跳过 + 计时 + 审计 |
| **输入** | image_id, label_id, time_spent_ms, is_confirm |
| **输出** | image.final_label_id + AnnotationLog + 状态变更 |
| **验收标准** | ✓ 标注结果 100% 写入审计日志<br>✓ 4 状态机完整（pending/ai_labeled/human_confirmed/human_corrected）<br>✓ 实时统计 4 卡（已标注/AI 命中/节省时间/平均耗时）<br>✓ 单张标注耗时 < 5 秒 |
| **对应 API** | `POST /api/annotations/save` / `GET /api/annotations/stats/{id}` |
| **完成度** | ✓ W2 已实现 |

### MVP-C：模型训练与版本管理

| 项 | 说明 |
|---|---|
| **功能点** | 异步训练 + 进度轮询 + 训练曲线 + 4 指标 + 激活 + 对比 |
| **输入** | dataset_id, base_model, epochs, batch_size, learning_rate |
| **输出** | ModelVersion + 训练曲线 JSON + 混淆矩阵 |
| **验收标准** | ✓ 5 类 × 200 张 × 5 epoch CPU 训练 < 30 分钟<br>✓ 4 指标全部计算（accuracy/precision/recall/f1）<br>✓ 训练曲线 Redis 持久化（前端可查）<br>✓ 同一时刻仅 1 个模型激活 |
| **对应 API** | `POST /api/training/start` / `GET /api/training/progress/{id}` / `GET /api/training/history/{id}` / `GET /api/models` / `POST /api/models/{id}/activate` / `GET /api/stats/models/compare/{a}/{b}` |
| **完成度** | ✓ W2 已实现 |

### MVP-D：数据集与图像管理

| 项 | 说明 |
|---|---|
| **功能点** | 数据集 CRUD + 类别管理 + 批量上传 + 去重 |
| **输入** | 数据集名/描述/类别；图像文件 |
| **输出** | 数据集记录 + 图像记录（带 SHA-256 hash） |
| **验收标准** | ✓ 同一 hash 不重复入库<br>✓ 单数据集支持 1000+ 张图<br>✓ 创建数据集时支持批量创建类别 |
| **对应 API** | `/api/datasets/*` / `POST /api/images/upload/{id}` / `GET /api/images/list/{id}` |
| **完成度** | ✓ W2 已实现 |

### MVP-E：基础统计

| 项 | 说明 |
|---|---|
| **功能点** | 系统总览 + 数据集统计 + 置信度分布 + 时间线 + 标注员效率 + 模型对比 |
| **验收标准** | ✓ 6 个统计端点全部返回正确数据<br>✓ 4 个 ECharts 图渲染正常<br>✓ 数据精度满足图表需求 |
| **对应 API** | `/api/stats/*`（6 个端点） |
| **完成度** | ✓ W2 已实现 |

### MVP-F：用户认证

| 项 | 说明 |
|---|---|
| **功能点** | 注册/登录/me/登出 |
| **输入** | username + password (+ email) |
| **输出** | JWT token + user info |
| **验收标准** | ✓ bcrypt 密码哈希<br>✓ JWT 过期时间 24 小时<br>✓ 401 自动跳登录 |
| **对应 API** | `/api/auth/*`（4 个端点） |
| **完成度** | ✓ W2 已实现 |

## 七、风险与应对

### 7.1 技术风险

| 风险 | 影响 | 应对 |
|---|---|---|
| CPU 训练太慢 | W3/W4 无法完成训练 | 减 epoch（5 → 3） + 减数据集（200 → 100） |
| MySQL 部署问题 | 真实环境跑不起来 | 暂时用 SQLite，文档描述 MySQL 部署方案 |
| Celery worker 起不来 | 训练任务同步卡死 | 改为同步执行 + 进度模拟 |
| MinIO 部署问题 | 文件存储失败 | 用本地文件系统兜底 |

### 7.2 时间风险

| 风险 | 影响 | 应对 |
|---|---|---|
| W3 拖延 | W4 压紧 | 减少测试用例数（17 → 10） |
| 截图不齐 | 系统图少 | 优先 6 张主图，次要图可省略 |
| 性能测试跑不完 | 性能数据缺失 | 用单个测试用例的数据代替基准 |
| 模型对比未完成 | 对比章节空 | 仅跑 2 个模型（仅列 2 个） |

### 7.3 文档风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 字数不足 | 被问 | 扩展对应章节技术对比表的描述（每张表多 200 字） |
| 章节失衡 | 老师提意见 | 严格按目录字数预算（引言 1800 / 技术 2500 / 设计 3500 / 实现 4500 / 测试 2500 / 总结 1500） |
| 图太丑 | 影响观感 | 用 ECharts 默认主题，不追求花哨 |
