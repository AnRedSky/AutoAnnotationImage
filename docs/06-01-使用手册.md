## 一、快速开始

### 1.1 一键 Docker 启动 (推荐)

适用于本地体验与开发环境，要求本机已安装 Docker 20.10+ 与 Docker Compose v2。

```bash
# 1) 克隆代码
git clone <repository-url>
cd thesis-image-annotation

# 2) 启动全部服务 (MySQL + Redis + MinIO + API + Workers + 前端)
docker compose up -d

# 3) 查看启动日志
docker compose logs -f api
docker compose logs -f worker-train
```

服务启动后访问：

| 服务 | URL | 默认凭据 |
|---|---|---|
| 前端 | http://localhost:5173 | (页面注册) |
| API 文档 | http://localhost:8000/docs | — |
| API 健康检查 | http://localhost:8000/api/health | — |
| MinIO 控制台 | http://localhost:9001 | minioadmin / minioadmin |
| MySQL | localhost:3306 | root / root123 |
| Redis | localhost:6379 | (无密码) |

### 1.2 默认管理员账户

首次启动会自动创建超级管理员（详见 `backend/app/database/seed.py` 或初始化脚本）：

| 用户名 | 密码 | 角色 |
|---|---|---|
| `admin` | `admin123` | super_admin |

> ⚠️ **生产环境请第一时间修改默认密码**！

### 1.3 第一次使用流程

1. 访问 http://localhost:5173
2. 使用 `admin / admin123` 登录
3. **创建数据集**：左侧菜单「数据集」→ 右上角「新建」→ 选任务类型（分类/检测/分割）
4. **上传图片**：进入数据集详情 → 「上传」→ 拖拽多文件
5. **AI 预标注**：「自动标注」→ 选模型 + 设阈值 → 启动
6. **人工修正**：左侧菜单「人工标注」→ 键盘快捷键快速标注
7. **训练模型**：「模型训练」→ 选数据集 + 基础模型 → 启动
8. **导出**：「数据集详情」→ 「导出」→ 选 COCO / YOLO / CSV

## 二、安装指南

### 2.1 环境要求

#### 2.1.1 硬件最低配置

| 角色 | CPU | 内存 | 硬盘 | GPU |
|---|---|---|---|---|
| API 服务 | 2 核 | 4 GB | 20 GB | — |
| Worker (CPU) | 4 核 | 8 GB | 50 GB | — |
| Worker (GPU) | 4 核 | 16 GB | 100 GB | NVIDIA 8GB+ |
| MySQL | 2 核 | 4 GB | 50 GB | — |
| Redis | 1 核 | 1 GB | 5 GB | — |
| MinIO | 1 核 | 2 GB | 100 GB+ | — |

#### 2.1.2 软件依赖

| 软件 | 版本 | 用途 |
|---|---|---|
| Python | 3.10+ | 后端运行时 |
| Node.js | 18+ | 前端构建 |
| MySQL | 8.0+ | 主数据库 |
| Redis | 7.0+ | 缓存 / 队列 |
| MinIO | 最新稳定版 | 对象存储（可选，本地存储可替代） |
| Docker | 20.10+ | 容器化（可选） |
| uv | 0.4+ | Python 包管理（推荐） |

### 2.2 方式一：Docker Compose 一键启动

#### 步骤 1：克隆代码

```bash
git clone <repository-url>
cd thesis-image-annotation
```

#### 步骤 2：环境变量配置（可选）

复制 `backend/.env.example` 为 `backend/.env.docker`，根据需要修改：

```bash
cp backend/.env.example backend/.env.docker
```

默认配置已经能跑通完整流程，无需修改即可启动。

#### 步骤 3：启动全部服务

```bash
docker compose up -d
```

服务列表：

| 容器名 | 作用 | 端口 |
|---|---|---|
| `annotation_mysql` | MySQL 8.0 | 3306 |
| `annotation_redis` | Redis 7 | 6379 |
| `annotation_minio` | MinIO | 9000 / 9001 |
| `annotation_api` | FastAPI | 8000 |
| `annotation_worker_train` | Celery 训练 worker | — |
| `annotation_worker_annotate` | Celery 标注 worker | — |
| `annotation_frontend` | Vue dev server | 5173 |

#### 步骤 4：验证启动

```bash
# API 健康检查
curl http://localhost:8000/api/health

# 前端页面
# 浏览器访问 http://localhost:5173
```

#### 步骤 5：停止服务

```bash
# 停止但保留数据
docker compose down

# 停止并清空全部数据 (谨慎)
docker compose down -v
```

### 2.3 方式二：本地开发模式

适合需要修改代码、调试、扩展功能的开发者。

#### 步骤 1：启动基础设施

只启动 MySQL + Redis + MinIO（推荐用 Docker）：

```bash
docker compose up -d mysql redis minio
```

#### 步骤 2：后端启动

```bash
cd backend

# 2.1 安装依赖 (推荐使用 uv, 比 pip 快 10 倍)
pip install uv
uv sync                 # 等价于 uv pip install -r requirements.txt

# 或使用 pip
python -m venv .venv
.venv\Scripts\activate   # Windows
# source .venv/bin/activate  # Linux/macOS
pip install -r requirements.txt

# 2.2 配置环境变量
cp .env.example .env
# 用编辑器打开 .env, 至少修改以下项:
#   MYSQL_PASSWORD=root123
#   SECRET_KEY=<随机生成 32+ 字符>
#   MINIO_ROOT_USER=minioadmin
#   MINIO_ROOT_PASSWORD=minioadmin

# 2.3 启动 API 服务 (前台, 支持热重载)
python start_api.py --reload
# 等价命令: uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload

# 2.4 启动 Celery worker (另开终端)
python start_workers.py
# 内部会启动 train (concurrency=1) + annotate (concurrency=4) 两个 worker
```

#### 步骤 3：前端启动

```bash
cd frontend

# 3.1 安装依赖
npm install

# 3.2 启动开发服务器
npm run dev
# 默认 http://localhost:5173

# 3.3 生产构建
npm run build
# 产物在 dist/ 目录
```

#### 步骤 4：访问

- 前端：http://localhost:5173
- API：http://localhost:8000/docs

### 2.4 方式三：只跑离线示例（无需任何后端）

适合快速体验 AI 推理能力：

```bash
cd demo
python demo_inference.py --offline        # 离线模式 (使用 timm 预训练权重)
python demo_inference.py your_image.jpg   # 指定图片
```

## 三、系统配置

### 3.1 后端配置（`.env`）

后端配置基于 `pydantic-settings`，所有项可由环境变量或 `.env` 文件覆盖。

#### 3.1.1 必填项（生产环境强制）

```bash
# 应用环境 (development / production)
APP_ENV=development

# JWT 签名密钥 (生产环境必填, 至少 32 字符)
SECRET_KEY=<随机字符串, 至少 32 字符>

# MySQL 密码 (生产环境不能用默认值)
MYSQL_PASSWORD=<强密码>
```

#### 3.1.2 数据库配置

```bash
# 方式 1: 完整连接串 (优先)
DATABASE_URL=mysql+aiomysql://user:password@host:3306/dbname

# 方式 2: 分散配置
MYSQL_HOST=localhost
MYSQL_PORT=3306
MYSQL_USER=root
MYSQL_PASSWORD=root123
MYSQL_DATABASE=image_annotation

# 数据库连接池
DB_POOL_SIZE=10              # 常驻连接
DB_MAX_OVERFLOW=20           # 峰值溢出
DB_POOL_RECYCLE=3600         # 连接主动回收 (秒)
```

#### 3.1.3 Redis & Celery 配置

```bash
# Redis
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
REDIS_DB=0
REDIS_PASSWORD=

# Celery (默认复用 Redis)
CELERY_BROKER_URL=           # 留空用 redis://...
CELERY_RESULT_BACKEND=       # 留空用 redis://...

# Worker 池配置
CELERY_WORKER_POOL=threads   # Windows 推荐 threads; Linux 可用 prefork
CELERY_WORKER_CONCURRENCY=2  # 并发数
```

#### 3.1.4 存储配置

```bash
# 存储后端: local | minio
STORAGE_BACKEND=local

# 本地存储路径 (默认基于项目根, 相对路径会基于项目根解析)
UPLOAD_DIR=./uploads
MODEL_DIR=./models

# MinIO 配置 (STORAGE_BACKEND=minio 时生效)
MINIO_ENDPOINT=127.0.0.1:9000
MINIO_ACCESS_KEY=minioadmin
MINIO_SECRET_KEY=minioadmin
MINIO_BUCKET=image-annotation
MINIO_SECURE=false
```

#### 3.1.5 ML 配置

```bash
# 默认推理设备
INFERENCE_DEVICE=cpu          # cpu | cuda

# 默认模型
DEFAULT_MODEL=efficientnet_b0

# 默认置信度阈值
DEFAULT_CONFIDENCE_THRESHOLD=0.6

# DataLoader 工作进程
DATALOADER_WORKERS=0          # 0=同步, >0=多进程

# 分割推理 batch size
SEG_INFERENCE_BATCH_SIZE=4
```

#### 3.1.6 HuggingFace 镜像（国内网络必配）

```bash
HF_ENDPOINT=https://hf-mirror.com
HUGGINGFACE_HUB_ENDPOINT=https://hf-mirror.com
HF_HOME=./models/cache/huggingface

# Windows 必备
HF_HUB_DISABLE_SYMLINKS=1
HF_HUB_DISABLE_SYMLINKS_WARNING=1
HF_HUB_DOWNLOAD_TIMEOUT=60
```

#### 3.1.7 安全配置

```bash
# JWT
JWT_ALGORITHM=HS256
JWT_ISSUER=image-annotation
JWT_AUDIENCE=image-annotation-api
JWT_LEEWAY_SECONDS=60
ACCESS_TOKEN_EXPIRE_MINUTES=1440  # 24 小时

# CORS (生产环境配置实际域名)
CORS_ORIGINS=http://localhost:5173,http://127.0.0.1:5173
CORS_ALLOW_CREDENTIALS=true
```

#### 3.1.8 缓存与性能

```bash
CACHE_ENABLED=true
CACHE_DEFAULT_TTL=300
CACHE_KEY_PREFIX=app:
SQL_SLOW_THRESHOLD_MS=200
REQUEST_SLOW_THRESHOLD_MS=500
MAX_UPLOAD_SIZE_MB=20
```

### 3.2 前端配置（`.env.development` / `.env.production`）

```bash
# API 基础 URL
VITE_API_BASE_URL=http://localhost:8000

# 其他可选项
VITE_APP_TITLE=图像标注平台
```

### 3.3 生产环境 checklist

部署到生产前请确认：

- [ ] `APP_ENV=production`
- [ ] `SECRET_KEY` 随机 32+ 字符（不能用默认值）
- [ ] `MYSQL_PASSWORD` 强密码（不能用 `root123` / `root` / 空）
- [ ] `CORS_ORIGINS` 配置为实际前端域名
- [ ] `STORAGE_BACKEND=minio`（生产推荐）
- [ ] `INFERENCE_DEVICE=cuda`（如有 GPU）
- [ ] 关闭 `APP_DEBUG`
- [ ] 数据库备份策略就绪
- [ ] 日志收集方案就绪

启动时若 `APP_ENV=production` 且上述任何一项不合规，进程会**直接 fail-fast** 拒绝启动。

## 四、用户指南

### 4.1 登录与注册

#### 4.1.1 登录

1. 访问 http://localhost:5173
2. 输入用户名、密码
3. 首次登录会进入系统总览页

#### 4.1.2 注册

- **开发模式**：在登录页点击「注册」→ 填用户名 / 密码 / 邮箱 → 创建
- **生产模式**：默认注册关闭，需超级管理员在「用户管理」中创建

#### 4.1.3 退出

- 右上角头像 → 「退出登录」
- 后端会撤销 Token（写黑名单），防止 Token 继续可用

### 4.2 系统总览

登录后默认进入「系统总览」页，展示：

- 4 个统计卡片：总数据集 / 总图片 / 已标注 / 待标注
- 最近活动时间线
- 我的数据集快入口
- 训练任务概览

### 4.3 数据集管理

#### 4.3.1 创建数据集

1. 左侧菜单「数据集」→ 右上「新建数据集」
2. 填写：
   - **名称**（必填，2-50 字符）
   - **任务类型**（分类 / 目标检测 / 语义分割）
   - **描述**（可选）
   - **类别**（可后续添加，建议创建时一并填好）
3. 点击「确定」

#### 4.3.2 上传图片

1. 进入数据集详情
2. 「上传」按钮 → 选择文件 / 拖拽到上传区
3. 支持批量上传，进度条实时显示
4. 支持格式：JPG / PNG / WebP，单文件 ≤ 20MB（可配置）

#### 4.3.3 类别管理

- 进入数据集详情 → 「类别」标签页
- 可添加 / 编辑 / 删除类别
- 类别用于：分类标签、BBox 关联、分割 mask 关联

#### 4.3.4 团队共享

- 创建团队 → 邀请成员 → 把数据集共享给团队
- 团队成员可访问被共享的数据集

#### 4.3.5 数据集列表筛选

- 按任务类型 / 名称 / 创建时间 / 拥有者筛选
- 切换网格 / 列表视图

### 4.4 标注工作台

#### 4.4.1 进入标注

1. 左侧菜单「人工标注」
2. 选数据集（如未选，跳转到数据集列表选择）
3. 标注主界面会显示当前图片、候选标签、Top-K 预测

#### 4.4.2 分类标注

| 操作 | 快捷键 |
|---|---|
| 选第 N 个候选标签 | `1` ~ `5` |
| 确认（接受 AI 预测） | `A` |
| 跳过 | `D` |
| 下一张 | `→` / `Space` |
| 上一张 | `←` |
| 清空标注 | `Shift+C` |
| 标记不合格 | `Shift+U` |

**流程**：
1. 看到 AI 预测 Top-5（按置信度降序）
2. 正确：按 `A` 接受（计时 +1）
3. 错误：按数字键 `1-5` 选正确标签（计时 +1）
4. 都不对：手动点选其他类别（计时 +1）
5. 加载下一张图片

#### 4.4.3 目标检测标注

- 鼠标拖拽绘制矩形框
- 拖完弹窗选类别
- 单框：点击选中后按 `Delete` 删除
- 整图重画：「重画」按钮清空后重画
- 复制建议：「复制建议」可拉取相似图片的 BBox 复用

#### 4.4.4 语义分割标注

- 上传 PNG 调色板格式 mask
- 弹窗选类别关联
- 「拉取 mask」可下载当前图 mask
- 「清除 mask」可一键清除

#### 4.4.5 不合格图片标记

- 快捷键 `Shift+U` 或工具栏「标记不合格」
- 选原因（图片模糊 / 无关内容 / 重复图片 / 类别错误 / 其他）
- 选「其他」时可填自定义文案
- 标记后图片会进入「不合格」视图，便于后期复核
- 再次 `Shift+U` 可取消标记

### 4.5 AI 自动标注

#### 4.5.1 启动预标注

1. 进入数据集详情 → 「自动标注」按钮
2. 选择模型：
   - **分类任务**：timm 模型下拉（efficientnet_b0、resnet50、convnext_tiny 等）
   - **检测任务**：预训练 YOLOv8n/s/m/l/x 或自训练 ModelVersion
   - **分割任务**：预训练 DeepLabV3+ 或自训练 ModelVersion
3. 设置**置信度阈值**（0-1，默认 0.6）：
   - ≥ 阈值：自动写入 `ai_labeled`
   - < 阈值：保持 `pending` 等人工标注
4. 选**是否覆盖已有标注**（默认不覆盖）
5. 点击「启动」

#### 4.5.2 实时进度

- 同步任务（图片 < 1000）：直接返回结果
- 异步任务：返回 task_id，前端订阅 SSE
- 进度面板显示：总数 / 已处理 / 失败 / 吞吐量

#### 4.5.3 预览置信度

「预览置信度」按钮可**不修改任何状态**地跑一遍推理：
- 显示每张图的 top-1 置信度
- 显示在当前阈值下是否会被自动标
- 便于提前评估阈值合理性

### 4.6 模型训练

#### 4.6.1 启动训练

1. 左侧菜单「模型训练」→ 右上「新建训练」
2. 填写：
   - **数据集**：选要训练的数据集
   - **基础模型**：timm 模型 / YOLOv8 / DeepLabV3+ backbone
   - **模型名（版本号）**：例如 `eff_v1`、`yolov8n_v1`
   - **超参**：epochs / batch_size / learning_rate
3. 点击「启动」

#### 4.6.2 训练列表

- 列表显示所有训练任务（admin 看全部，其他看自己的）
- 支持按 dataset / state / task_type / 关键词搜索
- 状态：PENDING / PROGRESS / SUCCESS / FAILURE / REVOKED / PAUSED
- 操作：启动 / 暂停 / 取消 / 编辑 / 删除 / 查看详情

#### 4.6.3 训练详情

- **实时进度**：SSE 推送，epoch 进度 / loss / accuracy 实时刷新
- **训练曲线**：ECharts 展示 loss / accuracy 曲线
- **训练日志**：worker 实时输出，含 stdout / stderr
- **错误详情**：DB + Redis 双源错误捕获

#### 4.6.4 训练控制

| 操作 | 行为 | 适用状态 |
|---|---|---|
| 启动 | 创建 Celery 任务，state → PENDING → PROGRESS | 终态 / 未启动 |
| 暂停 | 写 Redis 标志 + revoke Celery，worker 在 epoch 边界优雅退出 → PAUSED | PENDING / PROGRESS |
| 取消 | revoke Celery + SIGTERM 强停 → REVOKED | PENDING / PROGRESS |
| 恢复 | 复用旧 job 重新启动 | PAUSED |
| 重跑 | 创建新 job，model_name 自动加 _r{ts} | 任意 |
| 编辑 | 改超参（仅未运行任务） | 非 PROGRESS |
| 删除 | 物理删除记录 + 清 Redis | 终态 |

### 4.7 模型管理

#### 4.7.1 模型列表

- 左侧菜单「模型管理」
- 支持按数据集 / 任务类型 / 激活状态过滤
- 显示：版本号 / 任务类型 / 关联数据集 / 训练指标 / 激活状态

#### 4.7.2 激活 / 取消激活

- 列表行点击「激活」→ 该模型被标记为激活
- 取消激活：再次点击「取消激活」（幂等）
- **支持多激活并存**：不会自动取消同 dataset 的其他激活

#### 4.7.3 批量操作

- 多选后「批量激活 / 批量删除」
- 删除时同步清理物理权重文件

#### 4.7.4 模型详情

- 训练指标：mAP / loss / 训练时长
- 关联训练任务
- 关联数据集
- 训练配置快照

### 4.8 数据导出

#### 4.8.1 导出格式

| 格式 | 任务 | 文件 |
|---|---|---|
| COCO | 检测 / 分割 | 单个 JSON（annotations.json） |
| YOLO | 检测 | 多个 .txt + data.yaml + classes.txt |
| CSV | 分类 | 单个 CSV（filename, label） |

#### 4.8.2 导出步骤

1. 数据集详情 → 「导出」
2. 选格式
3. 自动下载（文件名含数据集 ID 与时间戳）

#### 4.8.3 导出用途

- **COCO**：直接用于 mmdetection / detectron2 训练
- **YOLO**：直接用于 ultralytics / YOLOv5 训练
- **CSV**：通用格式，可读入任何 ML 框架

### 4.9 团队管理

#### 4.9.1 创建团队

- 左侧菜单「团队」→ 「新建团队」
- 填名称、描述，创建者自动成为 owner

#### 4.9.2 邀请成员

- 团队详情 → 「邀请成员」
- 输入用户 ID + 选角色（owner / admin / member / viewer）
- 重复邀请会被检测并提示

#### 4.9.3 数据集共享

- 数据集详情 → 「共享给团队」

### 6.2 数据库迁移

项目使用 SQLAlchemy 自动建表 + Alembic 显式迁移组合：

- **首次启动**：API 启动时自动 `init_db()` 建表

```bash
cd backend

# 生成迁移
alembic revision --autogenerate -m "描述变更"

# 应用迁移
alembic upgrade head

# 回滚
alembic downgrade -1
```

## 七、常见问题

### 7.1 安装与启动

**Q: Docker 启动后 API 一直重启？**
A: 查看日志 `docker compose logs api`，通常为数据库未就绪或 .env 配错。MySQL 健康检查未通过会阻断 API 启动。

**Q: Windows 上 Celery 报 `ValueError: not enough values to unpack`？**
A: Windows 不支持 prefork，确保 `CELERY_WORKER_POOL=threads`。

**Q: 前端 `npm run dev` 报端口被占用？**
A: 修改 `frontend/vite.config.ts` 的 `server.port`，或停掉占用 5173 的进程。

### 7.2 数据与标注

**Q: 标注完没看到"已标注"数减少？**
A: 检查 `image.status` 字段，单条 BBox 保存后会自动从 `pending/ai_labeled` 升级到 `human_confirmed`。

**Q: 删除图片后磁盘空间没释放？**
A: 容器模式下需进入容器内删除；本地模式下 `uploads/` 目录需手动清理。

**Q: 数据集共享给团队后成员看不到？**
A: 确认成员已被邀请到团队，且数据集已共享给该团队，刷新页面即可。

### 7.3 训练

**Q: 训练任务一直 PENDING 不动？**
A: 检查 `worker-train` 容器是否运行，`docker compose ps`，查看 worker 日志 `docker compose logs worker-train`。

**Q: 训练报错 "No module named 'ultralytics'"？**
A: `uv sync` 或 `pip install ultralytics==8.0.196`。

**Q: YOLO 训练时 GPU 显存不足？**
A: 调小 `batch`（如 8 → 4），或换用更小的模型（yolov8n）。

### 7.4 模型与导出

**Q: 自动标注不调用我训练的模型？**
A: 确认模型已激活 (`/api/models/{id}/activate`)，启动时 `model_id` 传该 id。

**Q: YOLO 导出后训练报错？**
A: 检查 `data.yaml` 的路径是否正确（绝对路径最稳），确认 `classes.txt` 数量与数据集类别一致。

### 7.5 性能

**Q: 图片列表加载慢？**
A: 加分页参数 (`page`, `page_size`)，缩略图已 Redis 缓存。

**Q: SSE 频繁断连？**
A: 检查反向代理（如 nginx）的 `proxy_buffering off` 与超时设置。

**Q: 训练时 CPU 100%？**
A: 正常现象，调小 `CELERY_WORKER_CONCURRENCY` 可缓解。

### 7.6 安全

**Q: SECRET_KEY 怎么生成？**
```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

**Q: 生产环境默认密码还能登录吗？**
A: `APP_ENV=production` 启动时会检查默认值，发现默认值直接拒绝启动。务必修改。

**Q: 怎么撤销已签发的 Token？**
A: 调用 `POST /api/auth/logout` 写黑名单，或修改 `SECRET_KEY` 强制全部失效。
