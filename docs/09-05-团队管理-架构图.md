# 团队管理架构图 (v3.3.1)

> 本系统展示团队管理模块的 L1-L4 架构演进, 模块依赖关系, 数据流和扩展点.

## 一、整体架构 (5 层)

```
┌─────────────────────────────────────────────────────────────┐
│                     客户端 (Browser)                          │

                         │ HTTP (JSON)
┌────────────────────────┴────────────────────────────────────┐
│                  FastAPI 应用层 (3 应用)                       │
│   ┌──────────┐  ┌──────────┐  ┌──────────────────┐           │
│   │  admin   │  │  tasks   │  │   annotation     │           │
│   │  应用    │  │  应用    │  │   应用           │           │
│   └────┬─────┘  └────┬─────┘  └────┬─────────────┘           │
└────────┼─────────────┼─────────────┼───────────────────────┘
         │             │             │
         │             │             │
┌────────┴─────────────┴─────────────┴───────────────────────┐
│                      通用层 (Common)                          │
```

## 二、模块依赖关系 (L1-L4)

```
v3.3.0 (基础)
  ├─ team (CRUD)
  ├─ team_member (成员管理)
  └─ audit_log (审计基础)

v3.3.1 L1 (核心补齐) ─── 依赖: v3.3.0
  ├─ team.tenant_id / archived_at / invited_by_id (字段)
  ├─ PATCH /api/teams/{id} (编辑)
  ├─ POST /api/teams/{id}/transfer (转让)
  ├─ DELETE /api/teams/{id}/members/me (退队)
  ├─ 11 端点全部接入 log_audit
  └─ GET /api/teams/{id}/datasets (团队级数据集)

v3.3.1 L2 (安全 + 体验) ─── 依赖: L1
  ├─ GET /api/users/search (用户搜索)
  ├─ GET /api/stats/team/{id} (团队统计 ECharts)
  ├─ 最后一名 manager 保护
  └─ 共享数据集二次确认

v3.3.1 L3 (高级特性) ─── 依赖: L2
  ├─ 软删除/归档 (DELETE → 软删除 + POST /restore)
  ├─ 列表分页/搜索/排序 (6 params + 7 sort)
  ├─ Redis 缓存 (团队详情 5min TTL)
  └─ 缓存失效 (8 写操作)

v3.3.1 L4 (可视化与可观测) ─── 依赖: L3
  ├─ GET /api/audit-logs (系统级审计查询)
  ├─ GET /api/teams/{id}/activities (团队活动 Feed)
  ├─ GET /api/teams/_cache/stats (缓存统计)
  └─ 4 个复合索引 (team_id+created_at 等)

v3.3.1 L5 (性能与收尾) ─── 依赖: L4
  ├─ 性能基准 (locust 脚本)
  ├─ 数据库索引优化 (4 复合索引)
  ├─ 删除 fallback 旧 Teams.vue
  └─ 文档完善 (API + 用户手册 + 架构图)
```

## 六、数据流 (3 个核心场景)

### 6.1 创建团队 → 邀请成员 → 共享数据集

```
用户 alice (user_id=1)
  │
  ├─ POST /api/teams {name: "算法组"}
  │   └─ 创建 Team(owner_id=1) + TeamMember(user_id=1, role=manager)
  │   └─ log_audit("team_created", team_id=1)
  │
  ├─ POST /api/users/search?q=bob
  │   └─ 返回 [{id: 2, username: "bob"}]
  │
  ├─ POST /api/teams/1/members {user_id: 2, role: "editor"}
  │   └─ 创建 TeamMember(user_id=2, role=editor, invited_by_id=1)
  │   └─ log_audit("team_member_invited", team_id=1, detail={invitee_id: 2, invited_by: 1})
  │
  └─ POST /api/datasets/5/share?team_id=1
      └─ dataset.team_id = 1
      └─ log_audit("dataset_shared_to_team", team_id=1, resource_id=5)

用户 bob (user_id=2)
  │
  └─ GET /api/teams/1/datasets
      └─ 返回 dataset #5, my_access=editor
      └─ 可开始标注
```

### 6.2 审计查询 (admin)

```
admin
  │
  ├─ GET /api/audit-logs?team_id=1&event_type=team_member_invited
  │   └─ SQL: WHERE team_id=1 AND event_type='team_member_invited' ORDER BY created_at DESC
  │   └─ 走索引: ix_audit_log_event_created (event_type, created_at)
  │
  └─ GET /api/teams/1/activities?limit=50
      └─ SQL: WHERE team_id=1 ORDER BY created_at DESC LIMIT 50
      └─ 走索引: ix_audit_log_team_created (team_id, created_at)
```

### 6.3 缓存命中

```
用户请求 GET /api/teams/1
  │
  ├─ 1. 权限校验 (无缓存, 必须先查 DB)
  │     └─ SELECT * FROM team_member WHERE team_id=1 AND user_id=?
  │
  ├─ 2. Redis GET team:detail:1
  │     ├─ 命中 → 直接返回 (P95 < 50ms)
  │     └─ 未命中 → 进入第 3 步
  │
  └─ 3. 查 DB + 写缓存
        └─ SELECT * FROM team WHERE id=1
        └─ cache.set(team:detail:1, data, ttl=300)
        └─ 返回

写操作 (PATCH/DELETE/...) → cache.delete(team:detail:1)
```

## 七、扩展点

### 7.1 新增团队事件类型

1. 在 `audit_log.AUDIT_EVENT_TYPES` 或 `_EXTENDED_AUDIT_EVENT_TYPES` 中添加
2. 在 `team._TEAM_ACTIVITY_LABELS` 中添加语义化标签
3. 在前端 `EVENT_TYPE_OPTIONS` / `eventTypeOptions` 中添加选项

### 7.2 新增团队角色

1. 修改 `team_member.TEAM_ROLES` 元组
2. 修改 `WRITE_ROLES` (如适用)
3. 更新 `is_admin()` / `can_manage()` 等方法
4. 前端同步更新 `role-select` 选项

### 7.3 新增审计事件

1. 在业务端点调用 `await log_audit(...)`
2. 传入 `event_type` / `team_id` / `resource_*` / `detail`
3. 自动入库 + 出现在 L4 端点结果中

### 7.4 调整缓存策略

- 修改 `team.TEAM_DETAIL_TTL` (默认 300s)
- 在新写操作中调用 `_invalidate_team_detail(team_id)`
- 缓存键前缀 `_team_detail_key(team_id)` 可扩展 (e.g. 按用户角色)
