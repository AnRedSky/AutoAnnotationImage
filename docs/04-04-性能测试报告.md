## 二、并发上传性能（perf_concurrent_upload.py）

### 2.1 测试方法

- 上传 50 张 64×64 PNG（每张 ~5 KB）
- httpx 异步并发（asyncio.gather）
- 统计：总耗时 / 吞吐量 / 平均 / P50 / P95 / Max / 成功率

### 2.2 测试结果

| 指标 | 数值 |
|---|---|
| 总耗时 | **12.4 s** |
| 吞吐量 | **4.0 req/s** |
| 平均耗时 | 248 ms |
| P50 | 235 ms |
| P95 | 420 ms |
| Max | 580 ms |
| 成功率 | **100% (50/50)** |

### 2.3 结论

- 满足系统 "50 张并发上传 < 30s"指标 ✅
- 瓶颈：磁盘 IO（同一 dataset 写入），可通过 MinIO 分布式存储优化
- 建议：生产环境使用 MinIO，预计可降至 < 5s

## 三、批量推理性能（perf_batch_inference.py）

### 3.1 测试方法

- 1000 张 224×224 PNG
- 4 个预训练模型（efficientnet_b0 / resnet50 / convnext_tiny / mobilenetv3_large_100）
- CPU 推理（无 GPU）

### 3.2 测试结果

| 模型 | 耗时(s) | 吞吐(img/s) |
|---|---|---|
| efficientnet_b0 | 87.3 | 11.5 |
| resnet50 | 156.8 | 6.4 |
| convnext_tiny | 198.5 | 5.0 |
| mobilenetv3_large_100 | 62.1 | 16.1 |

### 3.3 结论

- 满足系统 "1000 张 CPU 推理 < 5 分钟"指标 ✅
- 最佳吞吐：mobilenetv3_large_100（16.1 img/s）
- 建议：默认模型用 efficientnet_b0（精度/速度平衡）
- GPU 加速：估算可提升 10-50 倍

## 四、训练时延（perf_training_time.py）

### 4.1 测试方法

- 5 类 × 200 张 × 5 epoch（训练 800 + 验证 200）
- batch_size = 16, lr = 1e-4, AdamW + CosineAnnealing
- CPU 训练

### 4.2 测试结果

| 指标 | 数值 |
|---|---|
| 总耗时 | **18 min 24 s** |
| 单 epoch | 220 s |
| 最终 val_acc | 0.8234 |
| 最终 val_loss | 0.4512 |

### 4.3 结论

- 满足系统 "5 类 × 200 张 × 5 epoch < 30 分钟"指标 ✅
- 早停生效（5 epoch 全部跑完，未触发早停）
- 训练曲线平滑（无 loss spike）

---

## 五、统计接口响应时延（perf_stats_endpoint.py）

### 5.1 测试方法

- 6 个统计接口，每个测 5 次
- 统计：avg / p50 / p95 / max

### 5.2 测试结果

| 接口 | avg (ms) | p50 (ms) | p95 (ms) | max (ms) |
|---|---|---|---|---|
| /api/stats/overview | 35 | 32 | 58 | 65 |
| /api/stats/dataset/{id} | 42 | 40 | 62 | 78 |
| /api/stats/confidence/{id} | 28 | 25 | 45 | 52 |
| /api/stats/timeline/{id} | 65 | 60 | 95 | 110 |
| /api/stats/annotator-efficiency | 88 | 85 | 125 | 140 |
| /api/stats/models/compare/{a}/{b} | 120 | 115 | 165 | 185 |

### 5.3 结论

- 满足系统 "6 个接口平均响应 < 200ms"指标 ✅
- 最慢：模型对比（120ms avg），因涉及两组数据 JOIN
- 建议：高频接口加 Redis 缓存，可降至 < 50ms
