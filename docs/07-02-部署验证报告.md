### 0.3 统一 .env 三层消费链路

```
┌────────────────────────────────────────────────────────┐
│  <项目根>/.env (Single Source of Truth)                │
│  12 个分组, 60+ 环境变量, 7 个 CHANGEME 占位符          │
└────────┬────────────────┬────────────────┬──────────────┘
         │ env_file       │ pydantic-      │ VITE_*
         │                │ settings       │ ARG
         ▼                ▼                ▼
   docker compose     Backend (API +    Frontend Build
   (7 services)       Worker)           (Vite)
   mysql/redis/      app/core/config.py  VITE_API_BASE_URL
   minio/api/        (.env 自动 fallback)
   workers/frontend
```

**核心收益**:
1. **一份配置 = 一处真相** — 消除"开发能跑、生产起不来"的偏差
2. **Docker Compose 与后端代码看到完全相同的配置** — 容器内 `MYSQL_HOST=mysql` 与本地 `MYSQL_HOST=127.0.0.1` 通过容器覆盖自动切换
3. **跨平台一致** — Windows/Linux/macOS 启动行为完全一致

### 0.4 一键部署 6 步流程

启动脚本 [start_docker.ps1](file:///D:/works/WorkBuddy/Myhome/ThesisDesignImplementation/thesis-image-annotation/scripts/start_docker.ps1) 自动完成：

| 步骤 | 操作 | 自动化程度 |
|---|---|---|
| 1️⃣ 准备 .env | 不存在则从 `.env.example` 复制 | 🟢 全自动 |
| 2️⃣ 生成强密钥 | 替换 7 个 CHANGEME 占位符 (SECRET_KEY/MYSQL_PASSWORD/...) | 🟢 全自动 |
| 3️⃣ 校验 Docker | 检查 docker / docker compose 版本 | 🟢 全自动 |
| 4️⃣ 构建镜像 | `docker compose build` 增量 / `--no-cache` 全量 | 🟢 全自动 |
| 5️⃣ 启动服务 | `docker compose up -d` (7 个服务) | 🟢 全自动 |
| 6️⃣ 等待 + 验证 | 等 healthy + 端到端 verify_deployment.py | 🟢 全自动 |


### 7.2 一致性保障机制

1. **项目根 .env 单一入口（v3.3.1 NEW）**
   - [docker-compose.yml](file:///D:/works/WorkBuddy/Myhome/ThesisDesignImplementation/thesis-image-annotation/docker-compose.yml) 所有服务 `env_file: - .env`
   - [app/core/config.py](file:///D:/works/WorkBuddy/Myhome/ThesisDesignImplementation/thesis-image-annotation/backend/app/core/config.py) 优先项目根 `.env`，回退 backend `.env`
   - **好处**: Docker Compose 与后端代码看到完全相同的配置，无配置漂移

2. **pydantic-settings 自动加载**
   - [app/core/config.py](file:///D:/works/WorkBuddy/Myhome/ThesisDesignImplementation/thesis-image-annotation/backend/app/core/config.py) 强制从项目根 `.env` 加载
   - 所有子模块必须用 `settings.X`, 不允许直接 `os.getenv`

3. **关键变量双向同步**
   - config.py 在加载时把关键环境变量 (REDIS_HOST/PORT 等) 写回 `os.environ`
   - 子模块 (database / minio_client) 即可用 `os.getenv` 也能用 `settings.X`

4. **占位符 fail-fast**
   - docker compose `${VAR:?msg required}` 启动时强制要求密钥
   - 防止误用默认密码

5. **validator 拦截**
   - `_validate_production_secrets` 在 APP_ENV=production 时强制校验密钥强度

6. **validate_config.py 静态校验**
   - 启动前确认所有 ${VAR:?required} 都已满足
   - 检查占位符是否已替换

7. **gen_secrets.py 自动生成（v3.3.1 NEW）**
   - [scripts/gen_secrets.py](file:///D:/works/WorkBuddy/Myhome/ThesisDesignImplementation/thesis-image-annotation/scripts/gen_secrets.py) 7 个字段强随机生成
   - 一键替换 .env 中所有 CHANGEME 占位符
   - 避免人工生成弱密钥

### 7.3 前端构建期 vs 运行期

| 维度 | 构建期 | 运行期 |
|---|---|---|
| 注入方式 | docker build ARG | runtime 通过 nginx 反代 |
| API 地址 | VITE_API_BASE_URL | 同源 /api |
| 容器间通信 | 不需要 | nginx → api:8000 |
| 配置来源 | `<项目根>/.env` (VITE_*) | `<项目根>/.env` (运行时不需要) |

**生产推荐**: `VITE_API_BASE_URL=` (空, 同源), 由 nginx 反代 `/api` 到后端, 避免跨域。

### 7.4 容器内 vs 宿主机的差异处理

docker-compose 通过 `environment:` 块**显式覆盖**容器内的服务地址：

```yaml
# docker-compose.yml
api:
  env_file:
    - .env                # 项目根 .env (含 MYSQL_HOST 等)
  environment:
    MYSQL_HOST: mysql      # 容器内必须用服务名（覆盖 .env 中的 127.0.0.1）
    MYSQL_PORT: "3306"
    REDIS_HOST: redis
    MINIO_ENDPOINT: minio:9000
```

**为什么**: 同一份 .env 想要同时供本地开发（127.0.0.1）和容器（服务名）使用，docker-compose 在容器启动时用 `environment:` 覆盖即可，无需在 .env 中维护两套值。
