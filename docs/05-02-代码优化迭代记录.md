# 代码优化迭代记录 (v3.1.0 Phase T — 前端训练性能)

---

## 一、问题背景与量化

后端 v3.1.0 (commit `5ec1284 perf(worker): v3.1.0 4-phase worker performance optimization`) 把每个 worker task 的 SSE 推送频率维持在 1s/帧, 同时单次推送数据量不变。该改动落地后, 前端训练页 (列表 + 详情同时打开) 出现以下症状:

| 现象 | 数据 |
|---|---|
| 同一 taskId 同时存在 2 条 SSE 连接 | 列表订阅 + 详情订阅, 后端每 1s 各查询一次 Celery + DB |
| 12 列表格行在每帧推送时整体重渲染 | `splice(idx, 1, next)` 触发整行 invalidate |
| 历史曲线每 5 秒固定轮询 | 详情打开期间, 与 SSE 帧驱动有 90%+ 冗余 |
| 列表兜底每 30 秒拉整页 | 与活跃 SSE 实时更新完全冗余 |

### 1.1 资源浪费估算

假设用户同时打开 3 个训练任务 + 详情弹窗, **N = 3**:

- 后端 SSE 推送查询次数: `2N × 1Hz = 6 次/秒` (理想 `N = 3 次/秒`, 浪费 50%)
- 前端 history 拉取次数: `1 个详情 × 1次/5s = 0.2 次/秒` (无论 SSE 是否已推到 epoch)
- 前端整页拉取次数: `1 次/30s = 0.033 次/秒` (无论列表是否在变)

### 1.2 期望目标

- 同 taskId 始终仅 1 条 SSE 连接
- SSE 帧推送时只更新变化字段 (细粒度)
- history 仅在 epoch 变更时拉 (兜底 8s 一次)
- 列表静默刷新在有活跃 SSE 时跳过

## 二、Phase T1 — SSE 连接池化 (单例 + 引用计数)

### 2.1 设计动机

`useTrainingListSSE` 在每个活跃 job 上独立建立 SSE, `useTrainingDetailStream` 在详情打开时又为同一 taskId 单独建立第二个 SSE。同一任务出现两个并发连接, 服务端每 1s 一次 Celery + DB 查询 × 2, 浪费 50% 后端资源。

### 2.2 解决方案: 新建 `useTrainingSsePool` 单例订阅池

**新增文件**: `frontend/src/composables/useTrainingSsePool.ts`

```
单例 (module 顶层 Map): 跨多个组件复用, Vue 多实例打开/关闭是同一个池
引用计数 (subscriber 数): 全部取消订阅时延迟 1.5s 再真正关闭, 防止 detail 弹窗
  快进快出导致反复 reconnect 的抖动
广播: 每条 frame 触发所有 listener, 各自决定如何处理 (列表行更新 / 详情重渲染 / 计数)
终态保持窗口: 连接进入 SUCCESS/FAILURE/REVOKED 后, 池先广播给所有监听器,
  再延迟 1.5s 清理连接 (避免新订阅者错失最后一帧)
```

**对外 API**:

```ts
const pool = useTrainingSsePool()
const off = pool.subscribe(taskId, {
  onMessage: (data) => updateRow(rowId, data),
  onComplete: () => reload(),
  onError: (err) => { /* 池内部统一收敛 */ },
})
// 卸载时:
off()
```

**关键参数**:

| 常量 | 值 | 含义 |
|---|---|---|
| `TERMINAL_GRACE_MS` | 1500 ms | 终态保持窗口, 让最后一帧广播到所有订阅者 |
| 默认退避 (活跃态) | 500 ms | 全员退订后延迟关闭, 给快进快出复用机会 |

### 2.3 联动改造

#### `useTrainingListSSE.ts`

旧实现每个 job 一个 `trainingApi.streamProgress` 独立 SSE, 新实现走 `pool.subscribe(taskId, listener)`:

```ts
// 旧: ~140 行, 内部管 stream 句柄 Map
// 新: ~98 行, listener 集合 Map (Unsubscribe 函数), 复用底层流
const off = pool.subscribe(taskId, {
  onMessage: (data) => {
    onProgressUpdate(j.id, data)
    if (isTerminal(data?.state)) onTerminalState(j.id)
  },
  onComplete: () => onComplete?.(j.id),
  onError: () => onError?.(j.id),
})
unsubs.set(j.id, off)
```

#### `useTrainingDetailStream.ts`

详情打开时 `pool.subscribe`, 关闭时 `off()`。池自动处理重连 / 复用 / 延迟关闭, 详情关闭后 1.5s 才真关连接 (允许详情快进快出场景复用)。

### 2.4 收益

- **同一 taskId 永远只 1 条 SSE 连接** (从 2N 降到 N, N=3 时从 6 降到 3)
- 后端每秒查询次数减半
- 详情弹窗快进快出不再触发反复 reconnect

## 三、Phase T2 — History 曲线刷新节流 + 智能触发

### 3.1 旧实现问题

`useTrainingDetailStream` 旧逻辑在 `startStream` 时启 `setInterval(refreshHistory, 5000)`, 5 秒轮询历史曲线:

- 训练活跃时, SSE 帧每秒都带新 epoch, 但 history 仍 5 秒才拉一次, **曲线滞后 1~5 秒**
- 训练稳态 (同一 epoch 持续多秒) 时, 5 秒拉一次完全冗余, 每次都拿同样数据
- 详情关闭时 `historyTimer` 必须在 onComplete / onError 都清, 否则网络异常断连会泄漏定时器

### 3.2 新实现: SSE 帧驱动 + 智能退避

引入 3 个常量:

```ts
const HISTORY_MIN_INTERVAL_MS = 1500   // 同一 taskId 至少 1.5 秒才允许刷新一次 (防抖)
const HISTORY_IDLE_BACKOFF_MS = 8000   // 无 epoch 变化时的兜底轮询间隔
const HISTORY_LIVE_CHECK_MS = 2000     // epoch 变更后多久不再主动拉 (SSE 接管即停止)
```

**新策略**:

1. **SSE 帧到时立即刷**: `current_epoch` 变化 → 立即调 `refreshHistory(taskId)`, 设置 `historyLiveUntilAt = now + 2000`
2. **节流防抖**: 任意两次 `refreshHistory` 至少间隔 1500ms
3. **兜底退避**: 若 8000ms 内无 epoch 变更, 退化到 `setTimeout(8000)` 轮询
4. **SSE 接管自动停止**: epoch 变更后 2s 内不再主动轮询 (避免与 SSE 推送争抢)

### 3.3 联动清理

- `onComplete` / `onError` 都清 `historyBackoffTimer`, 不再泄漏
- `cleanupDetail` 时统一清 `sseOff` + `historyBackoffTimer` + `chart.dispose`

### 3.4 收益

- 训练活跃时 history **滞后从 5s 降到 ~1.5s** (节流下限)
- 训练稳态时 history 拉取从 `1/5s` 降到 `1/8s`, **减少 37.5% 冗余**
- 定时器泄漏 Bug 一并修复 (网络异常断连时)

## 四、Phase T3 — 细粒度行更新

### 4.1 旧实现问题

`useTrainingJobs.ts:updateJobProgressInPlace` 旧逻辑:

```ts
const next = { ...cur }
if (data.state) next.state = data.state
// ... 一堆字段赋值
jobs.value.splice(idx, 1, next)  // 触发整行重新渲染
```

`splice(idx, 1, next)` 等价于替换数组第 idx 位为新对象, Vue 响应式系统判定该行引用变化, **整行 12 列全部重新计算**。SSE 1Hz 推送下, 每秒整页 12 列 × N 行全部 invalidate。

### 4.2 新实现: 直接修改响应式属性

```ts
let touched = false
if (data.state) { cur.state = data.state; touched = true }
if (typeof data.progress === 'number') { cur.progress = data.progress; touched = true }
// ... 逐字段
if (!touched) return
jobs.value[idx] = cur  // 显式浅 trigger, 让 <el-table> 检测到行对象引用更新
```

直接在已响应式代理上写属性, 触发细粒度依赖, **只更新引用了变化字段的 cell** (Vue 3 Proxy reactivity)。

### 4.3 收益

- SSE 高频 (秒级 progress) 路径下, 整行重渲染 → 单 cell 更新
- 空帧 (data 为空) 时直接 return, 避免空 Object.assign 触发依赖
- 12 列 × N 行的表格 CPU 占用显著下降

## 五、Phase T4 — 静默刷新与详情联动

### 5.1 旧实现问题

`useSilentRefresh` 旧逻辑固定每 30s 拉整页, 完全不知道活跃 SSE 的存在:

- 与活跃 SSE 的实时更新 100% 冗余
- 详情打开时虽然 `skipWhen: () => detailVisible.value` 跳过, 但仍有竞态 (刚拉了整页就开详情 → 浪费一次)

### 5.2 新实现: 探测活跃流 + 暂停/恢复

```ts
export function useSilentRefresh(options) {
  const { intervalMs = 60000, skipWhen, onTick, skipWhenSseActive = true } = options
  const pool = useTrainingSsePool()

  const tick = () => {
    if (paused.value) return                              // 手动暂停中 → 跳过
    if (skipWhen?.()) return                              // 用户自定义 skip
    if (skipWhenSseActive && pool.getActiveTaskIds().length > 0) return  // 任意活跃 SSE → 跳过
    onTick()
  }
  // ...
  const pause = () => { paused.value = true }   // 临时暂停 (不销毁定时器)
  const resume = () => { paused.value = false }
}
```

**Training/index.vue 联动**:

```ts
const { start, stop, pause, resume } = useSilentRefresh({ intervalMs: 60000, ... })

watch(detailVisible, (v) => {
  if (v) pause()
  else resume()
})
```

### 5.3 收益

- 默认间隔 30s → 60s (SSE 接管 99% 场景, 静默刷新只是极端兜底)
- 有活跃 SSE 流时静默刷新自动跳过 (无任何浪费)
- 详情打开 / 关闭联动 pause / resume, **零竞态零浪费**
- `pause` 不销毁定时器, 仅阻止 onTick, resume 后立即进入下一周期
