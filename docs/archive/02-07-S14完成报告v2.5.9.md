## 二、S14 详细改动

### v2.5.7 — Annotate.vue 子组件 + composable 拆分重构 (commit 0127048)

**文件**: 9 文件 (2 新增页面私有子组件 + 3 新增业务通用组件 + 3 新增 composable + 1 修改)

**问题**: Annotate.vue 单文件 1059 行, 超过 views ≤ 1000 行硬性限制。模板 + 脚本 + 样式全部混在一个文件里, 维护困难。

**拆分方案 (4 层组件 + 3 个 composable)**:

| 层级 | 文件 | 行数 | 职责 |
|---|---|---|---|
| 页面私有子组件 | `AnnotationToolbar.vue` | 254 | 顶部 5 个统计卡片 + 工具栏 |
| 页面私有子组件 | `AnnotationCanvas.vue` | 52 | 左侧画布壳 + slot 注入 annotator |
| 业务通用组件 | `ClassificationPanel.vue` | 133 | 图像分类右侧 AI 候选面板 |
| 业务通用组件 | `DetectionPanel.vue` | 321 | 目标检测右侧 5 sections |
| 业务通用组件 | `SegmentationPanel.vue` | 208 | 图像分割右侧 6 sections |
| Composable | `useDetectionAnnotate.ts` | 196 | 检测 state + 加载/保存/popover/catColor |
| Composable | `useSegmentationAnnotate.ts` | 124 | 分割 state + 加载/保存/mode handler |
| Composable | `useAutoAnnotate.ts` | 198 | AI 预标注逻辑 (分类/检测/分割) |

**Annotate.vue 瘦身结果**: 1059 → 597 行 (-462 行, -43.6%)

**设计原则落地**:
1. views 页面 ≤ 1000 行: 597 ✅
2. 组件四层分层: common (0) / business (3 Panel) / 页面私有 (2) / 页面根 (1) ✅
3. 严格单向数据流: Panel 通过 props 接数据 + emit 抛事件 ✅
4. 组件禁止直接引入 store/api: 3 个 Panel 完全无 API 调用 ✅
5. 复杂逻辑抽离 composable: 检测/分割/AI 业务全走 composable ✅

**附带 Bug 修复 (TS strict 校验发现)**:
1. ClassificationPanel.vue: `findCategory(c.label)` 改为 `findCategory(c.name)` — Category 接口无 label 字段
2. AnnotationToolbar.vue: `(m.accuracy * 100)` 加 `?? 0` 兜底 — accuracy 是 optional

**验证**: `vue-tsc --noEmit` 0 错误, `npm run build` 通过 (15.06s, Annotate-*.js = 67.77 kB)

### v2.5.8 — 前端项目整体架构优化 (commit 99ada7f + 35a0c85)

**文件**: 19 文件迁移 (git mv, similarity 97-100%)

**审计结论**: 所有 15 个组件均只属于单一业务模块, 0 个跨业务共享, `src/components/` 沦为"无业务归属混合目录"。

**业务模块识别 (8 个)**: annotate / datasets / datasetDetail / training / models / dashboard / login / layout

**视图业务模块化**: 8 个 view 文件从 `src/views/` 平铺 → 每个业务独立文件夹 + index.vue 入口

**组件私有化**: 15 个组件按业务模块归位到 view 私有 `components/` 子目录, 删除 `src/components/` 全集

| 业务模块 | 组件数 | 组件清单 |
|---|---|---|
| Annotate | 8 | AnnotationCanvas, AnnotationToolbar, ClassificationAnnotator, ClassificationPanel, DetectionAnnotator, DetectionPanel, SegmentationAnnotator, SegmentationPanel |
| Datasets | 2 | UploadQueue, DetectionStatsPanel |
| DatasetDetail | 2 | AnnotationViewer, PreviewList |
| Training | 3 | TrainingParamsForm, StateBadge, BaseModelSelect |

**跨页面共享方案**: UploadQueue 唯一跨页面组件 (Datasets + DatasetDetail), 物理位置在 `views/Datasets/components/`, DatasetDetail 通过相对路径 `'../Datasets/components/UploadQueue.vue'` 引用。

**import 路径变更**: 全部从绝对路径 `@/components/xxx` 改为相对路径 `./components/xxx`

**路由更新**: `src/router/index.ts` 中 8 处 component 引用从 `'@/views/Xxx.vue'` 改为 `'@/views/Xxx/index.vue'`

**代码分割效果**: build 后每个页面独立 chunk (index-*.js), 业务隔离更彻底

**验证**: `vue-tsc --noEmit` 0 错误; `npm run build` 通过 (15.21s); 全局 `@/components/` 旧路径搜索 0 残留

### 画布布局优化 (commit 7ed575a)

**文件**: 6 文件 (1 新增 + 5 修改), 817 行新增 / 259 行删除

**新增工具**: `canvasLayout.ts` (261 行)

| 函数 | 用途 |
|---|---|
| `CANVAS_W` / `CANVAS_H` | 实际绘制区尺寸 (600×400) |
| `WRAP_W` / `WRAP_H` | 外层容器尺寸 (600×480) |
| `SAFE_ZONE` | 上下文案安全区高度 (40px) |
| `clampToWrap` | 限制元素在容器内 |
| `isOverlapCanvas` | 判定矩形与画布绘制区重叠 |
| `getImageDrawRect` | 计算 letterbox 矩形 (检测/分割任务) |

**统一 info-panel 布局**:
- 三个 annotator 组件均实现统一的右上角 info-panel 两行紧凑布局
- 坐标浮标与画布尺寸信息统一整合至右上角区域

**画布完全填充容器**:
- `AnnotationCanvas.vue` 改为 flex 布局
- wrap 容器设置 `width:100%` / `height:100%` / `min-height:480`
- canvas-stage 设置 100% 填充 wrap
- 图片使用 `object-fit:contain` (分类) 或 `getImageDrawRect` (检测/分割) 自动居中

**ResizeObserver 自适应**:
- `useCanvasSize` composable 监听容器尺寸变化
- 窗口/侧栏缩放时自动触发重绘图片层、mask 层和 bbox 层

**验证**: TypeScript 类型检查与 Vite 构建均通过, 功能无回归

## 三、S14 架构设计原则落地

### 组件四层分层标准

| 层级 | 目录 | 数量 | 说明 |
|---|---|---|---|
| 公共原子组件 (common/) | src/components/common/ | 0 | 项目暂无纯 UI 原子组件, 全部用 Element Plus |
| 业务通用组件 (xxx-business/) | - | 0 | 每个组件只服务单一业务 |
| 页面私有子组件 | views/xxx-page/components/ | 16 | 含 v2.5.9 新增 AnnotationGuideSidebar |
| 页面根视图 | views/xxx-page/index.vue | 8 | 每个业务独立文件夹 + index.vue 入口 |

### 跨模块引用最佳实践
- 跨页面共享组件用相对路径 `'../<同模块其他页>/components/xxx.vue'`
- 不上提到 public 目录 (避免过度抽象)
- 若未来需第 3 个模块引用, 再上提到 `src/components/` (达到"2+ 业务模块"门槛)
