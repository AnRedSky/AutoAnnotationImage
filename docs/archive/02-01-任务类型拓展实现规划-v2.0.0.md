## 一、背景与目标

### 1.1 当前现状 (v1.0.0)

| 维度 | 现状 |
|---|---|
| 任务类型枚举 | DB + 前端均支持 3 种 (classification / detection / segmentation) |
| 图像分类 (classification) | **完全实现**: 标注 / AI 预标注 / 训练 / 激活 / 导出 |
| 目标检测 (detection) | **仅占位**: 无 bbox 数据模型 / 无标注工具 / 无训练代码 |
| 图像分割 (segmentation) | **仅占位**: 无 mask 数据模型 / 无标注工具 / 无训练代码 |

### 1.2 目标 (v2.0.0)

把 detection / segmentation 从占位升级为**完整功能**, 三大任务类型齐头并进。

| 任务类型 | 标注方式 | ML 框架 | 评估指标 | 导出格式 |
|---|---|---|---|---|
| classification (已有) | 单标签下拉 | timm + CrossEntropy | acc/precision/recall/f1 + 混淆矩阵 | COCO-cls / YOLO-cls / CSV |
| **detection (新增)** | 矩形框 (canvas) | ultralytics YOLOv8 | mAP@0.5 / mAP@0.5:0.95 / P / R | YOLO-det / COCO-det / CSV |
| **segmentation (新增)** | 多边形 (canvas) | torchvision DeepLabV3+ | mIoU / pixel-acc / dice | VOC / COCO-seg / CSV |

### 1.3 任务范围

**P0 必须实现**:
- detection 全链路 (数据模型 / 标注 / AI / 训练 / 评估 / 导出 / 激活)
- segmentation 全链路 (同上)

**P1 尽量实现**:
- 三任务类型统一 Dashboard 统计
- 训练任务混排 (按 task_type 过滤)

**P2 可选**:
- SAM (Segment Anything) 集成 (零样本分割)
- YOLOv8-seg 实例分割 (作为 detection 的扩展)

## 二、架构设计

### 2.1 数据模型扩展

**原则**: 兼容 v1.0.0 已有数据, 不破坏 classification 流程。新增字段用 nullable / 新建独立表。

#### 2.1.1 Image 表扩展

```python
# image.py 新增字段
task_type: Mapped[str] = mapped_column(
    Enum("classification", "detection", "segmentation", name="image_task_type"),
    default="classification", nullable=False, index=True
)
# 冗余存储 task_type, 避免每次 join dataset 读
```

#### 2.1.2 检测数据表 (新增)

```python
# bbox_annotation.py
class BBoxAnnotation(Base):
    __tablename__ = "bbox_annotation"
    id: int
    image_id: int (FK image.id, ON DELETE CASCADE, INDEX)
    category_id: int (FK category.id, nullable, INDEX)
    x_min: float (归一化 0-1)
    y_min: float
    x_max: float
    y_max: float
    confidence: float (nullable, AI 标注时填)
    source: Enum('human', 'ai', 'human_corrected')
    annotated_by: int (FK user.id, nullable)
    created_at: datetime
    updated_at: datetime
```

#### 2.1.3 分割数据表 (新增)

```python
# segmentation_mask.py
class SegmentationMask(Base):
    __tablename__ = "segmentation_mask"
    id: int
    image_id: int (FK image.id, ON DELETE CASCADE, UNIQUE)
    mask_path: str (PNG 文件, 索引调色板, H x W)
    width: int
    height: int
    source: Enum('human', 'ai', 'human_corrected')
    annotated_by: int (FK user.id, nullable)
    created_at: datetime
    updated_at: datetime
```

#### 2.1.4 Category 表扩展

```python
# category.py 新增
color: str = "#409EFF"  # 已有字段, 复用 (前端 canvas 渲染用)
# 检测场景: 类别对应 color
# 分割场景: 类别索引 = mask 像素值
```

#### 2.1.5 ModelVersion 表扩展

```python
# model_version.py 新增
task_type: Enum('classification', 'detection', 'segmentation')
# 检测 / 分割: 额外保存 model_file (.pt for YOLO / .pth for torchvision)
# 评估指标字段根据 task_type 不同存
classification_metrics: JSON (已有, precision/recall/f1/accuracy)
detection_metrics: JSON nullable (mAP_50, mAP_50_95, precision, recall)
segmentation_metrics: JSON nullable (mIoU, pixel_acc, dice)
```

### 2.3 ML 框架选型

| **segmentation** | **torchvision** | **deeplabv3_resnet50 / deeplabv3_resnet101 / fcn_resnet50** | torchvision |

## 三、迭代计划 (8 个冲刺)

> 每周 1-2 个冲刺, 总计 4-5 周。每个冲刺结束必须: 代码提交 + 单元测试通过 + 文档同步。

### 冲刺 S1: 基础设施 (P0, 3-4 天)

**目标**: 把"占位"变成"可用脚手架", 跑通 detection/segmentation 的数据流空壳。

**任务**:
1. **依赖增量**
   - `pyproject.toml` + `requirements.txt` 加 ultralytics / opencv-python / pycocotools
   - `frontend/package.json` 不变 (检测画布纯 canvas, 不引第三方库)
2. **数据库迁移**
   - 新增 `bbox_annotation` / `segmentation_mask` 表 + 索引
   - `image` 加 `task_type` 字段 (默认 classification 兼容老数据)
   - `model_version` 加 `task_type` + 任务专属 metrics JSON 字段
   - 迁移脚本: `backend/migrations/2XXX_add_detection_segmentation.py`
3. **后端 Pydantic Schema**
   - `app/schemas/detection.py` (BBoxCreate / BBoxOut / DetectionJobStart)
   - `app/schemas/segmentation.py` (SegmentationMaskOut / SegmentationJobStart)
4. **后端 Pydantic Schema (共享)**
   - `app/schemas/dataset.py` 加 `task_config` 响应字段
5. **任务类型统一枚举**
   - 抽 `app/schemas/enums.py` 集中所有 task_type / status 字符串
   - 重构已有 `image.py` / `dataset.py` 引用

**验收**:
- 已有 17 条 pytest 全部通过
- 新增 4 条 schema 单元测试
- 迁移脚本可重复执行 (idempotent)
- 1 个 commit: `feat(scaffold): 任务类型拓展基础设施 (检测+分割) 数据模型与枚举`

**风险**:
- 迁移脚本破坏老数据 → 用 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` (MySQL 8 支持) 或 `INFORMATION_SCHEMA.COLUMNS` 检查
- 测试环境 SQLite vs 生产 MySQL 行为差异 → 字段类型用通用 `Integer / String / JSON`, 不用 MySQL 专属

### 冲刺 S3: 检测 - AI + 训练 (P0, 5-6 天) ⭐ 最大冲刺

**目标**: YOLOv8 微调 + 推理全链路, 产出可用的 .pt 模型文件。

**任务**:
1. **ML 封装**: `app/ml/detection/` (新目录)
   - `yolo_dataset.py` - 读 BBoxAnnotation 转换为 YOLO txt
   - `yolo_train.py` - ultralytics YOLO CLI 包装, 进度回调
   - `yolo_predict.py` - 单图 / 批量推理
2. **Celery 任务**: `app/workers/detection_tasks.py`
   - `bbox_auto_annotate_task` - 异步批量推理
   - `bbox_train_task` - 异步微调, 进度 + checkpoint
3. **后端 API**:
   - `POST /api/detection/auto-annotate/{ds_id}` (sync/async 分流, 同 classification)
   - `POST /api/detection/train` (提交 Celery, 同 classification 接口签名)
   - `GET /api/detection/jobs/{id}/progress` (SSE 实时)
4. **进度回调机制**:
   - 沿用 v1.0.0 的 `progress_callback` + `extra` dict 模式
   - extra 字段加 `epoch / batch / map50 / map50_95`
5. **测试**: `tests/test_detection_train.py` - 10 条 (启动 / 进度 / 完成 / 异常)
6. **Demo 数据**: `scripts/prepare_detection_demo.py` - 用 COCO 128 跑通训练

**验收**:
- 在 demo 数据上 (50 张检测图) 训练 1 个 epoch 成功, mAP@0.5 > 0
- Celery 异步任务可启动, SSE 实时推进度
- 异常路径 (显存不足) 写 PENDING → FAILURE

**Commit**: 分 3 个:
- `feat(detection): YOLOv8 训练/推理/异步任务链路`
- `feat(detection): 检测专属进度回调 + SSE 推送`
- `test(detection): 训练任务 pytest 用例 10 条`

**风险**:
- ultralytics 与现有 timm PyTorch 版本冲突 → pin torch==2.2.0
- COCO 评估慢 → mAP 算子只算 1 次 (训练结束)
- CPU 训练 mAP 极低 → demo 数据集 50 张够, 论文承认 CPU 限制

| ultralytics | >=8.0.0 | YOLOv8 检测 | 需联网下载预训练权重 (yolov8n.pt ~6MB) |
| opencv-python | >=4.8 | bbox / mask 后处理 | 与已有 cv2 冲突需 pin |
| pycocotools | >=2.0.6 | COCO mAP | Windows 编译慢, 用 pre-built wheel |
| torchvision | 已有 (0.17+) | DeepLabV3+ | 复用, 无风险 |

### 4.2 技术风险

| 风险 | 影响 | 应对 |
|---|---|---|
| ultralytics 与 PyTorch 2.2 兼容 | 训练启动失败 | pin `torch==2.2.0` + `ultralytics==8.0.196` |
| YOLOv8 CPU 训练慢 | demo 跑不完 | demo 用 50 张 + 1 epoch, 论文承认 GPU 限制 |
| COCO mAP 计算慢 | 训练卡住 | mAP 只算最终 epoch, 不每 epoch 算 |
| 分割 mask PNG 写入慢 | 上传阻塞 | 后台异步写, 写完回调更新状态 |
| 大数据集 bbox 数量爆炸 | DB 性能 | 按 image_id 分区索引, 单图 ≤ 100 bbox 限制 |
| 画布卡顿 (大图 + 多 bbox) | 用户体验 | canvas 分层 (背景图 + bbox 层), bbox 限制 200 |

### 4.3 时间风险

| 风险 | 影响 | 应对 |
|---|---|---|
| S3 / S5 训练冲刺延期 | 后续冲刺压紧 | 调小 demo 数据 (50 → 30 张), 砍 P2 |
| S7 前端重构延期 | E2E 跑不起来 | 最小可用: 检测画布先上, 分割画布后置 |
| 测试覆盖不够 | 答辩被问 | S8 集中补 10 条 e2e |
