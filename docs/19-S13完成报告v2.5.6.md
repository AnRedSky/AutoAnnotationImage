## 二、S13 详细改动

### v2.5.1 — 统一标注工作台布局 + 修复保存按钮 disabled (commit 43c4745)

**文件**: DetectionAnnotator.vue / SegmentationAnnotator.vue / Annotate.vue (3 文件)

**布局标准化**:
- SegmentationAnnotator 极简化重构: 移除内部 .toolbar/.palette/.actions/.meta, 只保留双 canvas 叠层 + coord/size/mode overlay
- 与 DetectionAnnotator v2.3.1 极简版风格完全对齐
- 三种任务类型右侧操作面板统一为 `el-card title=` + 8 sections 编号前缀 + el-button-group flex:1 风格

**保存按钮 disabled 修复**:
- 根因: 父组件模板用 `detAnnotRef?.dirty?.value` 深层 ref 访问, Vue 模板响应式追踪失效
- 解决方案: 子组件 `emit('dirty-change', v)` 事件 + 父组件本地 `detDirty`/`segDirty` ref 同步
- DetectionAnnotator: `defineEmits` 新增 `(e: 'dirty-change', dirty: boolean): void`, dirty computed 后新增 `watch(dirty, (v) => emit('dirty-change', v), { immediate: true })`
- SegmentationAnnotator: 移除所有图标 import + modeTagType computed; 新增 `cancel()` 方法; `defineExpose` 新增 `maskStats` / `clearMask` / `cancel`
- Annotate.vue: 新增 `detDirty`/`segDirty` 本地 ref + handler; 子组件 `@dirty-change` 监听; 保存/取消末尾加 `await nextTick(); xxxRef.value?.resetInitial?.()`

**关键设计原则 (Vue 3 响应式)**: `defineExpose` 暴露的 ref/computed 在父组件通过模板 ref 访问时仍是 ref 对象, 深层属性访问的响应式依赖追踪在模板编译中不可靠, 必须用 emit 事件 + 父组件本地 ref 同步。

**验证**: 前端 `npm run build` 通过 (13.69s); 后端 pytest 14/14 通过

### v2.5.5-fix / v2.5.5-fix-2 — 修复 TDZ 错误 (commit 2b681c8 / 5c52946)

**文件**: Annotate.vue (1 文件)

**错误**: `Cannot access 'detAnnot' before initialization at watch getter at setup`
**根因**: v2.5.5 新增的 watch 在 setup 阶段立即执行 getter 追踪依赖, getter 中读 `detAnnot.value?.selectedIndex?.value`, 但 `detAnnot` 是后定义的 computed, setup 顺序执行时 watch 先执行导致 TDZ 错误
**修复**: 把整个 watch 块移到 detAnnotRef 定义后

**Vue 3 watch TDZ 最佳实践**: watch 默认不立即执行, 但 setup 期间 getter 会被封装, 真正执行是 lazy 的。但如果 getter 内部引用了 TDZ 中的 const 声明, 在 setup 阶段 reactive 依赖追踪时 getter 也会被同步调用, 触发 TDZ。解决方案: 把 watch 移到它依赖的状态定义之后。

**验证**: 前端 `npm run build` 通过 (13.86s)
