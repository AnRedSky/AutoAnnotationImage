# 图像标注平台 — 项目说明文档

---

## 一、项目概览

### 1.1 项目名称

**图像标注平台 (Image Annotation Platform)** — 基于深度学习的图像分类 / 目标检测 / 图像分割协同标注与训练系统。

### 1.2 项目定位

一款面向工业质检、内容审核、商品识别、医疗影像等真实业务场景的**协同式**图像标注与人机协同训练平台。系统使用 timm 预训练模型与 Ultralytics YOLOv8 / DeepLabV3+ 模型对图像进行批量预标注，标注员在预标注结果上**快速确认或修正**，并支持基于已标注数据**持续训练自有模型**，形成"AI 预标注 → 人工修正 → 增量训练"的人机协同闭环。

### 1.3 项目核心价值

| 价值点 | 描述 |
|---|---|
| **降本** | AI 预标注后人工只需确认/修正，单张图片平均节省 3-5 秒 |
| **提效** | 一次预标注可批量处理数千张图片；支持同步与异步两种推理模式 |
| **可持续** | 人工修正的数据自动反哺训练集，越用越准 |
| **多任务** | 一套平台同时支持分类、目标检测、语义分割三类任务 |
| **可审计** | 所有标注行为写入审计日志（confirm / correct + 耗时） |
| **可导出** | 支持 COCO / YOLO / CSV 三种主流数据集格式导出 |
| **可协作** | 团队 / 成员 / 角色三级权限管理，跨用户数据集共享 |
| **可观测** | 端到端实时 SSE 进度推送、训练曲线、效率统计面板 |

### 1.4 业务应用场景

| 场景 | 典型价值体现 |
|------|---------|
| 工业质检 | 替代人工目检，缺陷漏检率下降 60%+ |
| 内容审核 | 违规图片自动分流，人工仅复核低置信度样本 |
| 商品识别 | 新品上架自动归类，人工微调少量边界样本 |
| 医疗影像 | AI 预筛 + 医生复核，诊断效率显著提升 |
| 安防监控 | 异常行为自动告警，安全人员聚焦高风险事件 |
| 技术研究 | 标注数据可直接导出 COCO/YOLO 进入下游研究流水线 |

### 1.5 范围边界

**已实现并稳定运行**：
- 图像分类（单标签）场景的预标注 + 人工修正
- 目标检测（多目标 BBox）场景的预标注 + 人工修正
- 图像分割（语义分割 mask）场景的预标注 + 人工修正
- 批量上传、AI 预标注、Top-5 候选展示与一键确认
- 基于 timm 预训练模型的迁移学习微调训练
- 基于 YOLOv8 的目标检测训练与推理
- 基于 DeepLabV3+ 的语义分割训练与推理
- 模型版本管理、多激活并存、效果对比
- 标注数据导出（COCO / YOLO / CSV）
- 团队协作与权限管理
- 端到端实时 SSE 进度推送
- 基础统计、效率分析与可视化面板
- 完整审计日志与不合格图片标记

**规划中或未实现**：
- 实时多人协作（WebSocket 同步光标）
- 模型部署为在线推理服务
- 多标签分类场景
- 移动端 / 离线标注

## 二、平台核心能力

### 2.1 人机协同标注闭环

平台以"AI 预标注 + 人工修正"为核心范式，把传统的全人工标注工作流提升为 AI 辅助 + 人工复核模式：

1. **AI 预标注**：上传图片后，选择 timm / YOLO / DeepLabV3+ 预训练模型，平台对每张图片输出 Top-5 候选标签 / BBox / mask
2. **置信度分流**：根据用户设定的置信度阈值（默认 0.6），自动决定哪些图片可被 AI 直接标定（≥ 阈值），哪些需要人工复核（< 阈值）
3. **高效人工 UI**：键盘快捷键标注、标签联想、实时计时、批量操作
4. **增量训练闭环**：人工修正的数据自动加入训练集，一键 Fine-tune 出新模型版本
5. **模型对比**：每个数据集可有多个激活模型版本，供下游推理灵活选择

### 2.2 三类任务统一支持

| 任务类型 | 模型后端 | 输出 | 训练框架 |
|---|---|---|---|
| 图像分类 | timm (700+ SOTA 模型) | 单标签 | PyTorch + timm |
| 目标检测 | Ultralytics YOLOv8 (n/s/m/l/x) | 多目标 BBox + 类别 | Ultralytics |
| 图像分割 | DeepLabV3+ (ResNet50/101 backbone) | 像素级 mask PNG | torchvision + albumentations |

三种任务的标注、训练、推理、导出逻辑统一封装在前端工作台与后端业务服务中，使用一致的命名空间与权限模型。

### 2.3 实时进度推送（SSE）

平台为长时间运行的训练与自动标注任务提供基于 Server-Sent Events (SSE) 的端到端实时进度推送：

- **训练任务**：每秒推送 epoch 进度、loss、accuracy、learning rate
- **自动标注**：实时推送已处理图片数 / 总数、当前吞吐量
- **历史曲线**：epoch 结束后追加持久化，前端可还原完整训练轨迹
- **前端优化**：单例 SSE 池 + 引用计数，同一任务只保留 1 条连接；终态保持 1.5s 后清理

### 2.4 模型版本与多激活管理

- 每个数据集可有多个训练产出的模型版本（ModelVersion）
- 支持多激活并存（不强制单激活）
- 模型详情可看训练指标（mAP / loss / 训练时间）、关联数据集
- 可对模型进行 activate / deactivate / 删除操作
- 自动标注时可选择 ImageNet 预训练或自训练微调模型

## 三、技术架构

### 3.1 整体技术栈

| 层级 | 选型 |
|------|------|
| 前端 | Vue 3 + Vite + TypeScript + Element Plus + ECharts + Pinia + Axios |
| 后端 | Python 3.10+ + FastAPI + SQLAlchemy 2.0 (async) + Pydantic v2 |
| 数据库 | MySQL 8.0 + Redis 7 |
| 对象存储 | MinIO (开发) / 本地文件系统 (生产可切换) |
| 深度学习 | PyTorch 2.2 + torchvision 0.17 + timm 0.9.12 + ultralytics 8.0.196 |
| 异步任务 | Celery 5.3 (双队列：train / annotate) |
| 部署 | Docker + Docker Compose |
| 配置 | pydantic-settings (.env 自动加载) |

### 3.2 后端多应用架构（v3.0.0 Stage 2 重构）

后端从单文件 main.py 重构为四大业务应用 + 自动发现 + 自动挂载的模块化架构：

```
backend/app/
├── admin/        # 用户管理、统计、团队、系统级
├── auth/         # 登录、注册、Token 签发
├── tasks/        # 数据集、图像、训练、模型、检测、分割、文件、自动标注
├── annotation/   # BBox 标注、分割 mask 标注
├── common/       # 接口规范、几何工具、枚举、权限
├── core/         # 配置、安全、CLI、启动分析
├── database/     # SQLAlchemy 引擎、Redis 客户端
├── middleware/   # CORS、RequestID、RequestTiming、异常处理
├── schemas/      # Pydantic DTO
├── registry.py   # AppRegistry / MiddlewareRegistry / PluginRegistry
└── main.py       # 入口 (零硬编码路由)
```

**核心机制**：
- `AppInterface`：每个业务应用实现此接口，声明路由条目与启动钩子
- `AppRegistry.iter_routes()`：自动产出 14 个 RouteEntry，main.py 0 硬编码
- `MiddlewareRegistry.apply()`：中间件按 `order` 升序自动注册
- `PluginRegistry`：存储 / ML / 任务队列 / 通知四大插件可热插拔

### 3.3 前端模块化结构（v3.x）

```
frontend/src/
├── api/         # 与后端 1:1 对齐的 HTTP 客户端 (含 SSE 封装)
├── composables/ # 业务复用逻辑 (useTrainingSsePool 等)
├── router/      # 路由配置 + 权限守卫
├── stores/      # Pinia 状态 (user, dataset 等)
├── styles/      # 全局样式 (admin.css, annotator.css 等)
├── utils/       # 工具函数 (sse, date, format 等)
├── views/
│   ├── Login/        # 登录
│   ├── Layout/       # 主框架
│   ├── Dashboard/    # 系统总览
│   ├── Datasets/     # 数据集列表
│   ├── DatasetDetail/# 数据集详情
│   ├── Annotate/     # 标注工作台
│   ├── Training/     # 训练管理
│   ├── Models/       # 模型管理
│   ├── Admin/        # 管理员功能 (用户/团队/审计)
│   └── Profile/      # 个人中心
└── main.ts
```

**前端规范落地**：
- Vue 文件单文件 ≤ 1000 行（弹窗 / 表格 / 卡片按职责拆分子组件）
- 严格单向数据流（父传子 props、子通信父 emit）
- 公共 / 业务 / 页面私有三层组件分层
- 底层组件禁止 useStore，状态由页面层下发
- 所有 vue 组件均使用 `<style scoped>` 样式隔离

## 四、功能模块详细说明

### 4.1 认证与用户管理

| 子功能 | 说明 |
|---|---|
| 登录 | JWT 签发，标准 OAuth2PasswordRequestForm 协议，HS256 签名 |

| 审计日志 (admin) | 关键操作（登录/标注/训练/管理动作）全程可追溯 |
| 个人中心 | 个人信息修改、密码修改、Token 状态查看 |

### 4.2 数据集管理

| 子功能 | 说明 |
|---|---|
| 创建数据集 | 必填名称、任务类型（classification/detection/segmentation） |
| 类别管理 | 数据集内增删改类别，类别可携带描述与颜色 |
| 批量上传 | 支持拖拽多文件 / 选文件，实时显示进度条 |

| 团队共享 | 团队成员可访问所属团队的数据集 |
| 权限 | owner / editor / viewer 三级读写权限 |

### 4.3 标注工作台

#### 4.3.1 分类标注
- Top-5 候选标签展示，置信度可视化
- 键盘快捷键（数字键选标签，A 接受，D 跳过）
- 实时计时（AI 节省时间可量化）
- 单图确认 / 修正 / 清空 / 标记不合格
- 不合格图片标记（reason + 自定义文案）正交于 status 状态机

#### 4.3.2 目标检测标注
- 矩形框绘制（鼠标拖拽）
- 类别选择（标注时关联）
- 整图重画 / 单框删除 / 整图清空
- 跨图复制建议（同数据集相似图片可复用 BBox）
- 归一化坐标（与 YOLO txt 一致）

#### 4.3.3 语义分割标注
- 像素级 mask 上传（PNG 调色板格式）
- 类别关联
- 单图 mask 拉取 / 替换 / 清除
- 物理文件与 DB 记录同步管理

### 4.4 AI 自动标注

| 模式 | 任务类型 | 描述 |
|---|---|---|
| 同步预标注 | classification | 单数据集 < 1000 张图时，直接同步返回结果 |
| 异步预标注 | classification | 走 Celery 队列，返回 task_id，前端订阅 SSE |
| 预训练 YOLO | detection | 用 YOLOv8n/s/m/l/x 预训练权重自动标 BBox |
| 微调 YOLO | detection | 用数据集训练产出的 ModelVersion 自动标 BBox |
| 预训练 DeepLabV3+ | segmentation | 用 torchvision COCO 21 类预训练推理 |
| 微调分割 | segmentation | 用数据集训练产出的分割模型推理 |

**置信度分流规则**：
- top1_conf ≥ 用户设定阈值 → `status = ai_labeled`，写入 `ai_prediction` 字段
- top1_conf < 阈值 → `status = pending`，保持待人工标注

### 4.5 训练管理

| 子功能 | 说明 |
|---|---|
| 启动训练 | 选数据集 + 基础模型 + 模型名（版本号） + 超参 |
| 实时进度 | SSE 推送 epoch / loss / accuracy / learning rate |
| 暂停 / 恢复 | Redis 标志位 + Celery revoke，worker 在 epoch 边界优雅退出 |
| 取消 | Celery revoke + SIGTERM，硬停止 |
| 训练历史曲线 | 每个 epoch 持久化，前端 ECharts 展示 |
| 错误详情 | DB + Redis 双源错误捕获 |
| 任务编辑 | 未运行任务可改超参 / 模型名 |
| 任务删除 | 仅终态可删，自动清 Redis 残留 |
| 日志持久化 | 训练日志写入 DB，可还原历史 |
| 复用旧配置重启 | 模式 restart（新 job）/ resume（复用 job） |
| 列表分页 + 多维过滤 | 按 dataset / state / task_type / 关键词搜索 |

### 4.6 模型管理

- 模型版本列表（按数据集 / 任务类型 / 激活状态过滤）
- 模型详情（训练指标、关联训练任务、关联数据集）
- 激活 / 取消激活（幂等，多激活并存）
- 批量激活 / 批量删除
- 删除时同步清理物理权重文件

### 4.7 数据导出

| 格式 | 任务类型 | 描述 |
|---|---|---|
| COCO | detection / segmentation | 标准 COCO JSON，可直接用于 mmdetection / detectron2 |
| YOLO | detection | YOLO txt 格式 + data.yaml，可直接用于 ultralytics 训练 |
| CSV | classification | 简单两列（filename, label），可用于任何框架 |

### 4.8 团队协作

- 团队创建 / 编辑 / 删除（owner 权限）
- 团队成员邀请 / 移除 / 角色调整（owner / admin / member / viewer）
- 团队数据集共享（关联 dataset 可见性）
- 跨用户邀请（按 user_id 邀请，重复邀请检测）

### 4.9 统计与可视化

| 维度 | 指标 |
|---|---|
| 全局概览 | 用户数、数据集数、图片总数、已标/未标/AI标 |
| 数据集 | 各类别图片数 / 已标 / 未标 / 标注效率趋势 |

## 五、用户角色与权限

| 角色 | 数据集 | 标注 | 训练 | 模型 | 用户管理 | 审计 |
|------|------|------|------|------|---------|------|

启动命令：`docker compose up -d`

### 7.3 本地开发

- 后端：`uv sync` 安装依赖 / `python start_api.py` 启动
- Worker：`python start_workers.py` 启动双队列 worker
- 前端：`npm install` / `npm run dev`

### 7.4 数据存储路径

所有磁盘路径（`UPLOAD_DIR` / `MODEL_DIR` / `PRETRAINED_CACHE_DIR` / `ULTRALYTICS_HOME` 等）强制以**项目根**为基准，避开 cwd 依赖问题。

预训练权重缓存统一收纳到 `MODEL_DIR/cache/` 下，HF / torchvision / ultralytics 三套缓存共用。

## 八、当前实现价值与已知约束

### 8.1 真实可用的能力

- ✅ **多任务协同标注**：分类 / 检测 / 分割三套任务统一平台入口
- ✅ **AI 预标注 + 人工修正**：timm 700+ 预训练模型 + YOLOv8 + DeepLabV3+
- ✅ **置信度分流**：用户自定义阈值自动决定是否人工复核
- ✅ **增量训练闭环**：人工修正数据自动反哺训练
- ✅ **团队协作**：团队 / 成员 / 角色 / 数据集共享
- ✅ **完整审计**：每条标注写日志，可量化"AI 节省时间"
- ✅ **多格式导出**：COCO / YOLO / CSV
- ✅ **端到端实时 SSE**：训练进度、训练曲线、标注进度
- ✅ **管理员能力**：用户管理、角色管理、审计日志、系统监控
- ✅ **稳定的多 worker 队列**：train (低并发) / annotate (高并发)
- ✅ **完整测试覆盖**：43 个 pytest 测试 + E2E 套件

### 8.2 已知约束与待完善项

| 类别 | 项 | 说明 |
|---|---|---|
| 性能 | 大规模数据集列表分页 | 超过 10 万张图时建议增加游标分页 |
| 功能 | 不合格图片二次确认 | 当前缺少管理员批量复核界面 |
| 功能 | 模型部署为在线服务 | 当前仅训练，未提供独立推理服务 |
| 功能 | 多标签分类 | 当前仅单标签分类 |
| 协作 | 实时多人光标同步 | 当前采用轮询/SSE，未实现 CRDT/WebSocket |
| 测试 | 前端 E2E 自动化 | 当前主要靠后端 E2E，前端缺 Playwright 套件 |
| 部署 | K8s 编排 | 当前为 Docker Compose，生产 K8s 需自行迁移 |
| 监控 | Prometheus 指标 | 当前仅基础日志，缺 metrics 导出 |

### 8.3 风险点

| 风险 | 触发条件 | 缓解措施 |
|---|---|---|
| Celery worker OOM | 单次任务图片数 > 5k | 文档建议分批上传；后端有 batch 限制 |
| 训练任务长时占用 GPU | 用户并发开多个训练任务 | train 队列 concurrency=1 自动串行 |
| 数据库连接耗尽 | 高并发 + 长连接 | pool_size=10 + max_overflow=20 + pool_recycle=3600s |
| HF 下载失败 | 网络受限 | 默认配置 hf-mirror.com 国内镜像 |
| Windows symlink 报错 | WinError 14007 | 强制 `HF_HUB_DISABLE_SYMLINKS=1` |

## 十、结语

本平台以"AI 预标注 + 人工修正 + 增量训练"为协同范式，统一了图像分类、目标检测、语义分割三类任务，提供了从数据接入到模型产出的端到端能力。平台既可作为内部标注团队的生产工具，也可作为下游 AI 应用的数据供给平台。
