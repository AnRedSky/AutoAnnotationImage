## 一、设计目标

### 1.1 业务痛点

在没有正式的人工修正机制前，AI 预标注流程存在以下问题：

| 问题 | 影响 |
|---|---|
| AI 误判后**无 diff 提示** | 标注员需逐个对比 AI top5 与自身判断，效率低 |
| 修正后**无原因记录** | 训练师无法回溯"为什么这张图被改"，无法针对性提升模型 |
| 无法**回滚到 AI 预测** | 误操作后只能整图清除标注重做，破坏已积累的人工标注 |
| 数据集级**修正率无统计** | 管理者无法评估 AI 模型的真实可用度，无法决定是否触发下一轮训练 |

### 1.2 设计目标

1. **可视化**: 在标注工作台提供"AI vs 当前"差异徽章，让标注员一眼判断是否需要修正
2. **可追溯**: 每次修正都强制/选填记录原因 (comment) + 写完整 diff 到 `AnnotationLog.payload`
3. **可逆**: 误操作时可一键回滚到 AI 预测，**保留 ai_prediction 快照**
4. **可统计**: 数据集级修正统计 (修正率、热门修正方向、修正原因分布)，供训练师/管理者决策

### 1.3 范围与边界

- **本版本仅覆盖分类任务** (image.task_type === 'classification') 的人工修正
- 检测 / 分割任务的"确认/修正"语义不同 (前者修正 bbox 列表，后者修正 mask)，已在 v2.5.7 各自业务内处理
- **不破坏**既有 `/save` 接口行为 (comment 为选填，老调用方零迁移)

## 二、数据结构与存储

### 2.1 Image 表 (扩展语义，未改 schema)

```
Image
├── final_label_id       当前人工标注的类别 (status=trained 时为训练快照)
├── annotated_by         最后一次标注的 user_id
├── annotated_at         最后一次标注的时间
├── ai_prediction (JSON)  AI 预测快照, 含 top1 / top1_conf / top5
│   ├── top1             AI 最高置信度的类别名
│   ├── top1_conf        top1 置信度 (0~1)
│   └── top5             [{label, confidence}] top5 候选
└── status (枚举)
    ├── pending           初始, 未标注
    ├── ai_labeled        AI 预标注完成, 未被人工确认
    ├── human_confirmed   人工确认 (AI 正确)
    ├── human_corrected   人工修正 (AI 错误)
    └── trained           已参与训练
```

**关键点**: `ai_prediction` 字段一旦写入**不会被任何操作清空**（除了 `/clear` 端点显式清），即使 `revert_to_ai` 也会保留。这是 v3.4.0 修复方案能成立的核心前提。

### 2.2 AnnotationLog 表 (扩展枚举)

```
AnnotationLog (v3.4.0 扩展)
├── action (枚举, v3.4.0 新增 revert_to_ai)
│   ├── ... 既有枚举 (ai_predict/confirm/correct/reject/...)
│   └── revert_to_ai     v3.4.0 新增: 用户撤销人工修正
├── from_label_id         修正前类别
├── to_label_id           修正后类别 (revert_to_ai 时为 null)
├── time_spent_ms         耗时
└── payload (JSON, v3.4.0 扩展)
    ├── diff             仅 correct 写入
    │   ├── from.label_id        修正前类别 id
    │   ├── from.ai_top1         修正时 AI top1
    │   ├── from.ai_top1_conf    修正时 AI top1 置信度
    │   └── to.label_id          修正后类别 id
    ├── comment           用户填的修正原因 (≤500 字)
    ├── from_log_id       revert_to_ai 专用: 指向被回滚的 log
    ├── reason            revert_to_ai 专用: 'user_revert'
    └── ai_top1           revert_to_ai 专用: 回滚时 AI top1
```

### 2.3 状态机 (status 转换)

```
                ┌────────────┐
                │  pending   │ ← /clear 清空所有标注后
                └─────┬──────┘
                      │ auto_label
                      ▼
              ┌──────────────┐
        ┌────►│  ai_labeled  │◄──┐
        │     └──────┬───────┘   │
        │            │ /save     │
        │   /save    │ (confirm) │ revert_to_ai
        │ (correct)  ▼           │
        │     ┌──────────────┐   │
        │     │ human_       │───┘
        │     │ confirmed    │
        │     └──────┬───────┘
        │            │ /save (correct) 多次修改
        │            ▼
        │     ┌──────────────┐
        │     │ human_       │
        │     │ corrected    │───► (回到 ai_labeled 只能通过 revert_to_ai)
        │     └──────┬───────┘
        │            │ 训练完成
        │            ▼
        │     ┌──────────────┐
        │     │   trained    │ (禁止 revert_to_ai, 避免破坏训练快照)
        │     └──────────────┘
        │
        └── (任何状态, /clear 都能回到 pending)
```

## 三、API 端点 (v3.4.0 新增/扩展)

| 端点 | 方法 | 作用 | 权限 |
|---|---|---|---|
| `/api/annotations/save` | POST | **扩展** — 新增可选 `comment` 字段 | 写 |
| `/api/annotations/correction-history/{image_id}` | GET | 单图完整修正历史 (含 diff / comment) | 读 |
| `/api/annotations/revert-to-ai/{image_id}` | POST | 恢复 AI 预测 (撤销人工修正) | 写 |
| `/api/annotations/correction-stats/{dataset_id}` | GET | 数据集级修正统计 | 读 |

### 3.1 `/save` 扩展

**请求** (comment 选填):

```json
{
  "image_id": 123,
  "label_id": 5,
  "time_spent_ms": 3200,
  "is_confirm": false,
  "comment": "AI 误判: 实际是 [猫] 不是 [狗]"
}
```

**行为**:

- `is_confirm=true` 且 `from_label_id` 为空 → `action="confirm"`, payload 不含 diff
- `is_confirm=true` 但 `from_label_id` 不为空 (修改标注) → `action="correct"`, payload 含 diff
- `is_confirm=false` → `action="correct"`, payload 含 diff
- `comment` 写 `AnnotationLog.payload.comment` (≤500 字)
- `diff.from.ai_top1` 取自 `Image.ai_prediction.top1` (修正时的 AI top1)
- `diff.from.label_id` 取自 `Image.final_label_id` (修正前类别)
- `diff.to.label_id` 为新的 `label_id`

### 3.2 `/correction-history/{image_id}`

**响应**:

```json
{
  "image_id": 123,
  "current_status": "human_corrected",
  "current_label_id": 5,
  "current_label_name": "猫",
  "ai_prediction": { "top1": "狗", "top1_conf": 0.82, "top5": [...] },
  "items": [
    {
      "id": 1001,
      "action": "ai_predict",
      "username": "system",
      "from_label_id": null, "from_label_name": null,
      "to_label_id": 3, "to_label_name": "狗",
      "time_spent_ms": 0,
      "created_at": "2026-08-04T10:00:00",
      "payload": null
    },
    {
      "id": 1002,
      "action": "correct",
      "username": "alice",
      "from_label_id": 3, "from_label_name": "狗",
      "to_label_id": 5, "to_label_name": "猫",
      "time_spent_ms": 3200,
      "created_at": "2026-08-04T10:05:00",
      "payload": {
        "correction_type": "modify_label",
        "diff": { "from": {...}, "to": {...} },
        "comment": "AI 误判: 实际是 [猫] 不是 [狗]"
      }
    }
  ]
}
```

**只返回** `action ∈ {confirm, correct, revert_to_ai}` 的日志，按 id 升序。

### 3.3 `/revert-to-ai/{image_id}`

**业务规则** (前端按钮的可用性 + 后端强约束):

| 当前 status | 是否允许 revert | 原因 |
|---|---|---|
| `pending` | ❌ 无意义 | 没有 AI 预测可恢复 |
| `ai_labeled` | ❌ 无意义 | 已经是 AI 状态 |
| `human_confirmed` | ✅ 允许 | 撤销人工确认 |
| `human_corrected` | ✅ 允许 | 撤销人工修正 |
| `trained` | ❌ 禁止 | 避免破坏训练快照 (前端禁用按钮 + 后端 409 强约束) |

**约束**: 必须存在 `ai_prediction` 字段（否则 409 提示"请重新运行 AI 预标注"）

**行为**:
1. 清空 `Image.final_label_id` / `annotated_by` / `annotated_at`
2. `Image.status` 回 `ai_labeled`
3. 同步扣减原 category 的 `sample_count`（避免统计虚高）
4. 写一条 `action=revert_to_ai` 审计，`payload.from_log_id` 指向最近一次 correct/confirm 日志（用于追溯）

**响应**:

```json
{
  "success": true,
  "image_id": 123,
  "new_status": "ai_labeled",
  "ai_top1": "狗",
  "revert_log_id": 1003
}
```

### 3.4 `/correction-stats/{dataset_id}`

**响应**:

```json
{
  "total_ai_labeled": 500,
  "total_confirmed": 320,
  "total_corrected": 180,
  "total_revert": 12,
  "correction_rate": 0.36,           // 修正率: 180/500 = 36%
  "avg_corrections_per_image": 1.8,  // 每张被修过的图平均被修 1.8 次
  "top_flip_directions": [
    { "from_to": "狗 → 猫", "count": 35 },
    { "from_to": "汽车 → 卡车", "count": 28 }
  ],
  "top_correction_comments": [
    { "comment": "AI 误判", "count": 60 },
    { "comment": "类别模糊", "count": 24 }
  ]
}
```

**用途**:
- 修正率 > 50% → 触发"再标注一批"或"重新训练"决策
- 热门修正方向 → 训练师针对性提升特定类别的识别能力
- 修正原因分布 → 找出系统性 AI 缺陷（如"遮挡"原因占比高 → 数据集缺遮挡样本）

## 四、修正操作规范 (SOP)

### 4.1 标注员操作规范

#### 4.1.1 何时「确认」(is_confirm=true)

- AI top1 与自身判断**完全一致** → 直接点「确认此标签」
- 行为: `action=confirm`，**不写** `payload.comment`（不必要）

#### 4.1.2 何时「强制采用」(is_confirm=false, 但 label 仍是 AI top1)

- 场景: 选错标签才发现要改，**最终结果还是 AI top1**
- 系统行为: 仍记为 `action=correct`（因为 from_label_id != null），payload.comment 选填

#### 4.1.3 何时「修正」(is_confirm=false, label 是新类别)

- AI top1 错误 → 从下拉选正确类别
- **强制填写** correction_comment（建议从预设下拉选，至少 4 种预设原因之一）:
  - **AI 误判**: AI 模型判断错误
  - **类别模糊**: 多类别都合理，选了相对更合适的一个
  - **遮挡**: 目标被部分遮挡，AI 没识别出来
  - **多目标**: 图中有多个目标，选了主要目标
  - **数据增强需要**: 特定训练策略需要（如平衡类别）
  - **其他**: 自由输入

#### 4.1.4 何时「恢复 AI 预测」

- 发现自己误操作改错了
- 多人协作时同事标注错了，自己想从 AI top1 重新来过
- 业务规则: status ∈ {human_confirmed, human_corrected} 才允许
- status=trained 时**禁止**（按钮禁用 + tooltip 提示）

### 4.2 审计规范

| 场景 | 记录要求 |
|---|---|
| 首次确认 AI 标注 | `action=confirm`, payload 为空 |
| 首次人工标注 (无 AI 预测) | `action=correct`, payload.comment 强烈建议填写（"无 AI 预测"原因） |
| 修正 AI 标注 | `action=correct`, payload.diff + payload.comment |
| 恢复 AI 预测 | `action=revert_to_ai`, payload.from_log_id 指向被回滚的日志 |

### 4.3 数据一致性约束

- **保存原子性**: `Image` 更新 + `AnnotationLog` 写入 + `Category.sample_count` 更新在**同一事务**内，任一失败全部回滚
- **可恢复**: 任何人工标注动作都可被 `revert_to_ai` 撤销（除了 trained 状态）
- **可追溯**: 每条 `AnnotationLog` 永久保留，不支持删除（即使图片被 /clear，也保留旧 log 作为审计）

## 五、质量控制标准

### 5.1 标注员质量指标

基于 `correction_stats` 端点的可量化指标:

| 指标 | 公式 | 期望范围 |
|---|---|---|
| **AI 接受率** | total_confirmed / total_ai_labeled | > 60% (项目微调模型) |
| **修正率** | total_corrected / total_ai_labeled | < 40% |
| **平均修正次数** | total_corrections / total_corrected | < 2.0 (避免反复改) |
| **回滚率** | total_revert / (total_confirmed + total_corrected) | < 5% (操作熟练度) |

### 5.2 AI 模型质量指标

- **修正率 > 50%** → AI 模型在该数据集上效果差，建议:
  1. 增加训练数据 (优先补充"热门修正方向"中频繁被误判的类别)
  2. 调整训练超参 (epochs / learning_rate)
  3. 切换到更强的 base model (efficientnet_b3 / resnet50)

- **特定方向修正率高** (如"狗→猫" 35 次) → 重点优化:
  1. 收集更多易混淆类别的训练样本
  2. 引入难例挖掘 (hard example mining)
  3. 在标注指南中明确"狗 vs 猫"区分标准

### 5.3 流程门槛

| 训练触发条件 | 阈值 |
|---|---|
| 已确认 (human_confirmed) | ≥ 50 张 |
| 已修正 (human_corrected) | ≥ 20 张 (确保多样性) |
| 不合格率 | < 10% (避免训练集含太多低质量样本) |
| 类别平衡度 | 任意类别 ≥ 5 张 (避免单类别主导) |

### 5.4 修正原因 → 训练策略映射

| 高频修正原因 | 训练策略 |
|---|---|
| AI 误判 | 收集误判样本做 fine-tune, 增加 hard example 权重 |
| 类别模糊 | 在标注指南中提供更明确的视觉标准, 加难例 |
| 遮挡 | 数据增强添加 CutOut / RandomErasing, 模拟遮挡 |
| 多目标 | 在数据集中标注多个目标, 训练 multi-label 能力 |
| 数据增强需要 | 主动 SMOTE 过采样少数类, 或用 weighted loss |

## 八、未来扩展

### 8.1 短期 (v3.5.x)

- **检测 / 分割的 diff 增强**: 当前仅分类任务支持, 检测/分割的"bbox 修改 diff" + "mask 修改 diff" 待扩展
- **AI 二次建议**: 修正后, 后台异步调用 AI 模型"如果按你的修正反向训练, top1 会变什么" — 帮助用户判断修正合理性
- **批量子集评估**: 在 `/correction-stats` 基础上, 支持按时间窗口 / 标注员 / 修正原因切片

### 8.2 中期 (v4.x)

- **协同标注冲突检测**: 多人同时标注同一图时, 实时提示他人正在修改, 避免重复劳动
- **标注质量评分**: 基于修正次数 / 修正原因 / 与 AI top1 一致度, 给每个标注员算"质量分"
- **智能推荐修正原因**: 根据 diff 类型 (例如"类别模糊"判断: top1 与 top2 置信度差 < 0.1) 自动推荐预设原因

### 8.3 长期

- **Active Learning 闭环**: 高频被修正的样本自动进入下一轮训练集, 减少重复劳动
- **跨数据集修正模式聚类**: 找出"所有数据集共同的难例模式", 提升基础模型能力
