# 系统功能设计文档

---

## 一、系统概述

### 1.1 系统名称

基于深度学习的图像自动标注系统

### 1.2 系统定位

面向中小型图像分类场景的协同式自动标注工具。系统使用 timm 预训练的深度学习模型对图像批量预标注，标注员在预标注结果上快速确认或修正，并支持基于已标注数据持续训练自有模型。

### 1.3 核心价值

| 价值点 | 描述 |
|---|---|
| 降本 | AI 预标注后人工只需确认/修正，单张图片平均节省 3-5 秒 |
| 提效 | 一次预标注可批量处理数千张图片 |
| 可持续 | 标注数据可即时训练自有模型，越用越准 |
| 可审计 | 所有标注行为写入审计日志（confirm / correct + 耗时） |
| 可导出 | 支持 COCO / YOLO / CSV 三种主流格式导出 |

### 1.4 目标用户

| 角色 | 典型场景 |
|---|---|
| 标注员（annotator） | 日常标注工作，需要高效准确的工具 |
| 管理员（admin） | 数据集与用户管理，模型训练与激活 |
| 观察者（viewer） | 只读访问，用于审查与汇报 |

### 1.5 范围边界

**当前版本实现**：

- 图像分类（单标签）场景的预标注 + 人工修正
- 批量上传、AI 预标注、Top-5 候选展示与一键确认
- 基于 timm 预训练模型的迁移学习微调训练
- 模型版本管理与对比
- 标注数据导出（COCO / YOLO / CSV）
- 基础统计与可视化

**当前版本不实现**：

- 多标签分类 / 目标检测 / 图像分割
- 实时多人协作（WebSocket）
- 模型部署为在线推理服务（仅训练，不上线）
- 复杂权限管理（仅 admin / annotator / viewer 三级）
- 移动端 / 离线标注

## 二、核心功能模块

### 模块 A：AI 自动标注

#### A.1 功能描述

使用 timm 预训练模型（如 ResNet50 / EfficientNet-B0 / ConvNeXt-Tiny）对待标注图片批量推理，输出每个图片的 Top-5 候选标签及置信度。

#### A.2 详细功能

| 子功能 | 描述 | API |
|---|---|---|
| A.2.1 同步预标注 | 选数据集 → 选模型 → 设阈值 → 立即返回结果 | `POST /api/auto-annotate/run` |
| A.2.2 异步预标注 | 任务提交到 Celery，返回 task_id，前端轮询进度 | `POST /api/auto-annotate/run` + `GET /api/auto-annotate/status/{task_id}` |
| A.2.3 可用模型查询 | 列出系统支持的预训练模型（名称 + 参数量 + 描述） | `GET /api/auto-annotate/models` |
| A.2.4 置信度阈值分流 | top1_conf ≥ 阈值 → `ai_labeled`；< 阈值 → 保持 `pending` | 后端逻辑 |
| A.2.5 单图自动标注（旧版） | 调用预训练模型对单数据集所有 pending 图片推理 | `POST /api/images/auto-label/{dataset_id}` |

#### A.3 数据流

```
[图片上传] → status=pending
   ↓
[选择模型 + 阈值] → POST /api/auto-annotate/run
   ↓
[Celery auto_annotate_task]
   ├─ 加载 timm 模型
   ├─ 批量推理（每 10 张更新一次进度）
   └─ 按阈值分流
        ├─ top1_conf ≥ threshold → status=ai_labeled, ai_prediction={top1, top1_conf, top5}
        └─ top1_conf < threshold → 保持 status=pending
   ↓
[前端 Annotate 页面] 拉取 ai_labeled + pending 图片
```

#### A.4 输出格式

每张图片的 `ai_prediction` 字段（JSON）：

```json
{
  "top1": "Egyptian cat",
  "top1_conf": 0.8234,
  "top5": [
    {"label": "Egyptian cat", "conf": 0.8234},
    {"label": "tabby",        "conf": 0.0921},
    {"label": "tiger cat",    "conf": 0.0456},
    {"label": "Persian cat",  "conf": 0.0234},
    {"label": "Siamese cat",  "conf": 0.0089}
  ]
}
```

### 模块 B：人工标注与协同

#### B.1 功能描述

在 AI 预标注基础上，标注员确认或修正 Top-5 候选，写入审计日志，并实时统计效率指标。

#### B.2 详细功能

| 子功能 | 描述 | API |
|---|---|---|
| B.2.1 拉取待标注图 | 从数据集的 `pending` 池取下一张 | `GET /api/images/list/{id}?status=pending` |
| B.2.2 确认 AI 标注 | 选 Top-1 候选 → 标 `human_confirmed` | `POST /api/annotations/save` |
| B.2.3 强制采用候选 | 选 Top-2~5 候选 → 标 `human_confirmed` | 同上 |
| B.2.4 修正 AI 标注 | 选其他类别（不在 Top-5）→ 标 `human_corrected` | 同上 |
| B.2.5 跳过 | 不标注直接拉下一张 | 前端逻辑 |
| B.2.6 计时 | 进入页面时记录 startTs，保存时写入耗时 | 前端 |
| B.2.7 实时统计 | 4 个统计卡（已标注 / AI 命中 / 节省时间 / 平均耗时） | `GET /api/annotations/stats/{id}` |

#### B.3 数据流

```
[拉取 next pending 图片] 
   ↓
[显示图片 + Top-5 候选 + 置信度]
   ↓
[标注员点击候选/选择其他类别] 
   ↓
[POST /api/annotations/save]
   ├─ 写 image.final_label_id
   ├─ 写 AnnotationLog (action=confirm/correct, time_spent_ms)
   ├─ 更新 image.status
   └─ 更新 category.sample_count
   ↓
[刷新统计 + 拉下一张]
```

#### B.4 状态机

```
pending  ───[AI 预标注 ≥ 阈值]──→  ai_labeled
   │                                   │
   │                                   ├──[确认]──→ human_confirmed
   │                                   └──[修正]──→ human_corrected
   │
   └──────[人工直接标注（无 AI）]──→  human_confirmed / human_corrected
```

#### B.5 审计日志

每条 `AnnotationLog` 记录：

- 标注员 ID
- 图片 ID
- 动作（confirm / correct）
- 起始 label_id / 目标 label_id
- 耗时（ms）
- 时间戳

### 模块 C：模型训练与版本管理

#### C.1 功能描述

基于已标注数据，使用 timm 预训练模型进行迁移学习微调，训练结果作为新模型版本保存。支持版本对比与激活切换。

#### C.2 详细功能

| 子功能 | 描述 | API |
|---|---|---|
| C.2.1 启动训练 | 表单提交（数据集 + 基础模型 + 超参）→ Celery 异步任务 | `POST /api/training/start` |
| C.2.2 进度查询 | 前端每 3 秒轮询 | `GET /api/training/progress/{task_id}` |
| C.2.3 训练历史曲线 | 从 Redis 拉取 epoch 级别 loss/acc  | `GET /api/training/history/{task_id}` |
| C.2.4 任务历史列表 | 显示所有训练任务（数据集/状态/进度/耗时） | `GET /api/training/jobs` |
| C.2.5 任务详情 | 单个任务的完整信息 | `GET /api/training/jobs/{id}` |
| C.2.6 模型版本列表 | 列出所有训练成功的模型 | `GET /api/models` |
| C.2.7 模型详情 | 训练曲线 + 混淆矩阵 | `GET /api/models/{id}/detail` |
| C.2.8 激活模型 | 切换当前激活版本（事务原子化） | `POST /api/models/{id}/activate` |
| C.2.9 双模型对比 | Δ 指标 + 混淆矩阵对比 | `GET /api/stats/models/compare/{a}/{b}` |

#### C.3 训练流程

```
[前端 Training 页面] 选择数据集 + 基础模型 + 超参
   ↓
[POST /api/training/start]
   ↓
[Celery train_model_task]
   ├─ 1. 创建 TrainingJob 记录 (state=PROGRESS, progress=0)
   ├─ 2. 加载数据集 + 8:2 划分 train/val (要求 ≥ 10 张已确认)
   ├─ 3. 加载 timm 预训练模型
   ├─ 4. AdamW + CosineAnnealing + Warmup 训练循环
   │    ├─ 每 100 batch 调用 self.update_state(PROGRESS, {progress, current_epoch, total_epochs, msg})
   │    └─ 每 epoch 回调 _update_training_history + epoch_callback
   │         ├─ 写 Redis: train:history:{task_id} (24h 过期)
   │         ├─ 写 self.update_state (携带 val_acc/train_loss/val_loss)
   │         └─ 早停判断 (no_improve_count >= patience 时 break)
   ├─ 5. 评估（混淆矩阵 + 4 指标：accuracy/precision/recall/f1）
   ├─ 6. 保存 .pth 文件到 models/{model_name}_best.pth
   ├─ 7. 创建 ModelVersion 记录 (is_active=False, 由 API 显式激活)
   └─ 8. 更新 TrainingJob (state=SUCCESS, model_version_id, duration)
   ↓
[异常路径] try/except 清理:
   ├─ 删除 ModelVersion 半成品 (同 model_name + is_active=False)
   ├─ 删除磁盘 {model_name}_best.pth
   └─ TrainingJob 置 FAILED + error 字段
   ↓
[前端轮询 progress + history] 实时显示进度条 + ECharts 4 曲线
   ↓
[完成后] 列表 + 激活 + 对比
   ├─ POST /api/models/{id}/activate (with_for_update 行锁 + 事务)
   └─ GET /api/stats/models/compare/{a}/{b} (Δ 4 指标)
```

#### C.4 模型版本管理

| 操作 | 描述 |
|---|---|
| 列表 | 按 created_at 倒序展示所有版本 |
| 详情 | 训练曲线 JSON + 混淆矩阵 JSON + 4 指标 |
| 激活 | 一键切换（同一时刻仅 1 个 is_active=True） |
| 对比 | 选 2 个版本 → 显示 Δ 指标 |

## 三、辅助功能模块

### 模块 D：数据集与图像管理

| 子功能 | 描述 | API |
|---|---|---|
| D.1 数据集 CRUD | 创建/查询/删除数据集 | `/api/datasets/*` |
| D.2 类别管理 | 创建数据集时批量创建类别，或后续追加 | `/api/datasets/{id}/categories` |
| D.3 批量上传 | 多文件上传 + SHA-256 去重 | `POST /api/images/upload/{id}` |
| D.4 图像查询 | 分页 + 状态过滤 | `GET /api/images/list/{id}` |
| D.5 图片下载 | 提供图片访问 URL | `GET /api/files/{image_id}` |

### 模块 E：数据导出

| 格式 | 用途 | API |
|---|---|---|
| COCO | 业界标准，可直接接入 mmdetection / detectron2 | `GET /api/export/coco/{id}` |
| YOLO | 业界标准，可直接接入 ultralytics / darknet | `GET /api/export/yolo/{id}` |
| CSV | Excel 友好的明细表，便于人工审查 | `GET /api/export/csv/{id}` |

### 模块 F：统计分析

| 端点 | 用途 |
|---|---|
| `GET /api/stats/overview` | 系统总览（数据集数、图片总数、已标注、模型版本数） |
| `GET /api/stats/dataset/{id}` | 单数据集的详细统计（标注状态 + 类别分布 + AI 节省时间） |
| `GET /api/stats/confidence/{id}` | AI 置信度分布直方图（用于 Dashboard 展示） |
| `GET /api/stats/timeline/{id}` | 近 N 天每日标注量（用于 Dashboard 展示） |
| `GET /api/stats/annotator-efficiency` | 标注员效率排行（Top 10） |
| `GET /api/stats/models/compare/{a}/{b}` | 双模型对比（4 指标 Δ + 混淆矩阵） |

### 模块 G：用户认证

| 子功能 | 描述 | API |
|---|---|---|
| G.1 注册 | 用户名 + 密码 + 邮箱（可选） | `POST /api/auth/register` |
| G.2 登录 | OAuth2 form-data 登录，返回 JWT | `POST /api/auth/login` |
| G.3 当前用户 | 拉取登录信息（前端 Layout 展示） | `GET /api/auth/me` |
| G.4 登出 | 服务端确认 + 前端清 token | `POST /api/auth/logout` |

## 五、非功能需求

### 5.1 性能

| 维度 | 指标 |
|---|---|
| 图像上传 | 单张 ≤ 20MB，去重 < 1 秒 |
| 批量预标注 | 1000 张 CPU 推理 < 5 分钟 |
| 训练任务 | 5 类 × 200 张 × 5 epoch CPU < 30 分钟 |
| 接口响应 | 常规 CRUD < 200ms，统计查询 < 1s |

### 5.2 安全

- JWT Bearer Token 鉴权
- bcrypt 密码哈希
- 所有写操作要求登录
- 文件名/路径用 storage_key 防注入

### 5.3 可用性

- 前后端分离（独立部署/升级）
- API 自动文档（FastAPI Swagger `/docs`）
- 前端路由懒加载（首屏 < 50KB）
- 错误提示用 Element Plus 统一弹窗

### 5.4 可维护性

- 7 个 ORM 模型化清晰
- 5 个 Pydantic Schema 校验严格
- Celery 异步任务解耦重操作
- uv + pyproject.toml 锁定依赖

### 5.5 可移植性

- Docker Compose 一键部署
- 前端 Vite 静态构建
- 后端 SQLAlchemy 兼容 MySQL / SQLite
