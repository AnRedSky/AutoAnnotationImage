# 团队管理 API 文档 (v3.3.1)

> 团队管理模块的完整 API 参考
> 版本: v3.3.1 (基于 v3.3.0 团队基础模块)
> 适用范围: 团队 CRUD / 成员管理 / 权限控制 / 数据集共享 / 审计日志

---

## 一、通用约定

### 1.1 认证
所有端点需要在 `Authorization` header 中携带 Bearer token:
```
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```
获取方式: `POST /api/auth/login` (OAuth2 form-encoded)

### 1.2 数据隔离
- 用户仅可见自己创建或已加入的团队
- 非团队成员 (包括系统管理员) 不可访问团队信息
- 团队间数据完全独立

### 1.3 角色权限

| 角色 | 标识 | 权限范围 |
|---|---|---|
| 创建者 (owner) | 由 `team.owner_id` 标识 | 全部权限 + 转让所有权 |
| 可管理 (manager) | `role=manager` | 成员管理 + 编辑团队 + 数据集共享 |
| 可编辑 (editor) | `role=editor` | 数据集标注 |
| 仅阅读 (viewer) | `role=viewer` | 只读访问 |

### 1.4 错误码

| 状态码 | 含义 |
|---|---|
| 200 | 成功 |
| 400 | 请求参数错误 (e.g. 配额降级) |
| 401 | 未认证 |
| 403 | 无权限 (数据隔离) |
| 404 | 资源不存在 |
| 409 | 资源冲突 (e.g. 成员已存在) |
| 410 | 已归档 (软删除), 不可操作 |
| 422 | 参数校验失败 |
| 500 | 服务器错误 |

## 二、团队 CRUD

### 2.1 列出我的团队

```
GET /api/teams
```

查询参数:
| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| page | int | 否 | 1 | 页码 (≥ 1) |
| page_size | int | 否 | 20 | 每页条数 (1-100) |
| search | string | 否 | - | 模糊搜索 (name/description/slug) |
| sort | string | 否 | id_desc | 见下表 |
| include_archived | bool | 否 | false | 仅 admin 可用 |

sort 取值:
- `id_asc` / `id_desc`: 按 ID
- `name_asc` / `name_desc`: 按名称
- `created_asc` / `created_desc`: 按创建时间
- `member_count_desc`: 按成员数

响应:
```json
{
  "items": [
    {
      "id": 1,
      "name": "视觉算法组",
      "slug": "vision-algo",
      "description": "负责视觉算法研发",
      "owner_id": 2,
      "max_members": 20,
      "my_role": "manager",
      "member_count": 5,
      "created_at": "2026-08-01T08:00:00",
      "archived_at": null
    }
  ],
  "page": 1,
  "page_size": 20,
  "total": 1,
  "total_pages": 1,
  "sort": "id_desc",
  "search": ""
}
```

### 2.2 创建团队

```
POST /api/teams
```

请求体:
```json
{
  "name": "视觉算法组",        // 必填
  "slug": "vision-algo",       // 可选, 为空时自动从 name 生成
  "description": "负责视觉算法研发",  // 可选
  "max_members": 20             // 可选, 默认 20, 范围 [2, 100]
}
```

响应:
```json
{
  "id": 1,
  "name": "视觉算法组",
  "slug": "vision-algo"
}
```

**业务规则**:
- 任何已登录用户可创建
- 创建者自动加入为 manager
- slug 冲突时自动追加数字后缀 (`my-team` → `my-team-2`)

### 2.3 团队详情

```
GET /api/teams/{team_id}
```

响应: 同列表项, 包含 `archived_at`
- v3.3.1 L3: Redis 缓存 5 分钟, 写操作后失效
- 已归档团队对非 admin 返回 410

### 2.4 编辑团队

```
PATCH /api/teams/{team_id}
```

请求体 (所有字段可选, 至少一个):
```json
{
  "name": "视觉算法组 (新)",
  "description": "更新描述",
  "max_members": 30
}
```

**业务规则**:
- 仅 manager / owner 可调用
- `max_members` < 当前成员数 → 400
- 写入 `team_updated` 审计

### 2.5 删除团队 (软删除)

```
DELETE /api/teams/{team_id}
```

**业务规则 (v3.3.1 L3)**:
- 仅创建者可调用
- 设置 `archived_at = utcnow()`, 记录审计
- 数据集 `team_id` 字段被清空 (避免悬挂引用)
- 团队成员保留, 但无法访问
- admin 可通过 `POST /api/teams/{id}/restore` 恢复

### 2.6 恢复已归档团队

```
POST /api/teams/{team_id}/restore
```

权限: **仅 admin**
- 团队必须存在 (无论归档与否)
- 必须处于 archived 状态 (否则 400)
- 恢复后 `archived_at` 清空

## 三、成员管理

### 3.1 成员列表

```
GET /api/teams/{team_id}/members
```

响应:
```json
{
  "items": [
    {
      "user_id": 2,
      "username": "alice",
      "email": "alice@example.com",
      "role": "manager",
      "joined_at": "2026-08-01T08:00:00"
    }
  ]
}
```

### 3.2 邀请成员

```
POST /api/teams/{team_id}/members
```

请求体:
```json
{
  "user_id": 5,
  "role": "editor"   // manager | editor | viewer
}
```

**业务规则**:
- 仅 manager / owner 可调用
- 用户已在团队中 → 409
- 团队已满 → 400
- 写入 `team_member_invited` 审计 (含 invited_by)

### 3.3 修改成员角色

```
PUT /api/teams/{team_id}/members/{user_id}
```

请求体:
```json
{
  "role": "manager"
}
```

**业务规则**:
- 仅 manager / owner 可调用
- 创建者 (`owner_id`) 必须保持 manager → 否则 400
- **最后一名 manager 保护**: 降级最后一名 manager → 400
- 写入 `team_member_role_changed` 审计

### 3.4 移除成员

```
DELETE /api/teams/{team_id}/members/{user_id}
```

**业务规则**:
- 仅 manager / owner 可调用
- 不能移除创建者 (`owner_id`) → 400
- **最后一名 manager 保护**: 移除最后一名 manager → 400
- 写入 `team_member_removed` 审计

### 3.5 主动退队

```
DELETE /api/teams/{team_id}/members/me
```

**业务规则 (v3.3.1 L1)**:
- 创建者必须先转让所有权才能退队 → 400
- 写入 `team_left` 审计

## 四、所有权与共享

### 4.1 转让所有权

```
POST /api/teams/{team_id}/transfer
```

请求体:
```json
{
  "new_owner_id": 5,
  "confirm": true   // 二次确认, false → 400
}
```

**业务规则**:
- 仅当前 owner 可调用
- 接收方必须是本团队现有 member
- 接收方角色不能是 viewer → 400
- 接收方角色强制提升为 manager
- 原 owner 若仍在 member 表, 角色保持 manager (避免权限真空)
- 写入 `team_ownership_transferred` 审计 (含 old_owner / new_owner)

### 4.2 共享数据集给团队

```
POST /api/datasets/{dataset_id}/share
```

查询参数:
| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| team_id | int | 是 | 目标团队 ID |

**业务规则**:
- 仅数据集 owner 可调用
- 当前用户必须也是目标团队成员
- 写入 `dataset_shared_to_team` 审计

### 4.3 取消数据集共享

```
DELETE /api/datasets/{dataset_id}/share
```

**业务规则**:
- 仅数据集 owner 可调用
- 写入 `dataset_unshared_from_team` 审计

## 五、团队数据视图

### 5.1 团队级数据集列表

```
GET /api/teams/{team_id}/datasets
```

响应:
```json
{
  "items": [
    {
      "id": 1,
      "name": "城市道路数据集",
      "description": "...",
      "task_type": "detection",
      "image_count": 1000,
      "annotated_count": 800,
      "category_count": 10,
      "status": "active",
      "owner_id": 2,
      "owner_name": "alice",
      "my_access": "manager"
    }
  ]
}
```

权限: 任意团队成员可见

### 5.2 团队统计

```
GET /api/stats/team/{team_id}?days=7
```

查询参数:
| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| days | int | 否 | 7 | 趋势区间 (7/14/30) |

响应字段:
- `team_id`, `team_name`
- `dataset_count`: 数据集数
- `image_status`: 各状态图片数 {pending, ai_labeled, human_labeled, ...}
- `top_contributors`: Top 5 贡献者 [{username, count}]
- `timeline`: 趋势 [{date, count}]
- `ai_saved`: AI 节省时间统计
- `member_count`: 成员数

### 5.3 团队活动 Feed (L4)

```
GET /api/teams/{team_id}/activities?limit=50&event_type=team_updated
```

查询参数:
| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| limit | int | 否 | 50 | 返回条数 (1-200) |
| event_type | string | 否 | - | 事件类型过滤 |

响应:
```json
{
  "items": [
    {
      "id": 123,
      "user_id": 2,
      "username": "alice",
      "event_type": "team_updated",
      "event_label": "更新团队",
      "resource_type": "team",
      "resource_id": 1,
      "detail": {"changes": {"name": {"old": "A", "new": "B"}}},
      "created_at": "2026-08-05T10:00:00"
    }
  ],
  "total": 1,
  "limit": 50,
  "event_type": "team_updated"
}
```

权限:
- 团队成员可见活跃团队的活动
- admin 可见已归档团队的活动
- 已归档团队对非 admin 返回 410

事件类型白名单:
- `team_created`, `team_updated`, `team_deleted`, `team_restored`
- `team_ownership_transferred`, `team_left`
- `team_member_invited`, `team_member_role_changed`, `team_member_removed`
- `dataset_shared_to_team`, `dataset_unshared_from_team`

## 六、审计日志 (L4)

### 6.1 系统级审计查询

```
GET /api/audit-logs
```

权限: **仅 admin**

查询参数:
| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| page | int | 否 | 1 | 页码 (≥ 1) |
| page_size | int | 否 | 50 | 每页 (1-200) |
| event_type | string | 否 | - | 事件类型过滤 |
| team_id | int | 否 | - | 按团队过滤 |
| user_id | int | 否 | - | 按用户过滤 |
| resource_type | string | 否 | - | 按资源类型 |
| start | ISO8601 | 否 | - | 起始时间 |
| end | ISO8601 | 否 | - | 截止时间 |

响应:
```json
{
  "items": [
    {
      "id": 1,
      "user_id": 2,
      "username": "alice",
      "event_type": "team_updated",
      "resource_type": "team",
      "resource_id": 1,
      "team_id": 1,
      "detail": {"changes": {}},
      "ip_address": "127.0.0.1",
      "created_at": "2026-08-05T10:00:00"
    }
  ],
  "page": 1,
  "page_size": 50,
  "total": 1,
  "total_pages": 1,
  "filters": {
    "event_type": null,
    "team_id": null,
    "user_id": null,
    "resource_type": null,
    "start": null,
    "end": null
  }
}
```

排序: `created_at DESC` (最新在前)
