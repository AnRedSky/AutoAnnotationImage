```python
# app/core/celery_utils.py

def check_celery_available() -> None:
    """Redis ping 不可达 -> HTTPException(503)"""
    from app.core.redis_client import redis_client
    try:
        redis_client.ping()
    except Exception as e:
        raise HTTPException(503, f"Redis 不可用, 任务无法入队: {e}")

def run_async_in_worker(coro):
    """在 fresh event loop 中跑 coroutine, dispose engine 防止连接池绑到已关闭 loop"""
    from app.database import engine
    loop = asyncio.new_event_loop()
    try:
        asyncio.set_event_loop(loop)
        try: loop.run_until_complete(engine.dispose())
        except Exception: logger.debug("pre-run engine.dispose() skipped", exc_info=True)
        return loop.run_until_complete(coro)
    finally:
        try: loop.run_until_complete(engine.dispose())
        except Exception: logger.debug("post-run engine.dispose() skipped", exc_info=True)
        try: loop.close()
        except Exception: pass
```

## 三、统一异常处理体系

### 3.1 问题

原代码在业务层直接 `raise HTTPException(status_code=..., detail=...)`, 缺乏统一异常体系:
- 错误响应格式不一致
- 业务异常与 HTTP 层耦合
- 难以全局捕获和记录

### 3.2 修复方案

**新建** `app/core/exceptions.py`, 定义业务异常基类 + 4 个常用子类:

```python
class AppException(Exception):
    status_code: int = 400
    code: str = "APP_ERROR"
    # ...

class NotFoundError(AppException):       # 404, NOT_FOUND
class PermissionDeniedError(AppException): # 403, PERMISSION_DENIED
class ValidationError(AppException):       # 422, VALIDATION_ERROR
class ConflictError(AppException):         # 409, CONFLICT

def to_response_payload(exc: AppException) -> dict:
    return {"code": exc.code, "message": exc.message}
```

**修改** `app/main.py`, 注册全局异常处理器:

```python
@app.exception_handler(AppException)
async def app_exception_handler(request: Request, exc: AppException):
    return JSONResponse(status_code=exc.status_code, content=to_response_payload(exc))

@app.exception_handler(Exception)
async def unhandled_exception_handler(request: Request, exc: Exception):
    logger.exception("Unhandled exception on %s %s", request.method, request.url.path)
    return JSONResponse(status_code=500, content={"code": "INTERNAL_ERROR", "message": "内部错误"})
```

### 3.3 收益

- 业务层可用 `raise NotFoundError("数据集不存在")` 替代 `raise HTTPException(404, ...)`
- 所有错误响应统一为 `{"code": "...", "message": "..."}` 格式
- 未捕获异常自动记录完整 traceback

## 四、数据库连接池健壮性

### 4.1 问题

- MySQL 连接池参数硬编码, 无法通过环境变量调优
- 缺少 `pool_pre_ping`, 长时间空闲连接可能已断开 (MySQL `wait_timeout` 默认 8h)
- 缺少 `pool_recycle`, 连接池中的连接不会主动回收

### 4.2 修复方案

**修改** `app/config.py`, 新增 3 个配置项:

```python
DB_POOL_SIZE: int = 10        # 连接池大小
DB_MAX_OVERFLOW: int = 20     # 溢出连接数
DB_POOL_RECYCLE: int = 3600   # 连接回收周期 (秒)
```

**修改** `app/database.py`, `_build_engine_kwargs()` MySQL 分支使用配置:

```python
kwargs.update({
    "pool_size": settings.DB_POOL_SIZE,
    "max_overflow": settings.DB_MAX_OVERFLOW,
    "pool_pre_ping": True,       # 使用前 ping, 自动剔除断开连接
    "pool_recycle": settings.DB_POOL_RECYCLE,
})
```

### 4.3 收益

- 连接池参数可通过环境变量调优, 无需改代码
- `pool_pre_ping` 自动检测并剔除断开连接, 避免 `MySQL server has gone away`
- `pool_recycle=3600` 每小时主动回收连接, 配合 MySQL `wait_timeout` 使用

## 五、统计接口 Bug 修复

### 5.1 问题

`GET /api/stats/overview` 的 `train_count` 统计逻辑错误:

```python
# 修复前 (错误)
train_count = select(func.count(ModelVersion.id)).where(
    ModelVersion.is_active.isnot(None)  # 布尔字段 isnot(None) 永远为 True
)
```

该查询实际统计的是 **模型版本数**, 而非 **训练任务数**, 且 `is_active.isnot(None)` 对布尔字段永远为 True, where 条件无效。

### 5.2 修复方案

```python
# 修复后 (正确)
from app.models.training_job import TrainingJob
train_count = select(func.count(TrainingJob.id))
```

### 5.3 收益

- Dashboard 训练任务数显示正确
- 查询从 `ModelVersion` 表改为 `TrainingJob` 表, 语义正确

## 六、优雅关闭

### 6.1 问题

`app/main.py` 的 `lifespan` 上下文管理器缺少关闭逻辑, 应用停止时:
- SQLAlchemy async engine 连接不会主动释放
- Redis 连接不会关闭

### 6.2 修复方案

```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    # startup
    yield
    # shutdown
    try:
        await engine.dispose()
    except Exception:
        logger.warning("engine.dispose() failed during shutdown", exc_info=True)
    try:
        redis_client.close()
    except Exception:
        logger.warning("redis_client.close() failed during shutdown", exc_info=True)
```

### 6.3 收益

- 应用停止时主动释放数据库连接和 Redis 连接
- 避免 Docker / K8s 容器重启时的连接泄漏
