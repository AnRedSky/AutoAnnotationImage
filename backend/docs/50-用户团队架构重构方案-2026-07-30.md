# 用户-团队架构重构方案 — 2026-07-30

> **触发器**: 用户要求"去掉租户概念，改为管理员+用户+团队架构"
> **基线**: MT-1~MT-10 多租户全链已交付 (commit a89b22e)
> **本文档目的**: 整理可行性方案，确认后实施

---

## 一、目标架构

```
管理员 (admin/super_admin)
  ├── 管理全部用户 (CRUD + 启停 + 改角色)
  ├── 查看全部数据集/模型/训练任务
  └── 查看系统审计日志

用户 (annotator/viewer)
  ├── 独立标注: 自己创建的数据集 → 自己标注
  ├── 创建团队: 用户可创建团队 (Team), 邀请其他用户加入
  ├── 团队共享: 团队内共享数据集, 团队成员可协同标注
  └── 团队权限: 团队创建者=队长 (可管理成员+编辑), 普通成员=可标注
```

### 角色体系 (简化为 3 级)

| 角色 | 范围 | 权限 |
|---|---|---|
| super_admin | 全局 | 管理所有用户 + 看全部数据 |
| admin | 全局 | 管理用户 + 看全部数据 (不能管 super_admin) |
| user | 个人+团队 | 自己的数据集 + 加入的团队共享数据集 |

**去掉**: tenant_admin, tenant_id 维度, per-tenant 角色

### 团队模型

```
Team (团队)
  ├── id, name, slug, description
  ├── owner_id (创建者=队长)
  ├── created_at
  └── max_members (默认 20)

TeamMember (团队成员)
  ├── team_id, user_id
  ├── role: leader (队长) | annotator (标注员) | viewer (观察者)
  └── joined_at

Dataset (数据集) — 复用已有
  ├── owner_id (创建者)
  ├── team_id (nullable: null=个人数据集, 非null=团队共享)
  └── team_role: 可标注 (annotator) | 只读 (viewer)
```

### 需要修改的 (权限检查升级)

当前 15 处 `is_admin() and owner_id != current_user.id` 检查要升级为:

```python
# 新模式: admin 全通, 否则 owner OR team_member
if not current_user.is_admin():
    if dataset.owner_id == current_user.id:
        pass  # 自己的
    elif dataset.team_id:
        # 检查 team_member
        tm = await db.execute(
            select(TeamMember).where(
                TeamMember.team_id == dataset.team_id,
                TeamMember.user_id == current_user.id
            )
        )
        if not tm.scalar_one_or_none():
            raise HTTPException(403, "无权限")
    else:
        raise HTTPException(403, "无权限")
```

**优化**: 把这个检查封装到 `User.can_access_dataset(db, dataset)` async 方法里。

## 七、方案决策点

1. **team_id 在 Dataset 上 vs 在 TeamMember 上**:
   - 方案 A: Dataset.team_id (nullable) — 一个数据集要么个人要么团队共享
   - 方案 B: 独立 DatasetTeam 关联表 — 一个数据集可共享给多个团队
   - **推荐方案 A** (简洁, 够用)

2. **用户能创建几个团队**:
   - 不限制 (低风险, 加 max_teams 到 settings 如需限制)

3. **团队内角色**:
   - leader (队长=创建者): 可管理成员 + 编辑数据集
   - annotator: 可标注
   - viewer: 只读
   - **只有 3 种, 不可自定义**

4. **super_admin vs admin 区别**:
   - super_admin: 管理所有用户 (含 admin)
   - admin: 管理普通用户, 不能管 super_admin
   - **保留两级管理员**
