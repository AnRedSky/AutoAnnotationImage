## 二、P2 多租户重构方案

### 2.1 数据模型变更

#### 新增表: `tenant`

```sql
CREATE TABLE tenant (
    id          INTEGER PRIMARY KEY AUTO_INCREMENT,
    name        VARCHAR(100) NOT NULL UNIQUE,
    slug        VARCHAR(50) NOT NULL UNIQUE,  -- URL 友好短名
    status      VARCHAR(16) DEFAULT 'active',  -- active | suspended
    max_users   INTEGER DEFAULT 50,
    max_datasets INTEGER DEFAULT 100,
    created_at  DATETIME NOT NULL
);
```

#### User 表加 `tenant_id`

```python
class User(Base):
    # 现有字段...
    tenant_id: Mapped[int] = mapped_column(
        Integer, ForeignKey("tenant.id"), nullable=False, index=True
    )
    # role 改为 per-tenant (通过 user_tenant_role 关联表)
    # 全局 role 字段保留为 system_role: "super_admin" | "user"
```

#### 新增表: `user_tenant_role` (per-tenant 角色)

```sql
CREATE TABLE user_tenant_role (
    id          INTEGER PRIMARY KEY AUTO_INCREMENT,
    user_id     INTEGER NOT NULL REFERENCES "user"(id),
    tenant_id   INTEGER NOT NULL REFERENCES tenant(id),
    role        VARCHAR(16) NOT NULL,  -- admin | annotator | viewer
    UNIQUE(user_id, tenant_id)
);
```

一个用户可属于多个 tenant，每个 tenant 内有不同角色。

#### 所有业务表加 `tenant_id`

| 表 | 加法 | 说明 |
|---|---|---|
| `dataset` | `tenant_id` (替代 owner_id 或共存) | 按 tenant 隔离 |
| `image` | 通过 dataset_id 间接 (不加字段) | 跟随 dataset |
| `category` | 同上 | 跟随 dataset |
| `model_version` | `tenant_id` | 按 tenant 隔离 |
| `training_jobs` | `tenant_id` | 按 tenant 隔离 |
| `bbox_annotation` | 通过 image 间接 | 跟随 dataset |
| `annotation_log` | `tenant_id` | 按 tenant 隔离 (审计日志独立) |
| `segmentation_mask` | 通过 image 间接 | 跟随 dataset |

### 2.2 中间件层: 自动注入 tenant 过滤

**核心设计**: SQLAlchemy `before_query` event listener，自动给所有 SELECT 加 `WHERE tenant_id = :current_tenant_id`。

```python
# app/middleware/tenant.py

class TenantContext:
    """请求级 tenant 上下文 (contextvar)."""
    _current: contextvars.ContextVar[Optional[int]] = contextvars.ContextVar("tenant_id", default=None)

    @classmethod
    def set(cls, tenant_id: int) -> None:
        cls._current.set(tenant_id)

    @classmethod
    def get(cls) -> Optional[int]:
        return cls._current.get()

    @classmethod
    def clear(cls) -> None:
        cls._current.set(None)

async def tenant_middleware(request: Request, call_next):
    """从 JWT token 解析 tenant_id, 注入 contextvar."""
    token = extract_token(request)
    if token:
        payload = decode_jwt(token)
        TenantContext.set(payload.get("tenant_id"))
    try:
        response = await call_next(request)
    finally:
        TenantContext.clear()
    return response

# app/database/tenant_filter.py

@event.listens_for(engine.sync_engine, "before_cursor_execute")
def _inject_tenant_filter(conn, cursor, statement, parameters, context, executemany):
    """自动给 SELECT 加 WHERE tenant_id = :current_tenant_id.

    只对有 tenant_id 列的表生效; 跳过 tenant 表自身 + user_tenant_role.
    """
    tid = TenantContext.get()
    if tid is None:
        return  # 超级管理员或系统级查询, 不过滤

    # 检查 statement 是否是 SELECT 且含 tenant_id 列的表
    # SQLAlchemy 2.x 提供 do_orm_execute 事件更精确
```

**更精确的方案** (SQLAlchemy 2.x 推荐):

```python
@event.listens_for(Session, "do_orm_execute")
def _filter_tenant(execute_state):
    if execute_state.is_select and not execute_state.is_relationship_load:
        tid = TenantContext.get()
        if tid is not None:
            execute_state.statement = execute_state.statement.where(
                # 给所有有 tenant_id 的 ORM 实体加过滤
                *[e.tenant_id == tid for e in execute_state.bind_mapper.entities
                  if hasattr(e, 'tenant_id')]
            )
```

### 2.3 JWT Token 扩展

```python
# JWT payload 加 tenant_id
{
    "sub": "user_id",
    "tenant_id": 1,           # 新增
    "system_role": "user",    # 新增 (super_admin | user)
    "exp": ...,
    "jti": "...",
}
```

Login 时:
1. 验证 username + password
2. 查 user_tenant_role, 取默认 tenant (或 URL `?tenant=xxx` 指定)
3. JWT 签发时写入 `tenant_id` + `system_role`

### 2.4 迁移路径 (非破坏性)

| 阶段 | 内容 | 风险 |
|---|---|---|
| Step 1 | 创建 tenant 表 + 插入默认 tenant (id=1, "default") | 零 |
| Step 2 | User 加 tenant_id 列 (DEFAULT 1, nullable) | 零 |
| Step 3 | 所有业务表加 tenant_id 列 (DEFAULT 1, nullable) | 零 |
| Step 4 | 创建 user_tenant_role 表 + 从 User.role 迁移数据 | 低 |
| Step 5 | 中间件上线 (TenantContext + do_orm_execute) | 中 (全 query 变化) |
| Step 6 | 旧 API 适配 (JWT 加 tenant_id, login 改流程) | 中 |
| Step 7 | 前端适配 (登录选 tenant, 切换 tenant) | 中 |

**每步可独立部署**, 不破坏现有功能。Step 1-4 是纯加列 (nullable + default), 老代码不感知。Step 5-6 开始过滤。

## 三、权限管理方案

### 3.1 角色体系 (三层)

| 层级 | 角色 | 范围 | 权限 |
|---|---|---|---|
| **系统级** | `super_admin` | 全局 | 管理所有 tenant + 用户 + 系统配置 |
| **租户级** | `tenant_admin` | tenant 内 | 管理 tenant 用户 + 分配角色 + 看全部 dataset |
| **租户级** | `annotator` | tenant 内 | 标注 + 查看 assigned dataset |
| **租户级** | `viewer` | tenant 内 | 只读 |

### 3.2 权限矩阵

| 操作 | super_admin | tenant_admin | annotator | viewer |
|---|---|---|---|---|
| 管理 tenant (创建/停用) | ✅ | ❌ | ❌ | ❌ |
| 管理用户 (创建/停用/分配角色) | ✅ | ✅ (本 tenant) | ❌ | ❌ |
| 创建 dataset | ✅ | ✅ | ❌ | ❌ |
| 删除 dataset | ✅ | ✅ (本 tenant) | ❌ | ❌ |
| 查看 dataset | ✅ | ✅ (本 tenant 全部) | ✅ (assigned) | ✅ (assigned) |
| 上传图片 | ✅ | ✅ | ❌ | ❌ |
| 标注图片 | ✅ | ✅ | ✅ (assigned) | ❌ |
| 启训练 | ✅ | ✅ | ❌ | ❌ |
| 查看训练任务 | ✅ | ✅ (本 tenant 全部) | ✅ (自己的) | ❌ |
| 查看模型 | ✅ | ✅ | ✅ (assigned) | ✅ (assigned) |
| 激活模型 | ✅ | ✅ | ❌ | ❌ |

### 3.3 Dataset 共享机制

```sql
CREATE TABLE dataset_membership (
    id          INTEGER PRIMARY KEY AUTO_INCREMENT,
    dataset_id  INTEGER NOT NULL REFERENCES dataset(id),
    user_id     INTEGER NOT NULL REFERENCES "user"(id),
    role        VARCHAR(16) NOT NULL,  -- annotator | viewer
    assigned_by INTEGER REFERENCES "user"(id),
    assigned_at DATETIME,
    UNIQUE(dataset_id, user_id)
);
```

- dataset owner (或 tenant_admin) 可把 dataset 分享给特定用户
- 被分享的用户有 `annotator` 或 `viewer` 角色 (per-dataset)
- `can_access_dataset` 扩展:

```python
def can_access_dataset(self, dataset, db) -> bool:
    if self.is_super_admin(): return True
    if self.is_tenant_admin() and self.tenant_id == dataset.tenant_id: return True
    if dataset.owner_id == self.id: return True
    # 查 dataset_membership
    return has_membership(db, dataset.id, self.id)
```

## 四、实施优先级

| 阶段 | 内容 | 工作量 | 前置 |
|---|---|---|---|
| **Phase MT-1** | tenant 表 + User 加 tenant_id + migration | 小 | P0 ✅ |
| **Phase MT-2** | user_tenant_role 表 + JWT 加 tenant_id | 小 | MT-1 |
| **Phase MT-3** | 业务表加 tenant_id (nullable, default 1) | 中 | MT-1 |

MT-1 → MT-2 → MT-3 → MT-4 → MT-5

完成后: 系统真正多租户, 数据按 tenant 隔离, dataset 可跨用户共享。

## 五、给当前部署的建议

如果当前是**单团队使用**:
- P0 已足够 (commit d3c8d4a)
- 不需要 P2

如果需要**多团队/多组织**:
- 做 MT-1 到 MT-5 (约 3-5 天工作量)
- 中间件层自动过滤是关键 (避免改 80 个端点)

如果需要**合规审计**:
- 加 MT-6 (audit_log)
- 所有权限操作记录到 audit_log

如果需要**资源配额**:
- tenant 表的 max_users / max_datasets 字段
- 中间件层做配额检查
