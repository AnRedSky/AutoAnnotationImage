## 二、问题 (Phase 1: Root Cause Investigation)

`GET /api/files/{image_id}/thumbnail?size=N` 当前实现 (app/tasks/api/files.py:159-221):
```python
result = await db.execute(...query for Image, Dataset...)
img = ...
_require_user(...)
content = await storage_service.load(img.storage_path)  # 读 disk
pil_img = PILImage.open(BytesIO(content))
pil_img.thumbnail((size, size), PILImage.LANCZOS)  # CPU bound
pil_img = pil_img.convert("RGB")  # CPU bound
pil_img.save(buf, format="JPEG", quality=80)  # CPU bound
return Response(content=thumb_bytes, ...)
```

**根因**: 每次请求都 PIL 重编码同一张图。docs/04 性能优化建议记录 P95 200ms, fix 后预计 1ms 量级 (cache hit)。

**症状**:
- 一张图被 N 用户访问 = N 次 PIL encode
- 列表页 20 张缩略图 = 20 次重复编码 (每页都重)
- doc 列的 P95 大就在这条链上

## 三、TDD: RED → GREEN

### RED (9 tests, 全部 fail)

`backend/tests/test_thumbnail_cache.py` 写完 9 个 RED tests：
1. 模块可 import
2. 模块导出 `thumbnail_for` callable
3. 模块导出 `clear_thumbnail_cache` callable
4. 首次调用调 loader 一次
5. 二次/三次调同 key 返回缓存 loader 不重
6. 不同 size 是不同 cache key
7. 不同 image_id 是不同 cache key
8. LRU 上限 2000 条不爆
9. 20 线程并发同 key: loader 只被调 <= 5 次 (容许 race), 所有线程返回同一 bytes

跑测试：**9 failed, 1 warning** (ImportError on `app.common.cache.thumbnail_cache` — feature missing).

### GREEN (最小实现)

`backend/app/common/cache/thumbnail_cache.py` (~70 行):
- `OrderedDict` 作 LRU dict
- `threading.Lock` 防 race
- 上限 2000 entries
- double-checked locking: 锁内 cache hit, 锁外调 loader, loader 后再锁一次确认 uniqueness

`app/common/cache.py` → `app/common/cache/__init__.py` 包, 因为需要 sub-module:
- 现有 `from app.common.cache import cache` / `cached` / `invalidate` 仍 work (在 __init__.py 重导出)
- 加 `from app.common.cache.thumbnail_cache import thumbnail_for` 也 work

跑测试：**9 passed**. TDD GREEN 完成。

### REFACTOR (端点接 cache)

`app/tasks/api/files.py:get_image_thumbnail` 接入 `thumbnail_for(image_id, size, loader=...)`:
- 用 `run_async_in_worker(storage_service.load(img.storage_path))` 让 sync loader 内能 await
- PII 不缓存到 image content, 只缓存 encoded JPEG bytes (Privacy: 不泄露原图)
- 失败回退原图, header `Cache-Control: private, max-age=86400` 不变 (CDN/浏览器层仍可长缓存)

错误回退逻辑保留: catch 异常 → fall back 原图, 不让一次转换失败影响前端。
