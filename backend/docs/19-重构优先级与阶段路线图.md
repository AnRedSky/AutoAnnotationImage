## 二、阶段衔接与依赖关系

```
Phase 1 (基础设施) ✅
    ↓ 提供干净的目录骨架
Phase 2 (Data 层)
    ↓ 让 ORM 更内聚, 查询函数可复用
Phase 3 (Service 层)
    ↓ 让业务规则有家, 路由可以薄
Phase 4 (API 薄化 + Schema)
    ↓ API 文件 < 300 行
Phase 5 (Worker 薄化)
    ↓ workers 委托 service, ml 纯计算
    ↓ (可选) Stage 2-5: 多应用拆分
```

**关键依赖**:
- Phase 2 强依赖 Phase 1 (model/ 目录已就位)
- Phase 3 强依赖 Phase 2 (需要 ORM 加业务方法)
- Phase 4 强依赖 Phase 3 (Service 抽取后才能薄化路由)
- Phase 5 弱依赖 Phase 3 (Worker 也可以直接调 model, 但调 service 更优)

## 十三、阶段验收与提交流程

每阶段完成后:

1. **代码自检**:
   ```bash
   cd backend
   python -m py_compile app/**/*.py
   python -c "import app.main; assert len(app.main.app.routes) >= 100"
   ```

2. **测试**:
   ```bash
   cd backend
   pytest tests/ -v --tb=short
   ```

3. **写完成报告**: 在 `backend/docs/` 下新增 `XX-StageN-实施完成报告.md`

4. **更新本路线图**: 标记当前 Stage 为 ✅, 更新下一阶段目标

5. **Git 提交** (原子提交, 每阶段 2-4 个 commit):
   ```bash
   git add backend/
   git commit -m "feat(stageN): <核心代码>"
   git commit -m "docs(stageN): <完成报告>"
   ```

6. **立即推进下一阶段**: 不等待用户指令, 按路线图自动衔接
