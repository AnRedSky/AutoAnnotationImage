> **版本**: v1.0 (2026-07-22)
> **配套文档**: `05-分阶段迭代计划.md`

## 一、工具总览

| 脚本 | 用途 | 状态 |
|---|---|---|
| `stage_runner.py` | 主编排器, 执行阶段/标记完成/推进 | ⭐ 核心 |
| `progress_tracker.py` | 单独更新进度看板 | 辅助 |
| `task_done.py` | 单独标记/取消任务完成 | 辅助 |
| `ai_task_helper.py` | 输出 AI 上下文 + 记录 AI 协助 | AI 协作 |
| `verify_exit.py` | 单独验证 exit_checks | 调试 |
| `rollback.py` | 回滚到上一阶段 | 应急 |

## 二、stage_runner.py 详解

### 2.1 主命令

```bash
# 执行当前阶段
python backend/scripts/stage_runner.py

# 查看整体进度
python backend/scripts/stage_runner.py --status

# 执行指定阶段
python backend/scripts/stage_runner.py --stage S1

# 标记任务完成
python backend/scripts/stage_runner.py --mark-complete S1-T1
python backend/scripts/stage_runner.py --mark-complete S1-T2 --note "改 action=ai_predict"

# 跳到指定阶段 (强制)
python backend/scripts/stage_runner.py --jump S3

# 回滚到上一阶段
python backend/scripts/stage_runner.py --rollback

# 强制推进 (跳过完成度阈值)
python backend/scripts/stage_runner.py --force-next

# 仅更新进度看板
python backend/scripts/stage_runner.py --update-board
```

### 2.2 工作流程

```
执行 stage_runner.py
  ↓
读取 stage_config.yaml
  ↓
检查前置依赖 → 不通过则退出
  ↓
列出待完成任务
  ↓
等待人工标记完成 (--mark-complete)
  ↓
重新运行 → 验证完成度
  ↓
跑 exit_checks
  ↓
完成度 ≥ 阈值? 
  ├─ 是 → 生成报告 + git commit + 推进下一阶段
  └─ 否 → 提示剩余任务, 等待
```

### 2.3 阶段流转图

```
S1 (P0 缺陷修复)
  ↓ 完成度 100% + exit_checks
S2 (ML 核心测试)
  ↓ 完成度 100% + 覆盖率 ≥ 80%
S3 (P1 安全加固)  ─┬─→ S5 (性能优化)
                  └─→ S6 (可观测性)
S4 (文档同步) ───────────────────┐
                                ↓
S7 (压测与验收) ← S5 + S6 完成
  ↓
S8 (发布准备) → v1.0.0 tag
```

## 三、其他脚本详解

### 3.1 progress_tracker.py

```bash
# 仅更新 PROGRESS.md 看板
python backend/scripts/progress_tracker.py
```

**适用场景**: 手动编辑 stage_config.yaml 后, 刷新看板。

### 3.2 task_done.py

```bash
# 标记完成
python backend/scripts/task_done.py S1-T1
python backend/scripts/task_done.py S1-T1 --note "删除 1 行"

# 取消完成
python backend/scripts/task_done.py S1-T1 --unmark
```

**适用场景**: 不想用 stage_runner.py 的完整流程, 快速标记。

### 3.3 ai_task_helper.py

```bash
# 输出 AI 上下文 (供 AI 读取)
python backend/scripts/ai_task_helper.py context S1-T1
# 输出: 任务元信息 + 阶段目标 + 涉及文件内容 + 期望输出格式

# 记录 AI 协助历史
python backend/scripts/ai_task_helper.py log S1-T1 done

# 查看历史
python backend/scripts/ai_task_helper.py list
```

**AI 协作模式**:
1. 运行 `context S1-T1` 获取任务上下文
2. 将输出发给 AI (如 Copilot/Claude/GPT)
3. AI 返回代码 diff 或修改建议
4. 人工应用 diff 到代码
5. 跑测试验证
6. 运行 `task_done.py S1-T1` 标记完成

### 3.4 verify_exit.py

```bash
# 验证当前阶段退出标准
python backend/scripts/verify_exit.py

# 验证指定阶段
python backend/scripts/verify_exit.py --stage S1
```

**适用场景**: 调试时单独验证 exit_checks, 不推进阶段。

### 3.5 rollback.py

```bash
# 回滚 1 个阶段 (默认)
python backend/scripts/rollback.py

# 回滚 2 个阶段
python backend/scripts/rollback.py --stages 2

# 仅回滚配置, 不操作 git
python backend/scripts/rollback.py --no-git
```

**适用场景**: 阶段流转后发现问题, 撤销状态。

**注意**: `git revert` 不会自动 commit, 需人工确认。

## 四、与 AI 协作的标准流程

### 4.1 单任务 AI 协助模式

```bash
# 步骤 1: 获取任务上下文
python backend/scripts/ai_task_helper.py context S1-T1 > task_context.txt

# 步骤 2: AI 读取 task_context.txt, 生成 diff
# (在 IDE/AI 工具中)

# 步骤 3: 应用 diff
git apply < diff.patch
# 或手动复制粘贴

# 步骤 4: 验证
pytest tests/test_xxx.py -v
python backend/scripts/verify_exit.py

# 步骤 5: 标记完成
python backend/scripts/task_done.py S1-T1 --note "AI 协助完成"

# 步骤 6: 进入下一任务
python backend/scripts/ai_task_helper.py context S1-T2
```

### 4.2 批量 AI 协助模式

```bash
# 一次性输出所有当前阶段任务上下文
for task in S1-T1 S1-T2 S1-T3 S1-T4; do
  python backend/scripts/ai_task_helper.py context $task >> all_context.txt
done
# 发给 AI 批量生成
```

### 4.3 AI 协助历史追踪

所有 AI 协助操作记录在 `backend/docs/stage_logs/ai_assist_history.jsonl`, 可用于:
- 回溯哪些任务由 AI 完成
- 统计 AI 协助效率
- 论文中"AI 辅助开发"章节引用

## 五、配置说明

### 5.1 stage_config.yaml 关键字段

```yaml
current_stage: S1                       # 编排器自动更新
current_stage_status: IN_PROGRESS       # 手动调整

stages:
  S1:
    name: P0 缺陷修复
    tasks:
      - id: S1-T1
        title: ...
        files: [...]
        ai_assisted: true               # 是否 AI 协助
        estimated_hours: 0.5            # 预计耗时
    exit_threshold: 100                 # 完成度阈值 (%)
    exit_checks:                        # 退出前必跑
      - description: 4 文件已修改
        command: git diff --name-only HEAD~1..HEAD | grep ...
```

### 5.2 调整阶段顺序

如需调整阶段顺序, 编辑 `stage_config.yaml` 中 `stages:` 下顺序, 重启编排器即可。

### 5.3 调整退出阈值

如某阶段允许 < 100% 完成 (例如 S4 文档同步, 5 个任务可跳过部分), 调整 `exit_threshold`:

```yaml
S4:
  exit_threshold: 60  # 至少完成 60%
```

## 六、常见问题

### Q1: 任务完成后, 阶段没自动推进?

检查:
1. 是否所有任务都已 `--mark-complete`
2. `exit_checks` 是否全部通过
3. 完成度是否 ≥ `exit_threshold`

解决:
```bash
# 查看详细状态
python backend/scripts/stage_runner.py --status

# 单独验证 exit_checks
python backend/scripts/verify_exit.py

# 强制推进 (跳过阈值)
python backend/scripts/stage_runner.py --force-next
```

### Q2: 阶段卡住, 想回滚?

```bash
# 仅回滚配置 (推荐)
python backend/scripts/rollback.py --no-git

# 完整回滚 (git + 配置)
python backend/scripts/rollback.py
```

### Q3: 想跳过某个阶段?

```bash
# 跳到指定阶段 (强制, 跳过依赖检查)
python backend/scripts/stage_runner.py --jump S3
```

### Q4: 看板不同步?

```bash
# 手动刷新
python backend/scripts/progress_tracker.py
```

### Q5: 怎么暂停迭代?

```yaml
# 编辑 stage_config.yaml
current_stage_status: PAUSED  # 标记暂停
```

下次启动时, 编排器检测到 PAUSED 会提示继续。

## 八、最佳实践

1. **每完成一个任务立即标记**: 避免遗忘
2. **每个任务单独 commit**: 便于回滚和定位
3. **AI 协助生成的代码必须人工审查**: 防止幻觉
4. **阶段报告保留在 git**: 可追溯
5. **看板每天至少看一次**: 防止停滞
6. **exit_checks 必跑**: 防止"假完成"
