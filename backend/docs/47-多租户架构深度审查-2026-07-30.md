# 多租户架构深度审查报告 — 2026-07-30

> **日期**: 2026-07-30
> **审查范围**: 用户结构、数据存在、数据隔离
> **审查方法**: 全量代码审计 (102 个 API 端点 + ORM model + 中间件)

---

## 一、审查结论

### 总体评级: ⚠️ **当前不是多租户系统，是单租户多用户系统**

系统设计为"一个团队共享一个部署实例"的单租户模式。所有用户共享所有数据，仅靠 `admin` 角色区分管理权限。

**如果作为多租户系统使用，存在严重数据隔离缺口。**

---

## 二、用户结构审查

### 2.1 User Model

```python
class User(Base):
    id            # PK
    username      # unique, index
    password_hash
    email
    role          # Enum("admin", "annotator", "viewer")
    is_active
    created_at
```

| 检查项 | 状态 | 说明 |
|---|---|---|
| tenant_id 字段 | ❌ **不存在** | User 无任何 tenant/org/team 维度 |
| 角色体系 | ✅ 基本完整 | admin/annotator/viewer 三级 |
| 角色是否 per-tenant | ❌ 否 | role 是全局的，不区分"在 A 项目是 admin，在 B 项目是 annotator" |
| 用户停用 | ✅ is_active | 有 deactivate/activate |
| 密码安全 | ✅ password_hash | 有 hash_password |

### 2.2 权限中间件

| 中间件 | 覆盖 | 缺口 |
|---|---|---|
| `get_current_user` | JWT 验证 + 用户加载 | ✅ |
| `require_admin` | 检查 role == "admin" | ✅ 但仅 6 个端点用 (user.py 5 个 + auth.py 1 个) |
| `can_access_dataset` | admin 全通 / 非 admin 只看 owner | ✅ 但仅 files.py 2 处调用 |
| `get_user_optional_for_query` | 可选鉴权 (?token=xxx) | ⚠️ 用于 `<img>` 标签场景 |

**关键缺口**: `can_access_dataset` **仅 2 处调用** — files.py 的 `get_image_file` + `get_image_thumbnail`。其他 100 个端点**不查** dataset 权限。

## 三、数据存在审查

### 3.1 各表 owner/tenant 维度

| 表 | owner_id / user_id | tenant_id | 说明 |
|---|---|---|---|
| **user** | — | ❌ 无 | 没有 tenant 维度 |
| **dataset** | ✅ `owner_id` FK→user | ❌ 无 | 有 owner 但无 tenant |
| **image** | ❌ 无 owner (通过 dataset_id 间接) | ❌ 无 | 隔离依赖 dataset.owner_id |
| **category** | ❌ 无 (通过 dataset_id) | ❌ 无 | 同上 |
| **model_version** | ❌ 无 owner | ❌ 无 | 谁都能看到所有模型版本 |
| **training_jobs** | ✅ `user_id` FK→user | ❌ 无 | 有 user_id 但 list 端点不过滤 |
| **bbox_annotation** | ✅ `annotated_by` FK→user | ❌ 无 | 有标注人但查询不按此过滤 |
| **annotation_log** | ✅ `user_id` FK→user | ❌ 无 | 有用户但 list 端点不按此过滤 |
| **segmentation_mask** | ✅ `annotated_by` FK→user | ❌ 无 | 同上 |

### 3.2 数据存在风险

| 风险 | 严重度 | 说明 |
|---|---|---|
| **所有用户共享所有 dataset** | 🔴 高 | `list_datasets` 返所有 dataset，不按 owner 过滤 |
| **所有用户看到所有 model** | 🔴 高 | `list_models` 返所有 model_version，不按 owner 过滤 |
| **所有用户看到所有 training job** | 🔴 高 | `list_training_jobs` 不按 user_id 过滤 |
| **标注员可修改任意 dataset 的图片** | 🔴 高 | `save_annotation` 不查 dataset owner 权限 |
| **标注员可删除任意 dataset** | 🔴 高 | `delete_dataset` 不查 owner / admin |
| **标注员可对任意 dataset 上传图片** | 🔴 高 | `upload_images` 不查 dataset owner |
| **标注员可对任意 dataset 启训练** | 🔴 高 | `start_training` 不查 dataset owner |

## 四、数据隔离审查

### 4.1 API 端点隔离矩阵

| 端点 | 权限检查 | 隔离方式 | 风险 |
|---|---|---|---|
| `GET /api/datasets` | ❌ 无 owner 过滤 | 无隔离 | 任意用户看所有 dataset |
| `GET /api/datasets/{id}` | ❌ 无 can_access | 无隔离 | 任意用户看任意 dataset 详情 |
| `DELETE /api/datasets/{id}` | ❌ 无 owner/admin 检查 | 无隔离 | 任意用户删任意 dataset |
| `POST /api/datasets/{id}/images` | ❌ 无 owner 检查 | 无隔离 | 任意用户上传到任意 dataset |
| `GET /api/images/list/{ds_id}` | ❌ 无 can_access | 无隔离 | 任意用户看任意 dataset 的图片 |
| `POST /api/annotations` (save) | ❌ 无 can_access | 无隔离 | 任意用户标注任意 dataset 的图片 |
| `GET /api/annotations/list/{ds_id}` | ❌ 无 can_access | 无隔离 | 任意用户看任意 dataset 的标注审计 |
| `GET /api/models/` | ❌ 无 owner 过滤 | 无隔离 | 任意用户看所有模型 |
| `GET /api/training/jobs` | ❌ 无 user_id 过滤 | 无隔离 | 任意用户看所有训练任务 |
| `POST /api/training/start` | ❌ 无 can_access | 无隔离 | 任意用户对任意 dataset 启训练 |
| `GET /api/files/{image_id}` | ✅ `_require_user` + `can_access_dataset` | ✅ 隔离 | 仅 owner/admin 可访问 |
| `GET /api/files/{image_id}/thumbnail` | ✅ 同上 | ✅ 隔离 | |
| `GET /api/admin/users` | ✅ `require_admin` | ✅ 隔离 | 仅 admin |
| `POST /api/admin/users/{id}/role` | ✅ `require_admin` | ✅ 隔离 | 仅 admin |

### 4.2 隔离缺口统计

| 维度 | 数值 |
|---|---|
| 总 API 端点 | 102 |
| 有 owner/user 过滤 | **19** (18.6%) |
| 无 owner/user 过滤 (排除 health/metrics) | **80** (78.4%) |
| `can_access_dataset` 调用次数 | **2** (仅 files.py) |
| `require_admin` 调用次数 | **6** (仅 user.py + auth.py) |

## 五、优化方向与优先级

### P0 (安全 — 必须修)

| # | 优化 | 影响 | 工作量 |
|---|---|---|---|
| P0-1 | `list_datasets` 加 owner 过滤 (非 admin 只看自己的) | 防止跨用户数据泄露 | 5 行 |
| P0-2 | `delete_dataset` 加 owner/admin 检查 | 防止跨用户删除 | 5 行 |
| P0-3 | `upload_images` 加 `can_access_dataset` 检查 | 防止跨用户上传 | 5 行 |
| P0-4 | `save_annotation` 加 `can_access_dataset` 检查 | 防止跨用户篡改标注 | 5 行 |
| P0-5 | `start_training` 加 `can_access_dataset` 检查 | 防止跨用户启训练 | 5 行 |
| P0-6 | `list_training_jobs` 加 user_id 过滤 (非 admin 只看自己的) | 防止跨用户查看训练 | 5 行 |

**总工作量**: ~30 行代码，统一用 `can_access_dataset` 或 `owner_id == current_user.id` 过滤。

### P1 (增强)

| # | 优化 | 说明 |
|---|---|---|
| P1-1 | `list_models` 按 dataset owner 过滤 (非 admin 只看自己 dataset 的 model) | 中等 |
| P1-2 | `list_annotations` 加 `can_access_dataset` 检查 | 中等 |
| P1-3 | `get_dataset` (详情) 加 `can_access_dataset` 检查 | 小 |
| P1-4 | `list_images` 加 `can_access_dataset` 检查 | 小 |

### P2 (多租户化 — 大重构)

| # | 优化 | 说明 |
|---|---|---|
| P2-1 | User 加 `tenant_id` 字段 + 所有表加 `tenant_id` | 大重构 (所有 ORM + 所有 query) |
| P2-2 | 中间件层注入 `tenant_id` 过滤 (SQLAlchemy event listener) | 中等 |
| P2-3 | 角色改为 per-tenant (UserDatasetRole 关联表) | 大 |
| P2-4 | Dataset 加 `is_public` 字段 (允许 owner 显式共享) | 小 |

### 建议路径

1. **先做 P0** (30 行代码，修安全缺口)
2. **再做 P1** (补齐剩余隔离)
3. **P2 视需求决定** — 如果系统定位是"单团队共享"，P2 不需要；如果需要多团队/多组织，P2 是必须的

## 六、当前定位判断

| 问题 | 回答 |
|---|---|
| 这是多租户系统吗？ | **否**。User 没有 tenant_id，所有表没有 tenant 维度。 |
| 它是单租户多用户吗？ | **是**。所有用户共享所有数据，admin 管全局。 |
| 数据隔离够吗？ | **不够**。仅 files.py 2 处做了 `can_access_dataset` 检查，其余 80 个端点裸跑。 |
| 当前部署能多团队用吗？ | **不能**。annotator 能看/改/删所有人的数据。 |
| 最小修复路径？ | P0: 6 处 ~30 行代码，统一加 `can_access_dataset` 或 `owner_id` 过滤。 |
