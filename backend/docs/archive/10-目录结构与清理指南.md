# 后端目录结构与清理指南

***

## 一、目录分类标准

`backend/` 目录按功能划分为 6 大类：

| 类别 | 路径 | 是否版本控制 | 说明 |
|---|---|---|---|
| **应用代码** | `app/` | ✅ 追踪 | FastAPI 应用代码（api / core / ml / models / schemas / services / workers） |
| **数据库迁移** | `migrations/` | ✅ 追踪 | Alembic 风格迁移脚本 |
| **测试代码** | `tests/` | ✅ 追踪 | pytest 测试（unit + integration + e2e） |
| **运维脚本** | `scripts/` | ✅ 追踪 | 数据准备、迁移、压测等一次性脚本 |
| **文档** | `docs/` | ✅ 追踪 | 审查报告、修复计划、性能优化建议等 |
| **运行时数据** | `models/`、`uploads/`、`demo/data/` | ❌ gitignore | 模型权重、用户上传、演示数据 |
| **环境/缓存** | `.venv/`、`.env`、`*.log`、`.pytest_cache/`、`__pycache__/`、`*.coverage` | ❌ gitignore | 虚拟环境、本地配置、日志、缓存 |

## 二、目录树（标准结构）

```
backend/
├── app/                          # 应用代码 (FastAPI)

│   │   └── segmentation/         # DeepLabV3+ 分割
│   ├── models/                   # ORM 模型
│   ├── schemas/                  # Pydantic 模型
│   ├── services/                 # 业务服务 (ai / bbox / storage)
│   ├── workers/                  # Celery 任务
│   ├── cli.py
│   ├── config.py
│   ├── database.py
│   └── main.py
├── migrations/                   # 数据库迁移
├── tests/                        # pytest 测试
├── scripts/                      # 运维脚本
├── docs/                         # 文档
│
# === 运行时数据（gitignore）===
├── models/                       # 训练好的模型权重
├── uploads/                      # 用户上传

│
# === 环境与缓存（gitignore）===

├── yolov8n.pt                    # YOLOv8 预训练权重（项目首次启动时下载）

├── .env.docker                   # Docker 部署环境变量模板
├── .env.example                  # 本地开发环境变量模板
├── .gitignore                    # 版本控制忽略规则

├── Dockerfile                    # Docker 镜像构建
├── README.md                     # 项目说明
├── run.py                        # 启动入口 (uvicorn wrapper)
├── start_api.py                  # API 启动脚本
└── start_workers.py              # Celery worker 启动脚本
```

## 四、定期清理流程

### 4.1 本地开发清理（每周一次）

```powershell
# 1. 删除 Python 字节码
cd "d:\works\WorkBuddy\Myhome\系统实现\thesis-image-annotation-zzh\backend"
Get-ChildItem -Recurse -Force -Directory | Where-Object { $_.Name -eq "__pycache__" } | ForEach-Object { Remove-Item -Recurse -Force $_.FullName }

# 2. 删除 pytest 缓存
Remove-Item -Recurse -Force .pytest_cache -ErrorAction SilentlyContinue

# 3. 删除覆盖率报告
Remove-Item -Force .coverage -ErrorAction SilentlyContinue
Remove-Item -Recurse -Force htmlcov -ErrorAction SilentlyContinue

# 4. 删除临时日志（保留 *.log 在 .gitignore 内的）
Remove-Item -Force backend_log.txt, run.log -ErrorAction SilentlyContinue
Get-ChildItem -Force -File | Where-Object { $_.Name -match "^pytest_.*\.log$" } | Remove-Item -Force
```

### 4.2 模型权重清理（每月一次）

```powershell
# 查看 models/ 目录大小
cd "d:\works\WorkBuddy\Myhome\系统实现\thesis-image-annotation-zzh\backend"
Get-ChildItem -Path "models" -Recurse -File | Measure-Object -Property Length -Sum

# 仅保留最近 5 个训练权重（按 LastWriteTime 排序）
Get-ChildItem -Path "models" -File -Filter "*.pth" |
    Sort-Object LastWriteTime -Descending |
    Select-Object -Skip 5 |
    Remove-Item -Force
```

### 4.3 演示数据清理（按需）

```powershell
# 删除演示数据 (可重新生成)
Remove-Item -Recurse -Force "demo/data" -ErrorAction SilentlyContinue
# 重新生成（参考 scripts/prepare_*_demo.py）
uv run python scripts/prepare_demo_data.py
```

### 4.4 用户上传清理（按需，谨慎）

```powershell
# 查看上传目录大小
Get-ChildItem -Path "uploads" -Recurse -File | Measure-Object -Property Length -Sum

# 仅清理已删除 dataset 关联的孤儿文件（需先 DB 校验）
# 建议通过管理 API 执行: POST /admin/cleanup-orphans
```

## 五、文件分类标准

### 5.1 应放在 `app/` 的文件
- FastAPI 路由、依赖、中间件
- SQLAlchemy ORM 模型、Pydantic Schema
- 业务服务（AI、BBox、Storage）
- Celery 任务
- ML 训练/推理代码
- 应用配置（config.py）

### 5.2 应放在 `migrations/` 的文件
- Alembic 风格迁移脚本
- 数据库 schema 变更

### 5.3 应放在 `tests/` 的文件
- 单元测试（test_*.py）
- 集成测试、E2E 测试
- pytest fixture（conftest.py）
- 测试数据 manifest（fixtures/manifest.json）

### 5.4 应放在 `scripts/` 的文件
- 数据准备脚本（prepare_*_demo.py）
- 一次性数据迁移（migrate_v2_0_0.*）
- 压测、基准测试脚本

### 5.5 应放在 `docs/` 的文件
- 审查报告、修复计划
- 性能优化建议、监控建议
- 业务功能清单
- API 文档、架构设计文档

### 5.6 **不应**放在 `backend/` 根目录的文件
- ❌ 临时日志（`backend_log.txt`、`run.log`）
- ❌ 覆盖率报告（`.coverage`、`htmlcov/`）
- ❌ 测试输出（`pytest_*.log`）
- ❌ 个人草稿、笔记
- ❌ 下载的临时文件

### 5.7 **不应**放在 `app/` 内的文件
- ❌ 模型权重（应在 `models/`）
- ❌ 用户上传（应在 `uploads/`）
- ❌ 训练数据（应在 `data/raw/` 或外部存储）

## 六、清理 Checklist

### 6.1 新功能开发后
- [ ] 代码放在 `app/` 对应子目录
- [ ] 测试放在 `tests/`（与 `app/` 结构镜像）
- [ ] 数据库变更同步写 alembic 迁移到 `migrations/`
- [ ] 删除调试日志（`print()` / `console.log`）
- [ ] 删除调试用的 `__pycache__`、`.pyc`

### 6.2 提交 PR 前
- [ ] `git status` 检查无遗留临时文件
- [ ] `git status --ignored` 确认忽略规则生效
- [ ] 删除个人测试用的脚本/数据
- [ ] 大文件（> 1MB）确认在 gitignore 中

### 6.3 每月清理
- [ ] 删除陈旧模型权重（保留最近 5 个）
- [ ] 清理孤儿上传文件
- [ ] 检查 `.venv` 体积（必要时 `uv sync --reinstall`）

## 七、常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 把模型权重上传到 GitHub | 仓库体积膨胀，PR diff 不可读 | `.gitignore` 忽略 `*.pth` |
| 把 `.env` 提交 | 泄露数据库密码 / API 密钥 | `.gitignore` 忽略 `.env`，提交 `.env.example` |
| 把 `__pycache__` 提交 | 仓库污染，跨平台冲突 | `.gitignore` 忽略 `__pycache__/` |
| 把 `models/` 与 `app/models/` 混淆 | import 路径错乱 | 明确职责：app/models = ORM, models/ = 权重 |
| 在 backend/ 根目录放临时脚本 | 目录混乱 | 一次性脚本放 `scripts/` |
