# Phase V 优化 #4: DB 索引补全 (model_version) — 2026-07-30

---

## 一、问题 (Phase 1: Root Cause)

`GET /api/models/active` (Phase V #2 已 N+1 fix) + `GET /api/models/?active=true` 走热查询:

```sql
SELECT ... FROM model_version
WHERE is_active = :value       -- 全表扫 (无 index)
ORDER BY created_at DESC      -- filesort
```

### 缺索引:
- **`model_version.is_active`** (热路径 WHERE 频繁)
- **`model_version.created_at`** (热路径 ORDER BY 频繁)

`dataset_id` 已有 FK 自动索引, `task_type` 已有 `index=True`, 但上面 2 列没显式索引.

---

## 二、Phase 2/3: 方案选择

| 方案 | 工作量 | 性能 | 备注 |
|---|---|---|---|
| A. ORM `index=True` 加列声明 | 极小 (5 行) | **新表自动建** | 老表无 |
| B. 配合 migration ALTER ADD INDEX | 中 (60 行) | 老表也建 | dev/prod 一致 |
| 选 B | 同时改 model 声明 + 新 migration | | |

考虑 `init_db()` 调用 `ensure_v2_0_0_schema()` — 现有迁移框架已经有 `_table_exists / _column_exists / _get_mysql_varchar_length` 等 helpers. 加 `_ensure_indexes` 复用同样模式: 幂等 check + create.

## 三、实现

### 1. `app/tasks/model/model_version.py`: 加 `index=True`

```python
is_active:   Mapped[bool] = mapped_column(Boolean, default=False, index=True)  # NEW
created_at:  Mapped[datetime] = mapped_column(DateTime, default=..., index=True)  # NEW
```

新表会从 ORM 声明自动建; 老表已存在的需 migration ALTER.

### 2. `app/database/migration.py`: 加 INDEXES 表 + `_ensure_indexes`


挂在 `ensure_v2_0_0_schema()` 末尾 (在 annotation_log.action ENUM 之后).

### 3. 幂等性保证

- `init_db()` 启动调一次 `ensure_v2_0_0_schema` → `_ensure_indexes` 检查
- 重复启动: 已存在索引 → 跳过
- 跨数据库 (MySQL/SQLite): `_mysql_index_exists` 非 MySQL 返 False → SQLite CREATE INDEX (SQLite 也支持)
- 失败不阻塞 (try/except 收集 errors, 不抛)

## 四、验证 (EXPLAIN 真证据)

```sql
EXPLAIN SELECT id FROM model_version WHERE is_active=1 ORDER BY created_at DESC LIMIT 1
```

**结果 (Phase V #4 之前)**: `type=ALL, key=NULL, Using filesort` (全表扫 + filesort)

**结果 (Phase V #4 之后)**:
```
| id | select_type | table         | type  | possible_keys               | key                            | rows | Extra                            |
| 1  | SIMPLE      | model_version | index | ix_model_version_is_active  | ix_model_version_created_at   | 8    | Using where; Backward index scan |
```

| EXPLAIN 列 | 之前 | 之后 | 解读 |
|---|---|---|---|
| type | ALL | **index** | 走 index 而非全表扫 |
| key | NULL | **ix_model_version_created_at** | MySQL 选用了 index |
| Extra | (nothing) | **Using where; Backward index scan** | Backward index scan = 不全表扫, 走 index |

**优化生效**: 真生产环境下 query `WHERE is_active=1 ORDER BY created_at DESC` 现在:
1. MySQL 选 `ix_model_version_created_at` 索引反向扫描
2. 用 WHERE 条件过滤 is_active
3. 不需要 filesort
