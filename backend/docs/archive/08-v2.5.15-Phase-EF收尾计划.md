## 二、关键决策与权衡

### 2.1 P0-1 model_name 字段处理
- **决策**: 删除 ORM 字段, 模型名写入 `AnnotationLog.payload` (JSON)
- **权衡**: 避免 migration 复杂度, payload 字段通用性更强

### 2.2 P0-2 枚举扩展值
- **决策**: 加 `auto_annotate_pretrained` / `auto_annotate_finetuned` 2 个值
- **权衡**: 区分两种 auto-annotate 场景, 审计可追溯

### 2.3 P1-4 线程池大小
- **决策**: `cpu_count * 2`, 上限 16
- **权衡**: CPU 模式 sweet spot, 避免过大 context switch

### 2.4 P1-5 ModelPool 设计
- **决策**: LRU + threading.Lock, max_size=2
- **权衡**: 预训练 + fine-tuned 双 model 是主流场景, 完全规避互踩

### 2.5 P1-6 批处理实现
- **决策**: torch.stack 拼 batch, 默认 batch_size=8
- **权衡**: CPU 模式内存 sweet spot, 大图场景可降到 4
