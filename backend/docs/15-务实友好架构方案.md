# 务实友好架构方案 (推荐版)

> **方案版本**: v2.0 (替代 v1.0 严格分层方案)
> **制定日期**: 2026-07-24
> **适用对象**: 中小型项目 / 毕业论文 / 1-3 人小团队
> **代码规模**: ~12,700 行 (app/) / 14 个 API 文件 / 9 个 ORM 模型
> **核心定位**: 务实、低迁移成本、按业务域组织、Service 为中心

---

## 一、为什么需要"更友好"的方案

### 1.1 v1.0 方案 (13-架构分层重构方案.md) 的反思

之前提出的 **Clean Architecture + DDD** 方案存在以下"不友好"问题:

| 问题 | 体现 |
|---|---|
| 🚨 抽象层太多 | Domain Entity + Repository 接口 + Repository 实现 + ORM Model, 同一个 TrainingJob 要在 4 处定义 |
| 🚨 转换代码爆炸 | ORM ↔ Entity 双向转换, 9 个表 × 2 方向 = 18 个转换函数, 纯样板代码 |
| 🚨 学习曲线陡 | 团队需懂 DDD / Clean Arch / 依赖倒置, 对毕业论文场景过重 |
| 🚨 迁移成本高 | 29 人天, 等于重写整个后端, 风险大 |
| 🚨 过度抽象 | Repository 接口只有一个 SQLAlchemy 实现, 抽象无收益 |
| 🚨 文件爆炸 | 12 个新目录 (domain/repositories/di/api/v1/...), 找代码反而更难 |

### 1.2 友好架构的评判标准

| 标准 | v1.0 严格分层 | v2.0 务实分层 (本文) |
|---|---|---|
| **学习曲线** | 高 (需懂 DDD) | ✅ 低 (业务域 + Service, 一句话能说清) |
| **代码量** | +30% (转换 + 接口) | ✅ -10% (消除重复) |
| **迁移成本** | 29 人天 | ✅ 12 人天 |
| **可读性** | 层清晰但文件多 | ✅ 按域归类, 找代码更快 |
| **可测试性** | 极佳 (Mock Repository) | ✅ 良好 (Mock Service) |
| **小团队适配** | 弱 (角色多, 文档多) | ✅ 强 (一人可全栈) |
| **毕业论文适配** | 弱 (体量过重) | ✅ 强 (规模匹配) |

### 1.3 核心改进思路

> **"消除痛点, 不增加抽象"**

- ✅ **保留**: models / schemas / workers / ml / core 目录不动
- ✅ **重组**: api/ 按业务域拆为 modules/{业务}/
- ✅ **新增**: 每个业务域一个 service.py (业务编排中心)
- ✅ **新增**: 通用 JobStateService (解决状态机分散)
- ✅ **新增**: 通用 SSE 工具 (消除三处重复)
- ❌ **不做**: 不引入 domain/ 实体层
- ❌ **不做**: 不引入 repositories/ 接口层
- ❌ **不做**: 不引入 di/ 容器
- ❌ **不做**: 不重写 ORM Model

## 二、目标架构 (一图概览)

### 2.1 三层结构 (而非五层)

```
┌──────────────────────────────────────────────────┐
│  API 层 (Router) — HTTP 适配, 薄                  │
│  modules/{业务}/router.py                         │
│  - 接收请求 / 调 Service / 返回响应              │
│  - 单文件 < 300 行, 单端点 < 30 行               │
└──────────────────────────────────────────────────┘
                       ↓
┌──────────────────────────────────────────────────┐
│  Service 层 (业务编排) — 厚, 业务规则中心        │
│  modules/{业务}/service.py + services/*          │
│  - 业务规则 / 事务 / 调 ML / 调 Worker           │
│  - 可单测 (Mock Session)                         │
└──────────────────────────────────────────────────┘
                       ↓
┌──────────────────────────────────────────────────┐
│  Data 层 (ORM + 查询助手) — 直接复用现有         │
│  models/* (ORM) + modules/{业务}/queries.py      │
│  - SQLAlchemy Model 即 Domain (加业务方法)       │
│  - queries.py 封装复杂查询, 不强求接口           │
└──────────────────────────────────────────────────┘

跨切: core/* (异常/依赖/Redis/安全)
     workers/* (Celery 入口, 委托 Service)
     ml/* (纯计算, 不依赖 DB)
```

### 2.2 关键设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 分层方式 | 3 层 (API/Service/Data) | 不引入 Domain/Repository 独立层 |
| 业务组织 | **按业务域** (feature-based) | 同一业务的代码集中, 找得快 |
| ORM 角色 | **Active Record 风格** | Model 上加业务方法, 不分离 Entity |
| Repository | **查询助手函数** (queries.py) | 不强制抽象接口, 直接函数 |
| DI 方式 | **FastAPI Depends** | 不引入 DI 容器, 原生够用 |
| 状态机 | **统一 JobStateService** | 解决 4 处真相源, 唯一改进点 |
| 模块内文件 | router + service + queries + schemas | 4 个文件覆盖一个业务域 |

## 四、核心代码示例

### 4.1 ORM 即 Domain (Active Record 风格)

**修改**: `models/training_job.py` — 在 ORM 上加业务方法

```python
"""
TrainingJob ORM 模型 (Active Record 风格)
直接在 ORM 上承载业务规则, 不分离 Domain Entity
"""
from datetime import datetime
from sqlalchemy import Column, Integer, String, Float, DateTime, JSON, Text
from app.database import Base


# 业务状态枚举 (放在 Model 旁, 不再单独建 domain/)
TERMINAL_STATES = ("SUCCESS", "FAILURE", "REVOKED")
VALID_TRANSITIONS = {
    "PENDING":   {"PROGRESS", "REVOKED"},
    "PROGRESS":  {"SUCCESS", "FAILURE", "REVOKED"},
    "SUCCESS":   set(),
    "FAILURE":   set(),
    "REVOKED":   set(),
}


class TrainingJob(Base):
    __tablename__ = "training_job"

    id = Column(Integer, primary_key=True)
    celery_task_id = Column(String(64), unique=True, index=True)
    user_id = Column(Integer, index=True)
    dataset_id = Column(Integer, index=True)
    task_type = Column(String(32), default="classification")
    base_model = Column(String(128))
    model_name = Column(String(128))
    state = Column(String(16), default="PENDING", index=True)
    progress = Column(Float, default=0.0)
    message = Column(String(512), default="")
    error = Column(Text)
    # ... 其他字段省略

    # ===== 业务方法 (Active Record) =====

    def is_terminal(self) -> bool:
        """业务规则: 终态判断"""
        return self.state in TERMINAL_STATES

    def transition_to(self, new_state: str, message: str = "") -> None:
        """业务规则: 状态机转移 (非法转移抛异常)"""
        if new_state not in VALID_TRANSITIONS.get(self.state, set()):
            raise ValueError(
                f"非法状态转移: {self.state} -> {new_state}"
            )
        self.state = new_state
        if message:
            self.message = message

    def append_history(self, metrics: dict) -> None:
        """业务规则: 追加训练历史"""
        history = self.history or []
        history.append(metrics)
        if len(history) > 1000:
            history = history[-1000:]
        self.history = history

    def calc_duration(self) -> float | None:
        """业务规则: 计算耗时"""
        if self.started_at and self.finished_at:
            return (self.finished_at - self.started_at).total_seconds()
        return None
```

**好处**: 业务规则集中在 ORM 上, Service / API / Worker 都能直接调 `job.transition_to(...)`, 无需转换。

### 4.2 查询助手 (queries.py) — 替代 Repository

**新增**: `modules/training/queries.py`

```python
"""
训练任务查询助手 (函数式, 不抽象接口)
封装复杂 SELECT, 简单 CRUD 直接用 db.get(TrainingJob, id)
"""
from typing import Optional, List
from datetime import datetime
from sqlalchemy import select, update, func
from sqlalchemy.ext.asyncio import AsyncSession
from app.models.training_job import TrainingJob


async def get_by_celery_task_id(
    db: AsyncSession, celery_task_id: str
) -> Optional[TrainingJob]:
    """按 Celery task id 查询"""
    result = await db.execute(
        select(TrainingJob).where(TrainingJob.celery_task_id == celery_task_id)
    )
    return result.scalar_one_or_none()


async def list_by_user(
    db: AsyncSession, user_id: int, *, limit: int = 50, offset: int = 0
) -> List[TrainingJob]:
    """按用户分页查询"""
    result = await db.execute(
        select(TrainingJob)
        .where(TrainingJob.user_id == user_id)
        .order_by(TrainingJob.created_at.desc())
        .limit(limit).offset(offset)
    )
    return list(result.scalars().all())


async def count_by_state(db: AsyncSession, state: str) -> int:
    """按状态计数 (统计接口用)"""
    result = await db.execute(
        select(func.count(TrainingJob.id)).where(TrainingJob.state == state)
    )
    return result.scalar() or 0


async def bulk_update_terminal_state(
    db: AsyncSession,
    celery_task_id: str,
    *,
    state: str,
    progress: float,
    message: str,
    finished_at: datetime,
) -> None:
    """终态批量更新 (一次 UPDATE 完成所有字段)"""
    await db.execute(
        update(TrainingJob)
        .where(TrainingJob.celery_task_id == celery_task_id)
        .values(
            state=state, progress=progress, message=message,
            finished_at=finished_at,
        )
    )
    await db.commit()
```

**vs Repository 接口的差异**:

| 项 | Repository 接口 (v1.0) | 查询助手 (v2.0) |
|---|---|---|
| 形式 | 抽象基类 + 具体实现 | 普通函数 |
| 代码量 | 250 行/表 (含转换) | 80 行/域 |
| 抽象价值 | 可换 ORM 实现 | 无 (项目不会换 ORM) |
| Mock 难度 | 易 (Mock 接口) | 中 (Mock 函数) |
| 学习成本 | 高 (懂接口/继承) | 低 (调函数) |

**结论**: 对不会换 ORM 的项目, 接口抽象是 YAGNI (You Aren't Gonna Need It)。

### 4.3 Service 层 (业务编排中心)

**新增**: `modules/training/service.py`

```python
"""
训练业务服务 (应用层)
所有业务编排在此: 校验 + 状态机 + 调 ML + 调 Worker
API 和 Worker 都通过此 Service 操作训练任务
"""
from typing import Optional, List
from datetime import datetime
import uuid

from sqlalchemy.ext.asyncio import AsyncSession
from fastapi import HTTPException

from app.config import settings
from app.core.celery_utils import check_celery_available
from app.models.training_job import TrainingJob
from app.models.model_version import ModelVersion
from app.modules.training import queries as q
from app.modules.training.state_machine import JobStateMachine
from app.modules.dataset.queries import get_dataset_by_id


class TrainingService:
    """训练业务服务 (有状态: 持有 db session)"""

    def __init__(self, db: AsyncSession, state_machine: JobStateMachine):
        self._db = db
        self._sm = state_machine

    # ===== Use Cases =====

    async def start_training(
        self,
        *,
        user_id: int,
        dataset_id: int,
        base_model: str,
        model_name: str,
        epochs: int,
        batch_size: int,
        learning_rate: float,
        pretrained_model_path: Optional[str] = None,
    ) -> TrainingJob:
        """启动训练 (Use Case)

        业务规则:
        - 数据集必须存在
        - epochs 1-1000
        - model_name 为空时自动生成
        - 预创建 PENDING 行 + Celery apply_async
        """
        # 1. 业务校验
        dataset = await get_dataset_by_id(self._db, dataset_id)
        if not dataset:
            raise HTTPException(404, f"Dataset id={dataset_id} not found")

        if not (1 <= epochs <= 1000):
            raise HTTPException(422, "epochs 必须在 1-1000 之间")

        if not model_name or not model_name.strip():
            ts = int(datetime.utcnow().timestamp()) % 10000000000
            model_name = f"{base_model}_v1_{ts}"

        task_type = (dataset.task_type or "classification").lower()

        # 2. 预检 broker
        check_celery_available()

        # 3. 预创建 PENDING 行
        celery_task_id = uuid.uuid4().hex
        job = TrainingJob(
            celery_task_id=celery_task_id,
            user_id=user_id,
            dataset_id=dataset_id,
            task_type=task_type,
            base_model=base_model,
            model_name=model_name,
            state="PENDING",
            progress=0.0,
            message="等待 worker 启动...",
            epochs=epochs,
            batch_size=batch_size,
            learning_rate=learning_rate,
            pretrained_model_path=pretrained_model_path,
            created_at=datetime.utcnow(),
        )
        self._db.add(job)
        await self._db.commit()
        await self._db.refresh(job)

        # 4. 派发到 Celery (按 task_type)
        try:
            await self._dispatch_task(
                task_type=task_type,
                celery_task_id=celery_task_id,
                kwargs={
                    "dataset_id": dataset_id,
                    "user_id": user_id,
                    "base_model": base_model,
                    "model_name": model_name,
                    "epochs": epochs,
                    "batch_size": batch_size,
                    "learning_rate": learning_rate,
                    "pretrained_model_path": pretrained_model_path,
                },
            )
        except Exception as e:
            # 派发失败, 回滚
            await self._db.delete(job)
            await self._db.commit()
            raise HTTPException(503, f"任务派发失败: {e}")

        return job

    async def get_progress(self, celery_task_id: str) -> dict:
        """查询训练进度 (Use Case)

        合并 Celery AsyncResult + DB TrainingJob, 返回统一视图
        """
        from celery.result import AsyncResult

        # 1. 先查 DB (权威)
        job = await q.get_by_celery_task_id(self._db, celery_task_id)

        # 2. 再查 Celery (拿实时 progress)
        state, info = "PENDING", {}
        try:
            result = AsyncResult(celery_task_id)
            state = result.state or "PENDING"
            if isinstance(result.info, dict):
                info = result.info
        except Exception:
            pass

        # 3. 合并 (终态以 DB 为准, 非终态用 Celery 实时数据)
        if job and job.is_terminal():
            return {
                "state": job.state,
                "progress": job.progress,
                "message": job.message or (job.error or "")[:200],
                "started_at": job.started_at,
                "finished_at": job.finished_at,
                "total_epochs": job.epochs,
                "current_epoch": (job.history or [{}])[-1].get("epoch") if job.history else None,
            }

        # 非终态: 优先 Celery info, 兜底 DB
        return {
            "state": state,
            "progress": float(info.get("progress", job.progress if job else 0)),
            "message": info.get("msg") or (job.message if job else ""),
            "started_at": job.started_at if job else None,
            "finished_at": None,
            "total_epochs": info.get("total_epochs") or (job.epochs if job else None),
            "current_epoch": info.get("epoch"),
        }

    async def list_jobs(
        self, user_id: int, *, limit: int = 50, offset: int = 0
    ) -> List[TrainingJob]:
        """列出用户的训练任务"""
        return await q.list_by_user(self._db, user_id, limit=limit, offset=offset)

    # ===== 私有辅助 =====

    async def _dispatch_task(
        self, *, task_type: str, celery_task_id: str, kwargs: dict
    ) -> None:
        """按 task_type 选择 Celery 任务并 apply_async"""
        if task_type == "detection":
            from app.workers.detection_tasks import train_detection_task as task
        elif task_type == "segmentation":
            from app.workers.segmentation_tasks import train_segmentation_task as task
        else:
            from app.workers.tasks import train_model_task as task
        task.apply_async(kwargs=kwargs, task_id=celery_task_id)
```

### 4.5 通用 SSE 工具 (消除三处重复)

**新增**: `core/sse.py`

```python
"""
通用 SSE 推送工具
消除 training.py / detection.py / segmentation.py 三处 300+ 行重复
"""
import asyncio
import json
from typing import Callable, Awaitable, Any
from fastapi.responses import StreamingResponse
from fastapi import Request

SSE_POLL_INTERVAL = 1.0       # 每 1s 拉一次状态
SSE_KEEPALIVE_INTERVAL = 15.0  # 每 15s 发 keepalive


def stream_job_progress(
    *,
    task_id: str,
    fetch_state_fn: Callable[[str], Awaitable[dict]],
) -> StreamingResponse:
    """
    通用 SSE 流: 订阅任务进度

    Args:
        task_id: 任务 ID
        fetch_state_fn: 异步函数, 返回当前状态 dict

    使用:
        return stream_job_progress(
            task_id=task_id,
            fetch_state_fn=service.get_progress,
        )
    """
    async def event_generator():
        last_signature = None
        last_keepalive = 0.0

        # 首帧
        yield f": connected task_id={task_id}\n\n"

        while True:
            # 拉状态
            try:
                state = await fetch_state_fn(task_id)
            except Exception:
                state = {"state": "UNKNOWN", "progress": 0, "message": ""}

            # 仅在签名变化时推送 (避免静默期洪水)
            signature = (
                state.get("state"),
                round(state.get("progress", 0), 2),
                state.get("message"),
            )
            if signature != last_signature:
                yield f"data: {json.dumps(state, default=str)}\n\n"
                last_signature = signature

            # 终端态自动结束
            if state.get("state") in ("SUCCESS", "FAILURE", "REVOKED"):
                return

            # keepalive
            now = asyncio.get_event_loop().time()
            if now - last_keepalive > SSE_KEEPALIVE_INTERVAL:
                yield f": keepalive\n\n"
                last_keepalive = now

            await asyncio.sleep(SSE_POLL_INTERVAL)

    return StreamingResponse(
        event_generator(),
        media_type="text/event-stream",
        headers={
            "Cache-Control": "no-cache",
            "Connection": "keep-alive",
            "X-Accel-Buffering": "no",  # Nginx 不缓冲
        },
    )
```

**收益**: 三处 SSE 端点 (training/detection/segmentation 各 ~300 行) 收敛为 1 处 (~70 行), 调用方仅 3 行。

### 4.6 状态机服务 (解决 4 处真相源)

**新增**: `services/job_state_service.py`

```python
"""
训练状态机服务: 统一管理 TrainingJob + Celery meta + Redis 历史

之前 (v2.5.x): API + Worker + Celery meta + DB 4 处状态写入
现在: 全部通过 JobStateService.on_xxx() 统一入口
"""
import json
from datetime import datetime
from typing import Optional, Dict, Any
from sqlalchemy.ext.asyncio import AsyncSession

from app.core.redis_client import redis_client
from app.models.training_job import TrainingJob
from app.modules.training import queries as q


class JobStateService:
    """训练状态机 (跨域共享, 放在 services/)"""

    def __init__(self, db: AsyncSession):
        self._db = db

    # ===== 状态转移入口 (Worker 调用) =====

    async def on_start(
        self, celery_task_id: str, *, total_epochs: int
    ) -> None:
        """Worker 接手任务"""
        job = await q.get_by_celery_task_id(self._db, celery_task_id)
        if not job:
            return
        try:
            job.transition_to("PROGRESS", "开始训练")
        except ValueError:
            pass  # 已是 PROGRESS
        job.started_at = datetime.utcnow()
        await self._db.commit()

        # Celery meta
        from celery import current_task
        if current_task:
            current_task.update_state(
                state="PROGRESS",
                meta={"progress": 0.0, "msg": "开始训练", "total_epochs": total_epochs}
            )

    async def on_progress(
        self, celery_task_id: str, progress: float, message: str,
        extra: Optional[Dict[str, Any]] = None,
    ) -> None:
        """进度更新 (每 batch)"""
        # 1. Celery meta (实时)
        from celery import current_task
        if current_task:
            current_task.update_state(
                state="PROGRESS",
                meta={"progress": progress, "msg": message, **(extra or {})}
            )

        # 2. DB (每 5% 写一次, 减抖动)
        job = await q.get_by_celery_task_id(self._db, celery_task_id)
        if job and (int(progress * 100) - int(job.progress * 100) >= 5 or progress >= 1.0):
            job.progress = progress
            job.message = message
            # 数据集统计 (sticky_meta)
            if extra and "data_total" in extra:
                job.data_total = extra.get("data_total")
                job.data_train = extra.get("data_train")
                job.data_val = extra.get("data_val")
                job.num_classes = extra.get("num_classes")
                job.class_names = extra.get("class_names")
            await self._db.commit()

    async def on_epoch(
        self, celery_task_id: str, metrics: Dict[str, Any]
    ) -> None:
        """Epoch 完成"""
        # 1. Redis (训练历史曲线, 24h 过期)
        key = f"train:history:{celery_task_id}"
        raw = redis_client.get(key)
        history = json.loads(raw) if raw else []
        history.append(metrics)
        if len(history) > 1000:
            history = history[-1000:]
        redis_client.setex(key, 86400, json.dumps(history))

        # 2. DB (TrainingJob.history JSON 列)
        job = await q.get_by_celery_task_id(self._db, celery_task_id)
        if job:
            job.append_history(metrics)
            await self._db.commit()

    async def on_success(
        self, celery_task_id: str, model_version_id: int
    ) -> None:
        """训练成功"""
        job = await q.get_by_celery_task_id(self._db, celery_task_id)
        if not job:
            return
        finished_at = datetime.utcnow()
        try:
            job.transition_to("SUCCESS", "训练完成")
        except ValueError:
            pass
        job.progress = 1.0
        job.finished_at = finished_at
        job.duration_seconds = job.calc_duration()
        await self._db.commit()

    async def on_failure(
        self, celery_task_id: str, error: str
    ) -> None:
        """训练失败"""
        job = await q.get_by_celery_task_id(self._db, celery_task_id)
        if not job:
            return
        finished_at = datetime.utcnow()
        try:
            job.transition_to("FAILURE", error[:200])
        except ValueError:
            pass
        job.error = error[:1000]
        job.finished_at = finished_at
        job.duration_seconds = job.calc_duration()
        await self._db.commit()
```

### 4.7 Worker 入口 (薄, 委托 Service)

**修改**: `workers/tasks.py`

```python
"""
分类训练 Celery 任务 (薄入口, 委托 Service)
"""
from app.workers.celery_app import celery_app
from app.core.celery_utils import run_async_in_worker
from app.database import AsyncSessionLocal
from app.modules.training.service import TrainingService
from app.services.job_state_service import JobStateService
from app.ml.train import run_classification_training


@celery_app.task(bind=True)
def train_model_task(
    self,
    dataset_id: int,
    base_model: str,
    model_name: str,
    user_id: int,
    epochs: int = 20,
    batch_size: int = 32,
    learning_rate: float = 1e-4,
    pretrained_model_path: str | None = None,
) -> dict:
    """Celery 任务入口 (薄, 业务在 Service)"""
    async def _run():
        async with AsyncSessionLocal() as db:
            sm = JobStateService(db)
            service = TrainingService(db=db, state_machine=sm)

            # 1. 状态: PROGRESS
            await sm.on_start(self.request.id, total_epochs=epochs)

            # 2. 加载数据 (调 queries)
            train_data, val_data, class_names = await service.load_dataset(
                dataset_id, celery_task_id=self.request.id
            )

            # 3. 调 ML (纯计算, 不依赖 DB)
            try:
                result = run_classification_training(
                    train_data=train_data,
                    val_data=val_data,
                    base_model=base_model,
                    epochs=epochs,
                    batch_size=batch_size,
                    learning_rate=learning_rate,
                    pretrained_model_path=pretrained_model_path,
                    output_dir=service.get_model_dir(user_id, model_name),
                    progress_callback=lambda p, m, e: run_async_in_worker(
                        sm.on_progress(self.request.id, p, m, e)
                    ),
                    epoch_callback=lambda metrics: run_async_in_worker(
                        sm.on_epoch(self.request.id, metrics)
                    ),
                )
            except Exception as e:
                await sm.on_failure(self.request.id, str(e))
                raise

            # 4. 持久化 ModelVersion
            mv_id = await service.save_model_version(
                user_id=user_id,
                dataset_id=dataset_id,
                model_name=model_name,
                base_model=base_model,
                result=result,
                class_names=class_names,
            )

            # 5. 状态: SUCCESS
            await sm.on_success(self.request.id, mv_id)

            # 6. 返回 (必须 JSON 可序列化)
            return {
                "status": "success",
                "model_version_id": mv_id,
                "best_accuracy": float(result["best_accuracy"]),
            }

    return run_async_in_worker(_run())
```

- 新: 入口 30 行, 业务在 Service, ML 在 `ml/train.py`, 状态机在 `JobStateService`

A: 不会, 只加**简单的、与数据本身强相关的业务规则**:
- ✅ 加: `is_terminal()` / `transition_to()` / `calc_duration()` (单字段判断)
- ❌ 不加: `start_training()` (涉及外部依赖, 放 Service)
- ❌ 不加: `export_to_coco()` (涉及其他实体, 放 Service)

参考 Django / Rails 的 Active Record 实践, 是经过验证的模式。

### Q4: modules/ 和 services/ 怎么区分?

A:
- `modules/{业务}/service.py` — **业务域专属** Service (训练/检测/图像/...)
- `services/*.py` — **跨业务共享** Service (AI 推理 / 几何 / 存储 / 状态机)
- 判断标准: 只被一个业务用 → `modules/`, 多业务共用 → `services/`

### Q5: 已经迁移了一半 v1.0 怎么办?

A: v1.0 和 v2.0 可以**并存**:
- 已迁移的 domain/ + repositories/ 可保留 (不浪费)
- 新模块按 v2.0 走 modules/
- 长期看 v2.0 是主流, v1.0 残余可逐步淡化
