### 2.4 ML 训练与推理层 (`app/ml/*.py`)

#### ✅ 优点

1. **统一抽象**: `train.py` (分类) + `yolo_train.py` (检测) + `seg_train.py` (分割) 三个训练入口
2. **ultralytics 懒加载**: 仅在真正训练时 import, 避免影响非 AI 链路测试
3. **PyTorch 懒加载**: `_build_model` / `load_model` 内部 import, 节省 ~2GB 启动内存
4. **进度回调统一**: `progress_cb(stage, current, total, info)` 三种任务风格一致
5. **指标计算**: mIoU + pixel accuracy (分割) / mAP@0.5 + mAP@0.5:0.95 (检测) / 混淆矩阵 (分类)
6. **CPU 友好**: 论文 demo 走 CPU, `mosaic=0.0` + `amp=False` 优化
7. **模型保存**: best.pt + last.pt 双权重, state_dict 落盘为字节流
8. **增量训练**: 加载旧 state_dict 作为起点, 模式 `mode=restart`
9. **结果结构化**: 返回 `{"best_pt": ..., "metrics": {...}, "duration_seconds": ...}` 统一

```python
# 模式 1: TrainingJob 预创建 (消除竞态)
@router.post("/start")
def start_training(...):
    # 1. API 层预生成 UUID
    celery_task_id = uuid.uuid4().hex
    # 2. 预创建 PENDING 行
    db.execute(insert(TrainingJob).values(celery_task_id=celery_task_id, state="PENDING"))
    db.commit()
    # 3. 强制 Celery 用此 ID 入队
    train_model_task.apply_async(task_id=celery_task_id, kwargs={...})

# 模式 2: Worker 端 UPDATE 而非 INSERT
@celery_app.task(bind=True)
def train_model_task(self, ...):
    task_id = self.request.id
    async def _create_job():
        existing = await db.execute(
            select(TrainingJob).where(TrainingJob.celery_task_id == task_id)
        )
        if existing:
            existing.state = "PROGRESS"
            return existing.id
        # INSERT 兜底 (API 层已预创建, 正常情况走不到)
        ...
```
