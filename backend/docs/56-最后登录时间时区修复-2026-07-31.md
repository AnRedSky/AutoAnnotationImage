# 最后登录时间时区修复 — 2026-07-31

## 问题

User model 的 `last_login_at` 和 `created_at` 字段在序列化为 ISO 字符串时**不带时区信息**:

```python
"last_login_at": u.last_login_at.isoformat()  # → '2026-07-31T06:47:01'
```

但 DB 里存的是 `datetime.utcnow()` 的值（即 UTC 时间）。

前端 JavaScript 解析:
- `new Date('2026-07-31T06:47:01')` 没有 Z 后缀 → JS 当作**本地时间**解析
- 北京时区浏览器 → 显示 `2026/07/31 06:47:01`
- 但实际北京时间应该是 `2026/07/31 14:47:01`
- **少 8 小时**

## 修复

新增 helper `_iso_utc(dt)`: 把 naive datetime 序列化为带 `Z` 后缀的 UTC ISO 字符串:

```python
def _iso_utc(dt):
    if dt is None:
        return None
    if dt.tzinfo is not None:
        return dt.isoformat()  # 已带 tzinfo: 直接返回 (e.g., '+00:00')
    return dt.isoformat() + "Z"  # naive: 补 'Z' 表明 UTC
```

应用位置:
- `/api/users/` 列表的 `created_at` + `last_login_at`
- `/api/users/me/profile` 的 `created_at` + `last_login_at`

## 验证

| 检查 | 修复前 | 修复后 |
|---|---|---|
| API 返回格式 | `2026-07-31T06:47:01` | `2026-07-31T06:47:01Z` |
| 前端 JS 解析 | 当本地时间 → 显示 06:47 | 当 UTC → 转本地 → 显示 14:47 ✅ |
| 与服务器实际北京时间匹配 | 偏差 -8h | 偏差 0 ✅ |

实测:
```
server wallclock Beijing: 2026-07-31 14:47:01
API /me/profile last_login_at: '2026-07-31T06:47:01Z' (Z: True)
→ toLocaleString('zh-CN') in Beijing browser: 2026/07/31 14:47:01 ✅
```
