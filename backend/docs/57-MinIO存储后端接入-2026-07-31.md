## 关键设计：LazyStorageProxy

```python
class _LazyStorageProxy:
    __slots__ = ()
    def __getattr__(self, name):
        return getattr(_real_storage_service(), name)

storage_service = _LazyStorageProxy()
```

**为什么需要**：Python `from x import y` 把 y **绑定** 到当前 x 模块的对象上。如果直接 `storage_service = MinioStorageService()`，那已 import 它的模块拿到的就是死绑定的实例 — backend 切换不生效。

**Proxy 解决**：调用方 `from app.common.storage.storage_service import storage_service` 拿到的是 proxy，方法调用时才查 backend。`upload.py` / `files.py` 等 30+ 文件**零改动**。

## 配置步骤

### 启用 MinIO (生产)
```bash
# .env
STORAGE_BACKEND=minio
MINIO_ENDPOINT=127.0.0.1:9000    # 或 s3.amazonaws.com
MINIO_ACCESS_KEY=minioadmin
MINIO_SECRET_KEY=***
MINIO_BUCKET=image-annotation
MINIO_SECURE=false                # HTTPS 用 true
```

### 保持 Local (开发/单机)
```bash
STORAGE_BACKEND=local  # 或不设
```

### 迁移老数据
```bash
cd backend
# Dry-run 先看会迁移什么
env -u PYTHONPATH ./.venv/Scripts/python.exe scripts/migrate_local_to_minio.py

# 真迁移
env -u PYTHONPATH ./.venv/Scripts/python.exe scripts/migrate_local_to_minio.py --apply
```

脚本行为：
- 读 `image.storage_path` 列表
- 读本地 → put_object 到 MinIO
- 验证 sha256 + size 一致 → 删本地
- 已迁移的自动跳过 (`exists()` 检查)
- 默认 dry-run, `--apply` 才会删本地

## 性能特性

- **异步**: `asyncio.to_thread` 包装同步 minio SDK 调用, 不阻塞 event loop
- **幂等创建 bucket**: 启动时 `make_bucket`, 已存在则跳过
- **路径穿越防护**: key 校验 (`..` / 绝对路径禁止), 替代 local 的 `resolve().relative_to()`
- **错误传播**: `S3Error.code in ("NoSuchKey", "NoSuchObject")` 转 `FileNotFoundError`, 与 local backend 行为一致
- **预签名 URL**: 额外提供 `get_presigned_url(key, expires=3600)` — 给前端直链绕过 API, 减轻 API 压力

## 回滚方案

设 `STORAGE_BACKEND=local` 重启即可立即回滚, 无需迁移脚本 (数据不动, 上传会写回本地)。
